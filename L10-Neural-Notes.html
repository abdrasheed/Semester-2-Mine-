1. Overview – Neural Retrieval & Re-ranking

Neural IR replaces or augments classical retrieval (BM25, TF-IDF) with deep learning models that learn semantic representations from text. The central question: how to estimate relevance between a query and a document?

Two Sub-problems

  • Relevance Estimation: What architecture and training signal to use?
  • Retrieval Engine: How to efficiently find top results at scale?

2. Transformer Language Model Crash Course

All modern neural IR models are built on Transformer language models (BERT, T5, RoBERTa). Understanding the building blocks is essential for understanding why different architectures have different cost profiles.

Token Embeddings

Input text is tokenised into subword tokens (BERT uses WordPiece: ~30k vocabulary). Each token maps to a learnable embedding vector (typically 768 dims). Special tokens: [CLS] (classification token, first position), [SEP] (separator between sequences).

Self-Attention (Transformer Core)
\[ \text{Attention}(Q, K, V) = \text{softmax}\!\left(\frac{QK^T}{\sqrt{d_k}}\right)V \]

Q, K, V are projections of the input sequence. The key insight: attention computes pairwise interactions between all pairs of tokens. For a sequence of length |d|, this requires O(|d|²) computation and memory — this is the dominant cost for long documents.

[CLS] Pooling

Use the output embedding of the [CLS] token as a summary representation of the entire sequence. BERT was pre-trained with [CLS] for classification (NSP task). Used by: DPR (bi-encoder), MonoBERT (cross-encoder). Simple but discards token-level detail.

Mean Pooling

Average all token embeddings as the sequence representation. Shown to outperform [CLS] pooling for semantic similarity in several studies (e.g., TCT-ColBERT uses mean pooling). Captures information from all tokens, not just [CLS].

3. Generic Relevance Model Framework

All neural ranking models can be described by three components:

Generic Relevance Estimation Framework
\[ \text{score}(q, d) = F\!\left(\Phi_Q(q),\; \Phi_D(d)\right) \]

Φ_Q(q) = Query encoder: how expensive to encode the query?
Φ_D(d) = Document encoder: how expensive to encode the document?
F(·,·) = Combiner: how expensive to combine query and document representations?

3. Sparse / Lexical Retrieval

Traditional lexical retrieval represents documents as sparse term-weight vectors. Neural sparse models like SPLADE learn improved sparse representations.

BM25 (reminder)
\[ \text{BM25}(q,d) = \sum_{t \in q} \text{IDF}(t) \cdot \frac{\text{tf}(t,d) \cdot (k_1+1)}{\text{tf}(t,d) + k_1(1-b+b\frac{|d|}{\text{avgdl}})} \]
🔶 Practice Example

Given k₁=1.5, b=0.75, |d|=100, avgdl=200, tf(t,d)=3, IDF(t)=2.0 — compute the BM25 contribution of term t.

✅ Solved Example

TF part: tf × (k₁+1) / (tf + k₁(1 - b + b·|d|/avgdl))

= 3 × 2.5 / (3 + 1.5×(1 - 0.75 + 0.75×0.5))

= 7.5 / (3 + 1.5×0.625) = 7.5 / (3 + 0.9375) = 7.5/3.9375 ≈ 1.905

BM25 contribution = IDF × TF-part = 2.0 × 1.905 = 3.81

SPLADE — Learned Sparse

SPLADE Representation
\[ w_j = \log(1 + \text{ReLU}(\sum_{i} h_i \cdot E_j^T)) \]
🔶 Practice

Why use log(1 + ReLU(·)) instead of raw logits for sparse representations?

✅ Solved

ReLU ensures non-negative weights (no negative term weights). log(1+x) compresses large activations (prevents a few terms dominating) and ensures zero stays zero — maintaining sparsity. The vocabulary-level projection aggregates all token representations to produce a single doc-level sparse vector.

6. Learned Sparse Retrieval (LSR) Models

LSR models replace static term-weight functions (TF-IDF) with contextualised term weights learned by a BERT-based model. They produce sparse vectors compatible with inverted index infrastructure.

DeepCT

Deep Contextualized Term weights. Passes document through BERT; uses each token's output embedding to predict a contextualised term frequency for that word. Replaces raw TF with a learned weight that captures context. Compatible with BM25-style retrieval using the new TF values.

EPIC

Expansion via Prediction of Importance using Context. Uses a language model to expand each token: for each input token, predict which vocabulary terms it implies. Aggregates via max-pooling across tokens. Produces a sparse document vector over the full vocabulary — richer than TF-based representations.

TILDE

Term Independent Likelihood moDEl. Simplest LM-based expansion: uses a single [CLS] token representation to predict document expansion terms. Very fast — one LM inference gives the whole expanded representation. Less expressive than EPIC (single-token vs multi-token context).

7. Dense / Bi-Encoder Retrieval

A bi-encoder independently encodes query and document into fixed-size dense vectors, then scores via dot product or cosine similarity. Enables approximate nearest-neighbour (ANN) search at scale.

Bi-Encoder Scoring
\[ s(q,d) = E_Q(q) \cdot E_D(d) \]
🔶 Practice

Query vector q⃗ = [0.6, 0.8, 0.0], doc vector d⃗ = [0.5, 0.5, 0.7]. Compute the relevance score.

✅ Solved

s = 0.6×0.5 + 0.8×0.5 + 0.0×0.7 = 0.30 + 0.40 + 0.00 = 0.70

For cosine similarity: normalise both vectors first — ||q⃗|| = 1 (already unit), ||d⃗|| = √(0.25+0.25+0.49) = √0.99 ≈ 0.995, cosine ≈ 0.70/0.995 ≈ 0.704

DPR (Dense Passage Retrieval)

DPR trains separate BERT encoders for query and passages using in-batch negatives. Documents are pre-encoded offline; ANN indexes (FAISS) serve queries in milliseconds.

import torch
from transformers import DPRQuestionEncoder, DPRContextEncoder, DPRQuestionEncoderTokenizer

q_tokenizer = DPRQuestionEncoderTokenizer.from_pretrained('facebook/dpr-question_encoder-single-nq-base')
q_encoder = DPRQuestionEncoder.from_pretrained('facebook/dpr-question_encoder-single-nq-base')

query = "What is information retrieval?"
inputs = q_tokenizer(query, return_tensors='pt')
with torch.no_grad():
    q_vec = q_encoder(**inputs).pooler_output  # shape: (1, 768)

print("Query embedding shape:", q_vec.shape)

9. Cross-Encoders / Mono Models (Re-ranking)

A cross-encoder concatenates query and document as a single input to a transformer (e.g. BERT). Full attention between all tokens → highest quality, but too slow for first-stage retrieval.

monoBERT / monoT5

  • monoBERT: BERT fine-tuned on MS MARCO pairs, [CLS] → sigmoid → relevance prob
  • monoT5: T5 seq2seq, generates token "true"/"false" for relevance
Cross-Encoder Scoring
\[ s(q,d) = \sigma(\mathbf{W}^T \text{BERT}([q;d])_{[CLS]}) \]
🔶 Practice

Why can't cross-encoders be used for first-stage retrieval over a corpus of 10M documents?

✅ Solved

A cross-encoder must run inference for each (query, document) pair. At 10M docs, with each BERT inference taking ~20ms, that's 200,000 seconds ≈ 55 hours per query — completely infeasible. Cross-encoders are only practical for re-ranking a small shortlist (~100-1000) of candidates retrieved by a faster first stage (BM25, bi-encoder).

Pipeline: Retrieve → Re-rank

import pyterrier as pt
from pyterrier.measures import *

# Stage 1: BM25 first-stage retrieval
bm25 = pt.BatchRetrieve(index, wmodel="BM25", num_results=1000)

# Stage 2: monoT5 re-ranker
from pyterrier_t5 import MonoT5ReRanker
mono_t5 = MonoT5ReRanker(model='castorini/monot5-base-msmarco')

# Pipeline
pipeline = bm25 >> mono_t5

results = pipeline.transform(queries_df)

10. Interaction Models (DRMM, KNRM, PACRR, CEDR)

Interaction models build a query-document interaction matrix from token-level similarities, then use a neural network to score from this matrix. They use static (non-contextual) encoders like word2vec/GloVe for O(|d|) encoding, but O(|d|) or more for the interaction.

Key Intuition

Rather than compressing query and document into single vectors (bi-encoder) or processing them jointly (cross-encoder), interaction models compute a similarity matrix between all query tokens and document tokens, then learn from this rich interaction signal.

DRMM (Deep Relevance Matching Model)

Computes histogram of cosine similarity scores between each query term and all document terms. Feeds histogram through MLP to get per-query-term scores. Sum to final score. Uses static word2vec embeddings (O(|d|) encoder, O(|d|) combiner).

KNRM (Kernel-based Neural Ranking)

Uses RBF kernels to soft-count matches at different similarity levels (from exact to soft match). More principled than histograms. Differentiable → trained end-to-end. Also uses static embeddings.

PACRR (Position-Aware ConvolutionalRecurrent Ranking)

Applies 2D convolutions to the query-document interaction matrix to capture phrase-level patterns. Position-aware — the location of matching terms matters (unlike unordered histograms).

CEDR (Contextual-Enhanced Dense Retrieval)

Combines BERT's contextual token embeddings with DRMM/KNRM-style interaction. BERT encodes document and query (O(|d|²)), but interaction is O(|d|) — a hybrid between interaction models and transformers. Better quality than static embedding models.

11. ColBERT — Late Interaction

ColBERT encodes query and document independently per-token, then scores via a lightweight MaxSim operation. Balances expressiveness of cross-encoder with efficiency of bi-encoder.

ColBERT Scoring (MaxSim)
\[ s(q,d) = \sum_{i \in |q|} \max_{j \in |d|} E_Q(q)_i \cdot E_D(d)_j \]
🔶 Practice

Query has 2 token vectors: q₁=[1,0], q₂=[0,1]. Document has 3 token vectors: d₁=[0.8,0.1], d₂=[0.3,0.9], d₃=[0.1,0.2]. Compute the ColBERT score.

✅ Solved

MaxSim(q₁, D) = max(q₁·d₁, q₁·d₂, q₁·d₃) = max(0.8, 0.3, 0.1) = 0.8

MaxSim(q₂, D) = max(q₂·d₁, q₂·d₂, q₂·d₃) = max(0.1, 0.9, 0.2) = 0.9

ColBERT score = 0.8 + 0.9 = 1.7

ColBERT v2 Improvements

  • Denoised supervision: Uses cross-encoder labels for harder negative mining
  • Residual compression: Compresses document token vectors 4–16× for storage efficiency
  • PyTerrier-ColBERT: pip install pyterrier-colbert

13. Listwise & Duo Models

Mono models (MonoBERT, monoT5) score each document independently given the query. Duo models and listwise models explicitly compare multiple documents simultaneously — more expensive but more expressive.

DuoBERT (Duo+)

Jointly scores a pair of documents given a query. Input: [CLS] query [SEP] doc1 [SEP] doc2 [SEP]. Estimates P(d1 more relevant than d2 | q). Produces a pairwise preference. More expensive: O(|candidates|²) pairs to evaluate.

ListoBERT / RankGPT (Late Duo+)

Listwise: simultaneously considers the full list of candidates. RankGPT uses a large language model (GPT-4, LLaMA) prompted to rank a set of passages. Estimates Rel(d? | q, d₁, d₂, ..., dₙ) — explicitly conditioned on all candidates. Highest quality but very expensive: must process all candidates in one pass.

Duo+ Formulation
\[ \text{score}(d_i | q) = \sum_{j \neq i} P(d_i \succ d_j \mid q) \]

Aggregate pairwise preferences into a final score. Equivalent to counting "wins" in a round-robin tournament among candidate documents.

⚠️ Cost of Duo Models

For N candidates, DuoBERT requires N(N-1)/2 pairwise comparisons. For N=100: 4,950 BERT inferences. Only practical on very small candidate sets (top-20 or fewer) after aggressive re-ranking by a mono model.

14. Quality Estimators

Quality Estimators are query-independent models that estimate the general quality of a document — without any query context. They function as sophisticated replacements for PageRank or spam filters.

Spam Classifier

Trained ML classifier predicting whether a document is spam (link farm, keyword stuffing, thin content). Assigned a spam score at index time. Documents above the spam threshold are filtered from retrieval entirely or heavily downranked.

QualT5 (Quality Estimator)

A T5-based model fine-tuned to predict document quality (e.g., "high quality writing" vs. "low quality"). Generates a quality estimate without a query. Used as a QI (query-independent) feature in web search ranking alongside PageRank and spam scores.

Quality Estimators in the 2D Taxonomy

Quality estimators have Φ_D(d) = O(|d|²) (BERT/T5 over full document) but F() = 0 (no combiner — there is no query). They are computed offline and stored as a single scalar per document. The cost is paid at index time, not at query time.

15. Training Strategies

Pointwise Training

Predict relevance of each (q,d) pair independently. Simple but ignores relative ordering between documents.

Pointwise MSE Loss (Regression)
\[ \mathcal{L}_{\text{MSE}} = \left(\text{Rel}(d \mid q) - l\right)^2 \]

Where l is the graded relevance label (e.g., 0–4 from TREC scale). The model predicts a real-valued relevance score and is trained to minimise squared error from the label.

Binary Cross-Entropy Loss (Classification)
\[ \mathcal{L}_{\text{BCE}} = -y \log \hat{y} - (1-y) \log(1-\hat{y}) \]
🔶 Practice

A model predicts ŷ=0.9 for a relevant document (y=1). Compute the loss.

✅ Solved

L = -1·log(0.9) - 0·log(0.1) = -log(0.9) ≈ 0.105 (low loss, correct prediction)

7.2 Pairwise Training (RankNet / In-batch Negatives)

Softmax In-Batch Loss
\[ \mathcal{L} = -\log \frac{e^{s(q,d^+)}}{e^{s(q,d^+)} + \sum_{d^- \in \mathcal{B}} e^{s(q,d^-)}} \]
🔶 Practice

Batch has 1 positive (score=2.0) and 2 negatives (scores 0.5, 0.3). What is the in-batch loss?

✅ Solved

Numerator: e²·⁰ ≈ 7.389

Denominator: 7.389 + e⁰·⁵ + e⁰·³ = 7.389 + 1.649 + 1.350 = 10.388

Loss = -log(7.389/10.388) = -log(0.711) ≈ 0.340

Hard Negatives

In-batch negatives are easy (random docs unlikely to be relevant). Hard negatives are near-misses — retrieved by BM25 or a weaker model but not relevant. Critical for strong performance.

  • BM25 negatives: top-k BM25-ranked non-relevant docs — lexically similar but semantically different
  • MS-MARCO click negatives: documents shown to users but not clicked for a query — implicit human judgement of non-relevance
  • Model-mined negatives (iterative): top-k from a trained retrieval model, updated each training epoch
  • Denoised (ColBERT v2): cross-encoder re-labels top-k candidates to remove false negatives

Synthetic Training Data

When labelled (query, document) pairs are scarce, synthetic data can be generated:

InPars

Uses a large LLM (GPT-3) with few-shot examples to generate queries for each document. Produces (doc → synthetic query) pairs. Model fine-tuned on these pairs achieves competitive performance even without human labels.

Promptagator

Uses FLAN (instruction-following LLM) to generate task-specific queries for a target domain. Task instructions in the prompt enable adaptation to specialised domains (biomedical, legal, etc.) without any domain-labelled data.

Knowledge Distillation

KL-Divergence Distillation Loss
\[ \mathcal{L}_{KD} = \text{KL}(P_{teacher} \| P_{student}) = \sum_i P_T(i) \log \frac{P_T(i)}{P_S(i)} \]
🔶 Practice

Why distill from a cross-encoder teacher to a bi-encoder student instead of training the bi-encoder directly?

✅ Solved

Cross-encoders achieve higher ranking quality (full query-doc attention) but are too slow for retrieval. Distillation transfers the teacher's soft probability distributions (richer signal than binary relevance labels) to train a faster bi-encoder student — combining the teacher's quality with the student's speed.

8. Retrieval Engines for Neural Models

Forward Index

The forward index maps documents → list of terms (opposite of inverted index which maps terms → documents). Used for:
• Relevance feedback (finding related terms for a known document)
• Pseudo-relevance feedback — identifying expansion terms from top-k retrieved documents
• Impact-ordered posting lists (need to retrieve document's full term list)
In neural IR, the forward index may store pre-computed dense vectors or ColBERT token embeddings.

ANN Search for Dense Retrieval: HNSW

HNSW (Hierarchical Navigable Small World) is the dominant ANN structure for dense retrieval. Built on the cluster hypothesis: nearby vectors in embedding space are likely to be relevant.

HNSW Structure

Hierarchical layers: Each document appears in multiple layers. Upper layers have fewer nodes (sparse graph, long-range connections for fast navigation). Lower layers have more nodes (dense graph, precise local search). Search proceeds top-down: traverse upper layers quickly, refine in lower layers.

Key property: Based on cluster hypothesis — if A is similar to B and B is similar to C, A is likely similar to C. This allows greedy graph traversal to find approximate nearest neighbours without exhaustive search.

Trade-off: Construction time O(N log N), query time O(log N) — vs. exact search O(N). Small quality loss (~1–2% recall) for 10–100× speedup.

FAISS Inner Product Search
\[ \hat{d}^* = \arg\max_{d \in \mathcal{C}} E_Q(q) \cdot E_D(d) \]
🔶 Practice

A corpus has 10M documents, each with a 768-dim float32 vector. How much RAM does the flat (exact) FAISS index require?

✅ Solved

Storage = 10M × 768 × 4 bytes = 30,720,000,000 bytes ≈ 28.6 GB

In practice, product quantisation (PQ) compresses vectors 8–64× at slight recall cost, making this feasible on a single machine.

8.2 Cascade / Multi-Stage Pipeline

Adaptive Re-Ranking: GAR and LADR

Standard re-ranking uses a fixed cascade. Adaptive re-ranking uses the corpus graph (connections between similar documents) to dynamically find more candidates to re-rank.

GAR (Graph-based Adaptive Retrieval)

After initial retrieval, traverse the corpus graph: for each retrieved document, add its nearest neighbours (by embedding similarity) to the candidate set. Re-rank the expanded set. Finds semantically related documents that the initial retrieval missed.

LADR (Lexically-Accelerated Dense Retrieval)

Combines lexical (BM25) and dense retrieval via corpus graph traversal. Uses BM25 to retrieve initial candidates, then uses the corpus graph to find dense-retrieval-style neighbours of those candidates. Avoids full FAISS index query while approximating dense retrieval quality.

Corpus Graph

A pre-computed graph where nodes = documents, edges = k-nearest neighbours by dense embedding similarity (e.g., k=16). Used for traversal at query time. Analogous to HNSW but interpreted as a document similarity structure for retrieval augmentation.

Learned Sparse (SPLADE) + Inverted Index

SPLADE vectors are sparse over a 30k-vocabulary → compatible with classical inverted index infrastructure. Achieves dense-model quality with sparse-retrieval speed.

9. RAG — Retrieval-Augmented Generation

RAG combines a neural retriever with a generative LLM. Retrieved documents provide grounding context, reducing hallucination and keeping knowledge up-to-date.

RAG Marginalisation
\[ P(y|x) = \sum_{z \in \text{top-k}} P(z|x) \cdot P(y|x, z) \]
🔶 Practice

What are the two key failure modes of RAG systems?

✅ Solved

1. Retrieval failure: Relevant documents not in top-k → generator has no correct context to ground on.

2. Generator ignoring context: LLM relies on parametric knowledge instead of retrieved docs (context faithfulness issue). Mitigated by prompt engineering ("Answer only using the provided documents").

Short Answer

Q: What is the "late interaction" in ColBERT and why does it improve over bi-encoders?
Late interaction: query and document are encoded independently, but scoring involves fine-grained token-level interactions (MaxSim). Unlike bi-encoders (single vector dot product), late interaction retains per-token query information, allowing each query token to find its best-matching document token — richer than a single compressed vector.
Q: Describe the two-stage retrieve-and-rerank pipeline and why it is used.
Stage 1 (retrieval): Fast model (BM25/bi-encoder) retrieves top-1000 candidates efficiently. Stage 2 (re-ranking): Slow, high-quality model (cross-encoder) re-scores only those 1000. This combines the speed of sparse/dense retrieval with the accuracy of cross-encoders, making high-quality IR tractable at scale.
Q: What makes hard negatives important for training dense retrievers?
Hard negatives are semantically similar to the query but not relevant. They force the model to learn fine-grained distinctions. Random in-batch negatives are too easy (very different from the query) — the model can distinguish them without learning deep semantic similarity, leading to poor performance on actual retrieval tasks.
Q: How does RAG address the knowledge cutoff problem in LLMs?
LLMs have static parametric knowledge frozen at training time. RAG retrieves current documents from an up-to-date corpus at query time and injects them into the prompt context. The generator can then answer using retrieved information rather than relying solely on potentially stale internal knowledge.

H/M [8 marks] Describe the Retrieval-Augmented Generation (RAG) framework. Explain: (a) the role of each component, (b) the marginalisation formula P(y|x), (c) two failure modes, and (d) one technique to mitigate each failure mode.
(a) Retriever (DPR/ColBERT) fetches top-k relevant documents. Generator (LLM) conditions on query + docs to produce answer. (b) P(y|x) = Σz P(z|x)·P(y|x,z) — marginalises over retrieved documents. (c) Failure 1: retrieval failure — relevant doc not in top-k. Failure 2: generator hallucination — ignores retrieved context. (d) Mitigate 1: improve retriever (use dense+sparse hybrid). Mitigate 2: prompt engineering ("answer only from provided documents") or faithfulness fine-tuning.
H [6 marks] Explain knowledge distillation from a cross-encoder teacher to a bi-encoder student. Write the KL-divergence loss and explain why soft labels are preferable to hard binary relevance labels.
Loss: L_KD = KL(P_T || P_S) = Σᵢ P_T(i) log(P_T(i)/P_S(i)) Teacher (cross-encoder) produces probability distributions over candidate docs. Student (bi-encoder) trained to match these distributions. Soft labels encode relative relevance (e.g., 0.9 vs 0.7 vs 0.1) richer than binary (1/0). They convey partial relevance and inter-document relationships, providing stronger training signal — especially valuable for near-relevant documents.
H/M[10 marks]

Q. (a) Describe the generic Φ_Q(q)/Φ_D(d)/F(·) framework for neural relevance models. [2] (b) Using the 2D taxonomy (Encoder cost × Combiner cost), place BM25, Bi-Encoder (DPR), ColBERT, and MonoBERT in the correct cells. [4] (c) Explain DeepCT and SPLADE as learned sparse models. How do they differ from BM25? [4]

(a) score(q,d) = F(Φ_Q(q), Φ_D(d)). Φ_Q = query encoder (cost of encoding query). Φ_D = document encoder (cost of encoding document). F = combiner (cost of combining to produce score). Classification by cost allows predicting latency and scaling behaviour. [2]

(b) BM25: O(|d|) encoder, O(1) combiner (precomputed stats). Bi-Encoder (DPR): O(|d|²) encoder (BERT), O(1) combiner (dot product). ColBERT: O(|d|²) encoder (BERT per token), O(|d|) combiner (MaxSim sum). MonoBERT: O(|d|²) encoder (BERT on joint input), O(|d|²) combiner (full attention between q and d). [4]

(c) DeepCT: passes document through BERT to produce contextualised term frequency weights — same inverted index format as BM25 but TF values learned from context instead of raw counts. SPLADE: uses BERT + log(1+ReLU) activation to produce a sparse vector over full vocabulary — includes expansion terms not in the original document. Both differ from BM25 by: using contextual embeddings (BERT) rather than bag-of-words statistics, and (for SPLADE) expanding the vocabulary beyond terms actually present in the document. [4]
H/M[8 marks]

Q. (a) Distinguish between Mono, Duo, and Listwise neural ranking models. Give one example model for each. [4] (b) Explain HNSW for approximate nearest neighbour search: the hierarchical structure, the cluster hypothesis it relies on, and the trade-off vs. exact search. [4]

(a) Mono models: score each document independently given query. Rel(d|q). Example: MonoBERT/monoT5. Efficient: N inferences for N candidates. Duo models: score pairs of documents given query. Rel(d1 vs d2 | q). Example: DuoBERT. Cost: O(N²) pairs. Better quality through pairwise comparison. Listwise: score the whole ranked list simultaneously. Rel(d? | q, d1, d2, ...). Example: RankGPT (large LM prompted to rank passages). Highest quality but most expensive — must process all candidates at once. [4]

(b) HNSW: hierarchical graph where each document appears at multiple levels. Top levels: few nodes, long-range connections — fast navigation to approximate region. Bottom levels: all nodes, short connections — precise local search. Based on cluster hypothesis: similar documents cluster together in vector space, so greedy traversal from any start node converges to the query's neighbourhood. Trade-off vs. exact FAISS: ~10–100× faster search, but retrieves approximate (not exact) nearest neighbours — typically <2% recall loss. Query time O(log N) vs O(N) for exact. Construction time O(N log N) — paid offline. [4]

Q. Explain two approaches to synthetic training data generation for neural IR when relevance labels are scarce. For each: describe the method, the LLM's role, and one limitation. [6]

InPars: Given a document, prompt a large LLM (GPT-3) with few-shot examples ("Here is a document. Generate a question a user might ask that this document answers"). Produces (document → synthetic query) pairs at scale. Fine-tune retrieval model on these pairs. Role: LLM as a "question generator". Limitation: generated queries may not match real user query distributions — they tend to be longer and more formal than actual search queries. [3]

Promptagator: Uses an instruction-following LLM (FLAN) with task-specific instructions in the prompt ("Generate biomedical research questions that are answered by the following passage"). Enables rapid domain adaptation without domain-labelled data. Role: LLM as a task-conditioned data generator. Limitation: quality depends heavily on prompt quality and LLM's knowledge of the target domain — low-quality prompts produce low-quality training pairs. [3]
