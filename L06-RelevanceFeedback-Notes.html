Why Relevance Feedback?

The Query Formulation Problem

Users often struggle to formulate the right query without knowing the collection's vocabulary or the retrieval model's behaviour. The first query is a trial run. IR is inherently an iterative process.

16+% of web queries are ambiguous. The same query "ash" could refer to ash clouds, a musical band, or a Game of Thrones character.

ASK Hypothesis (Belkin, 1980)

Anomalous State of Knowledge — users' information needs often represent a gap in their knowledge that they cannot fully articulate. This is why iterative feedback and query reformulation are fundamental to IR, not just nice-to-haves.

📋 Explicit Feedback

  • User marks documents as relevant/non-relevant
  • High quality signal — deliberate user action
  • Low quantity — users rarely bother in practice
  • Rocchio algorithm uses explicit feedback
  • Most commonly studied in academic IR

🖱️ Implicit Feedback

  • Inferred from user behaviour (clicks, dwell time)
  • High quantity — happens automatically at scale
  • Noisier signal — clicks ≠ relevance
  • Powers learning-to-rank in commercial engines
  • Raises privacy concerns (user tracking)

Rocchio Algorithm

Rocchio Algorithm (1971) — Query Vector Update
\[ \vec{Q}_{new} = \alpha \vec{Q}_{old} + \frac{\beta}{|D_r|} \sum_{d \in D_r} \vec{d} - \frac{\gamma}{|D_{nr}|} \sum_{d \in D_{nr}} \vec{d} \]

Q_old = original query vector; D_r = set of relevant documents; D_nr = set of non-relevant documents;
α = weight of original query (typically 1);  β = weight towards relevant docs (typically 0.75);  γ = weight away from non-relevant docs (typically 0.25).

Typical Parameter Values

α = 1, β = 0.75, γ = 0.25. Note: γ is often set smaller than β because negative feedback is less reliable than positive feedback. γ = 0.25 is the standard value — not 0.15.

Practice Example

Q_old = (2, 1, 0). One relevant doc D_r = (3, 0, 2). One non-relevant D_nr = (0, 2, 1). Using α=1, β=0.75, γ=0.25, compute Q_new.

✅ Solved Example

Step 1 — Relevant centroid: D_r sum = (3,0,2). β/|D_r| × sum = 0.75 × (3,0,2) = (2.25, 0, 1.5)
Step 2 — Non-relevant centroid: D_nr sum = (0,2,1). γ/|D_nr| × sum = 0.25 × (0,2,1) = (0, 0.5, 0.25)
Step 3 — New query:
Q_new = α×Q_old + relevant_term − nonrelevant_term
= 1×(2,1,0) + (2.25,0,1.5) − (0,0.5,0.25)
= (2+2.25−0, 1+0−0.5, 0+1.5−0.25)
= (4.25, 0.5, 1.25)
New query is pulled towards relevant doc (gains term₃ = 1.25) and away from non-relevant (loses some term₂ weight).

Geometric Interpretation

In the vector space model, each document and query is a point in t-dimensional term space. Rocchio moves the query vector:

  • Towards the centroid of relevant documents (β term)
  • Away from the centroid of non-relevant documents (γ term)
  • The original query is preserved with weight α to prevent complete loss of original intent

Rocchio: Moving Query in Vector Space

Worked Numerical Example (Full)

Query Q = (1, 0, 1, 0). Two relevant docs R1=(2,1,1,0), R2=(1,0,2,1). One non-relevant doc NR=(0,3,0,1). α=1, β=0.75, γ=0.25.

✅ Full Step-by-Step

Relevant centroid: mean(R1,R2) = ((2+1)/2, (1+0)/2, (1+2)/2, (0+1)/2) = (1.5, 0.5, 1.5, 0.5)
β × centroid = 0.75 × (1.5, 0.5, 1.5, 0.5) = (1.125, 0.375, 1.125, 0.375)

Non-relevant centroid: NR = (0, 3, 0, 1). γ × centroid = 0.25 × (0,3,0,1) = (0, 0.75, 0, 0.25)

Q_new = 1×(1,0,1,0) + (1.125,0.375,1.125,0.375) − (0,0.75,0,0.25)
= (1+1.125−0, 0+0.375−0.75, 1+1.125−0, 0+0.375−0.25)
= (2.125, −0.375→0, 2.125, 0.125)

Negative values truncated to 0 (standard practice). Query gains more weight on terms 1 and 3 (shared with relevant docs) and loses weight on term 2 (prominent in non-relevant doc).

Negative Feedback

Why Negative Feedback is Rarely Used

The γ term in Rocchio applies negative feedback by moving the query away from non-relevant documents. In practice, γ is set to a small value (0.25) or even 0. Here is why:

  • Danger of over-suppression: Non-relevant documents may share some terms with relevant documents. Moving away from NR docs can inadvertently suppress good terms.
  • Asymmetric reliability: Users can easily recognise relevant results but marking NR is tedious and less reliable — the signal is noisier.
  • Risk of eliminating new topics: If the NR doc covers a different aspect of the query topic, suppressing it may narrow the query too much.
  • Practical absence in web search: Most web search relevance feedback systems set γ=0 (Rochio with no negative feedback). Users rarely explicitly mark non-relevant results.

Standard γ value

γ = 0.25 is the typical value when negative feedback is used. Some implementations ignore negative feedback entirely (γ = 0), especially for pseudo-relevance feedback where NR docs are not identified.

Pseudo-Relevance Feedback (PRF)

Pseudo-Relevance Feedback (Blind Feedback)

Instead of asking the user, automatically assume the top-k retrieved documents are relevant. Apply Rocchio (or term selection) using these assumed relevant documents to expand the query. No user interaction required.

PRF Process

  1. Submit original query Q₀ to the retrieval system
  2. Take the top-k results (e.g., top 10 or top 20 documents) as the pseudo-relevant set
  3. Extract expansion terms from these documents (using term frequency, KL-divergence, or log-likelihood)
  4. Add the top-m expansion terms to the original query to form Q₁
  5. Re-submit Q₁ and return final results

PRF Advantages

  • No user effort required — fully automatic
  • Works well empirically: typically 10–30% MAP improvement over the baseline
  • Easy to implement on top of any retrieval model
  • Adds vocabulary diversity — helps with vocabulary mismatch
  • Can be applied to every query at query time

PRF Risks and Failure Cases

  • Topic drift: if top documents aren't relevant, PRF amplifies the wrong terms and moves the query away from the intended topic
  • Ambiguous queries: "bank" (river bank vs financial bank) — PRF may lock onto one sense and miss the other
  • Short queries: with little context, the initial retrieval is less reliable, making PRF dangerous
  • Feedback loop: errors in initial retrieval compound when PRF is applied iteratively
  • Less effective when initial retrieval quality is poor (garbage in, garbage out)

Selective Query Expansion

Disable PRF when predicted retrieval quality is poor. Query Performance Predictors (QPPs) estimate initial query quality before seeing results. Apply PRF only to queries predicted to do well. Works well for tasks requiring early precision (e.g., web search).

Pre-retrieval QPP signals

Query scope (Inverse Collection Frequency), Simplified Clarity Score. If predicted quality is low, skip PRF to avoid making things worse.

Term Selection for PRF

Which Terms to Add?

After identifying pseudo-relevant documents, we must choose which terms from those documents are most useful to add to the query. Several principled approaches exist.

Method 1: Simple Term Frequency

Rank terms by their frequency in the pseudo-relevant set. Add the top-m most frequent terms (after removing query terms and stopwords). Simple but effective baseline. Used in Rocchio-style expansion.

Limitation

High-frequency terms in pseudo-relevant docs may also be high-frequency everywhere in the collection — they carry no discriminative information. Need to account for collection frequency.

Method 2: KL-Divergence (Kullback-Leibler)
\[ \text{KL}(R \| C) = \sum_{t} P(t | R) \log \frac{P(t | R)}{P(t | C)} \]

P(t|R) = probability of term t in the pseudo-relevant document set (estimated from tf in relevant docs).
P(t|C) = probability of term t in the entire collection (background model).

KL-divergence measures how different the pseudo-relevant set's language model is from the collection. Terms with high KL contribution are over-represented in relevant docs relative to the collection — they are good expansion terms.

Select the top-m terms ranked by their contribution: \( P(t|R) \log \frac{P(t|R)}{P(t|C)} \)

Intuition

KL selects terms that are characteristic of the relevant set and not just common everywhere. A term that appears often in relevant docs AND in the general collection is not very informative (e.g., "the"). A term that appears much more in relevant docs than the collection average is a good expansion term.

Method 3: Log-Likelihood Ratio (LLR)
\[ \text{LLR}(t) = 2 \left[ c(t,R) \log \frac{p}{p_0} + (N_R - c(t,R)) \log \frac{1-p}{1-p_0} \right] \]

c(t,R) = count of term t in pseudo-relevant set; N_R = total tokens in pseudo-relevant set;
p = c(t,R)/N_R (observed probability in relevant set); p_0 = P(t|C) (collection probability).

The log-likelihood ratio tests whether the term t occurs significantly more often in the pseudo-relevant set than expected under the null hypothesis (term is distributed like in the collection). High LLR → strong evidence the term is topically relevant.

LLR vs KL-Divergence

LLR is a statistical hypothesis test (can produce a p-value). KL-divergence is an information-theoretic measure. Both identify terms over-represented in the relevant set. LLR is more robust for rare terms; KL is simpler to implement. Both are commonly used in PRF term selection.

Practical PRF Term Selection Pipeline

  1. Retrieve top-k documents (e.g., k=10) as pseudo-relevant set
  2. Build a language model P(t|R) from these documents (normalised term counts)
  3. Score each candidate term using KL-divergence or LLR against collection model P(t|C)
  4. Select top-m terms (e.g., m=50) not already in the query
  5. Add to query with appropriate weights (uniform or KL score as weight)

Implicit Feedback

Implicit Feedback

Relevance signals derived from user behaviour without explicit relevance labels. Unlike explicit feedback (user marks documents), implicit feedback is inferred from interaction logs. It is the backbone of modern commercial search engine optimisation.

Clicks

Which search results the user clicks on. Widely used as a proxy for relevance.

  • Positive signal: clicked results are likely more relevant than un-clicked ones at the same rank
  • Position bias: users click rank 1 more than rank 5 regardless of actual relevance — raw click counts are biased
  • Relative comparisons (clicked > un-clicked at nearby ranks) are more reliable than absolute click counts

Dwell Time

How long the user spends on a clicked page before returning to the SERP.

  • Long dwell time (e.g., >30 seconds): user likely found content relevant — strong positive signal
  • Pogo-sticking: quick return to SERP (short dwell) → result was not satisfying
  • Used by search engines to detect poor-quality results even when they receive many clicks

Eye-Tracking (Lab Studies)

In controlled user studies, eye-tracking glasses record where users look on the results page.

  • Reveals the "golden triangle" — users focus attention on the top-left area of search results pages
  • Shows that users often do not look beyond the first 3–4 results
  • Explains why position bias exists in click data
  • Too expensive for real-world deployment; used for research insights

Other Implicit Signals

  • Query reformulation: user changes query after seeing results → dissatisfied with current results
  • Session length: many queries in a session = struggling to find answer (or complex task)
  • Bookmarks / saves / shares: strong positive relevance signal
  • Scroll depth: how far user scrolls on a page — deeper scroll = more engagement
  • Copy-paste: copying text from result = information found relevant

Challenges with Implicit Feedback

Position bias: clicks are biased toward higher ranks — must be corrected (e.g., inverse propensity scoring).
Presentation bias: snippets influence clicks independent of document relevance.
Privacy: collecting user interaction data raises ethical and legal concerns (GDPR).
Noise: misclicks, bots, and adversarial manipulation contaminate the signal.
Despite these issues, implicit feedback at web scale outperforms small-scale explicit feedback.

Query Expansion

Query Expansion

Adding related terms to the original query to improve recall and address vocabulary mismatch between queries and documents. Unlike relevance feedback (which requires retrieved documents), query expansion can be done before retrieval using external resources.

Methods

Thesaurus-based:

  • Manual thesaurus: WordNet, MeSH (medical) — curated synonym/hypernym relationships
  • Statistical thesaurus: build from corpus co-occurrence statistics
  • Co-occurrence similarity: \( \text{cos}(t_1, t_2) = \frac{C}{\sqrt{X \cdot Y}} \) where C = co-occurrence count, X/Y = individual counts
  • Word embeddings: word2vec, GloVe, fastText — nearest neighbours in embedding space are semantically related terms

External Resources:

  • Use Google/Wikipedia/Bing results as pseudo-relevant set for the query
  • "Collection Enrichment" / External Query Expansion
  • Works well for under-resourced or specialised collections
  • Kwok (2003): use Google top results as expansion source
  • Risk: external source may not align with the collection's domain

Thesaurus-Based Expansion: Advantages and Disadvantages

Advantages:

  • No retrieved documents needed — can be applied before retrieval
  • Consistent — same expansion for the same term every time
  • Curated thesauri (WordNet) are high quality
  • Domain-specific thesauri (MeSH) are very precise

Disadvantages:

  • Ignores query context — "bank" gets both "riverbank" and "financial bank" as synonyms
  • Manual thesauri are expensive to build and maintain
  • Statistical thesauri may add noisy, unrelated terms
  • Cannot handle new vocabulary or proper nouns

Co-occurrence-Based Term Similarity

Build a term-term co-occurrence matrix from the corpus. Two terms are similar if they frequently appear in the same documents or within a fixed window of each other.

Cosine Similarity of Term Co-occurrence Vectors
\[ \text{sim}(t_1, t_2) = \frac{\sum_d c(t_1,d) \cdot c(t_2,d)}{\sqrt{\sum_d c(t_1,d)^2} \cdot \sqrt{\sum_d c(t_2,d)^2}} \]

c(t,d) = count of term t in document d. High cosine similarity = terms often co-occur in the same documents = semantically related.

Python: Rocchio Query Expansion (Corrected)

import numpy as np

def rocchio(q_old, rel_docs, non_rel_docs, alpha=1.0, beta=0.75, gamma=0.25):
    # q_old: numpy array (query vector)
    # rel_docs: list of numpy arrays (relevant doc vectors)
    # non_rel_docs: list of numpy arrays (non-relevant)
    # Typical values: alpha=1, beta=0.75, gamma=0.25

    rel_centroid = np.mean(rel_docs, axis=0) if rel_docs else np.zeros_like(q_old)
    nr_centroid = np.mean(non_rel_docs, axis=0) if non_rel_docs else np.zeros_like(q_old)

    q_new = alpha * q_old + beta * rel_centroid - gamma * nr_centroid
    q_new = np.maximum(q_new, 0)  # remove negative weights (standard practice)
    return q_new

q = np.array([2.0, 1.0, 0.0])
rel = [np.array([3.0, 0.0, 2.0])]
nr  = [np.array([0.0, 2.0, 1.0])]

q_new = rocchio(q, rel, nr)  # gamma=0.25 (correct value)
print(f"New query: {q_new}")  # [4.25, 0.5, 1.25]

# KL-divergence based term selection for PRF
def kl_term_scores(rel_model, collection_model, top_m=20):
    # rel_model: dict {term: P(t|R)}, collection_model: dict {term: P(t|C)}
    scores = {}
    for t, p_rel in rel_model.items():
        p_col = collection_model.get(t, 1e-10)  # smoothed probability
        scores[t] = p_rel * np.log(p_rel / p_col)
    return sorted(scores.items(), key=lambda x: -x[1])[:top_m]

Summary

Relevance Feedback

Users mark relevant/non-relevant docs to refine query. Rocchio: Q_new = α·Q + β/|Dr|·ΣDr − γ/|Dnr|·ΣDnr. α=1, β=0.75, γ=0.25. Moves query towards relevant centroid, away from non-relevant centroid.

Negative Feedback

The γ term in Rocchio. Rarely used alone because: suppresses terms shared by relevant+non-relevant docs; users don't reliably mark NR; asymmetric reliability vs positive feedback. γ=0.25 (NOT 0.15).

Pseudo-RF (Blind Feedback)

Assume top-k retrieved docs are relevant. Automatic — no user effort. Typically 10–30% MAP gain. Risks: topic drift on ambiguous/short queries, amplifies initial errors. Selective PRF avoids applying when initial quality is poor.

Term Selection

KL-divergence: score(t) = P(t|R)·log(P(t|R)/P(t|C)). Selects terms over-represented in pseudo-relevant set vs collection. Log-likelihood ratio: statistical test for same purpose. Both outperform simple TF-based selection.

Implicit Feedback

Clicks (noisy, position-biased), dwell time (long=satisfied, short=pogo-sticking), eye-tracking (golden triangle), query reformulation (dissatisfaction), session length. Position bias must be corrected. Powerful at web scale.

Query Expansion

Add related terms before retrieval. Sources: manual thesaurus (WordNet/MeSH), statistical co-occurrence thesaurus, word embeddings (word2vec/GloVe), external resources (Wikipedia, Google). Trade-off: improves recall, risks adding noise.

[2 marks] Components: α=weight of original query (typ. 1), β=weight toward relevant docs (typ. 0.75), γ=weight away from non-relevant (typ. 0.25) [2 marks]. H[10 marks]
Q2. Explain pseudo-relevance feedback (PRF). Describe (a) the PRF process step by step, (b) two advantages and two failure cases, and (c) how KL-divergence is used for term selection in PRF. Give the KL-divergence formula and explain its interpretation.
(a) PRF process: (1) submit original query, retrieve top-k docs as pseudo-relevant set; (2) score candidate expansion terms; (3) select top-m terms; (4) re-submit expanded query [2 marks]. (b) Advantages: automatic — no user effort; typically 10–30% MAP improvement [2 marks]. They are not just frequent everywhere (captured by P(t|C) in denominator) but specifically associated with the relevant topic. [4 marks]
H/M[8 marks]
Q3. Compare explicit, implicit, and pseudo-relevance feedback. For each: what information is used, what are the main advantages, and what are the limitations? Which is most commonly used in commercial web search and why?
Explicit feedback: user deliberately marks docs as relevant/non-relevant. High quality signal. Advantage: accurate. Limitation: users rarely provide it — high cognitive burden, low adoption [2 marks]. Implicit feedback: inferred from behaviour (clicks, dwell time, eye-tracking, reformulations). High quantity at web scale. Advantage: abundant, automatic. Limitation: noisy (position bias, misclicks, presentation bias), privacy concerns [2 marks]. Pseudo-relevance feedback: automatically assume top-k docs are relevant. No user interaction. Advantage: fully automatic, works at query time. Limitation: risky for ambiguous/short queries — topic drift if initial retrieval is poor [2 marks]. Commercial web search uses implicit feedback most (Google, Bing, etc.) because it provides billions of signals per day at zero user burden. Explicit feedback is impractical at scale; PRF is used as a supplementary technique [2 marks].
H[8 marks]
Q4. Describe three methods for query expansion that do not require user relevance feedback. For each, briefly explain how it works and give one limitation. Which method is most robust to query ambiguity?
Three methods: (1) Manual thesaurus (e.g., WordNet): expand query terms with synonyms/hypernyms from a curated lexical database. Limitation: ignores word sense — "bank" gets financial and river synonyms regardless of context [2 marks]. (2) Statistical co-occurrence thesaurus: find terms that frequently co-occur with query terms across the corpus; compute cosine similarity of co-occurrence vectors. Limitation: may find topically related but not synonymous terms; noisy for rare query terms [2 marks]. (3) External query expansion (Collection Enrichment): submit query to an external resource (Google, Wikipedia), treat top results as pseudo-relevant, extract expansion terms. Limitation: external source may not match the domain or vocabulary of the local collection [2 marks]. Most robust to ambiguity: statistical co-occurrence, because it is grounded in the target collection's own vocabulary and does not rely on external ontologies that may not resolve ambiguity contextually. However, word embeddings (word2vec) are even more robust as they encode distributional context [2 marks].
H/M[6 marks]
Q5. Explain the concept of position bias in implicit feedback. How does it affect the reliability of clicks as relevance signals? Describe one technique to correct for position bias.
Position bias: users are more likely to click a result at rank 1 than rank 5, even if the rank-5 result is more relevant. This occurs because: (1) users tend to read top-to-bottom (confirmed by eye-tracking showing the "golden triangle"); (2) users assume top results are more relevant; (3) lower results may not even be seen. [2 marks] Effect on reliability: raw click counts cannot be directly interpreted as relevance. A result at rank 1 getting 1000 clicks vs rank 5 getting 200 clicks does not mean rank-1 is 5× more relevant — rank-1's clicks are inflated by position. Absolute click counts are not reliable; relative clicks (clicked-vs-skipped at similar ranks) are more trustworthy. [2 marks] Correction technique: Inverse Propensity Scoring (IPS) — estimate the probability p(rank) that a user examines position rank; weight clicks by 1/p(rank) to debias. Alternatively, use relative comparisons from interleaving where position effects cancel. [2 marks]
Flashcards
Rocchio Algorithm
Q_new = α·Q_old + β/|Dr|·ΣDr − γ/|Dnr|·ΣDnr. Typical: α=1, β=0.75, γ=0.25. Moves toward relevant centroid, away from non-relevant.
Rocchio γ value
γ = 0.25 (NOT 0.15). Weight applied away from non-relevant documents. Often set to 0 in PRF (no NR docs identified).
Pseudo-Relevance Feedback
Automatically assume top-k retrieved docs are relevant. Apply Rocchio without user interaction. Risk: topic drift on ambiguous queries.
KL-Divergence (PRF)
score(t) = P(t|R)·log(P(t|R)/P(t|C)). Selects terms over-represented in relevant set vs collection. Best principled term selection method.
Log-Likelihood Ratio
Statistical test: is term t significantly more frequent in pseudo-relevant set than expected from collection? Alternative to KL for term selection. Robust for rare terms.
Query Expansion
Adding related terms to a query to improve recall. Sources: thesaurus, word embeddings, PRF, external resources (Wikipedia, Google).
ASK Hypothesis
Anomalous State of Knowledge (Belkin 1980). Users' information needs are gaps in knowledge — hard to articulate precisely. Motivates iterative/interactive IR.
Topic Drift
When query expansion adds irrelevant terms, shifting retrieval away from the original topic. Main risk of PRF on ambiguous/short queries.
Position Bias
Users click rank-1 more than rank-5 regardless of relevance. Makes raw clicks unreliable. Corrected by IPS or relative (interleaving-based) comparisons.
Dwell Time
Time spent on clicked page. Long dwell = relevant. Short dwell ("pogo-sticking") = not satisfied. Used alongside clicks for richer implicit feedback.
Explicit vs Implicit
Explicit: user marks relevant/NR (high quality, low quantity). Implicit: inferred from clicks/dwell (high quantity, noisy). PRF: automatic, no user, risky.
Collection Enrichment
External query expansion: submit query to Google/Wikipedia, use top results as pseudo-relevant set for term extraction. Good for small/specialised collections.
