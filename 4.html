1. What is Text Classification?

Core Definition

The task of predicting which of a predefined set of classes (categories) an object belongs to — assigning a label to text based on pre-trained knowledge.

In NLP, objects we classify include: Web pages • News articles • Emails • Product descriptions • Social media posts • NL questions • Individual words
Applications
Topic

Is this about Technology / Sports / Lifestyle?

Spam

Is this comment/email spam?

Sentiment

Does this tweet express negative opinion?

Language ID

Is this written in Spanish?

Authorship

Was this written by John Smith?

Discourse

Is this Reddit post a question, answer, or clickbait?

2. Classification Types

Binary vs Multi-Class vs Multi-Label

Binary Classification

  • Each item belongs to exactly 1 of 2 classes
  • Number of classes: 2
  • Labels per item: Exactly 1
Example: Spam vs Not-Spam • Positive vs Negative sentiment

Multi-Class Classification

  • Each item belongs to exactly 1 of >2 classes
  • Number of classes: > 2
  • Labels per item: Exactly 1
Example: News topic: Sports / Politics / Tech / Entertainment

Multi-Label Classification

  • Each item can belong to 0, 1, or many classes
  • Number of classes: > 2
  • Labels per item: Any number
Example: A news article can be tagged: Tech + Health + Business simultaneously

Extreme Classification / Extreme Labeling

When the number of classes scales to thousands, millions, or billions — special techniques are required.

  • Standard classifiers become computationally infeasible
  • Requires hierarchical or approximate methods
  • Example: Classifying a product into Amazon's full taxonomy

Vectorisation Methods

Count how many times each word occurs in a document.

Vocabulary: [bru, i, irn, like, sprite]
Doc: "I like sprite"
Vector: [0, 1, 0, 1, 1]

1 if word occurs, 0 if not — ignores frequency.

"I like sprite like like" → [0, 1, 0, 1, 1] (NOT [0, 1, 0, 3, 1])

Weights words by frequency in document but inverse frequency across corpus.

TF(t,d) = count(t in d) / total terms in d
IDF(t) = log(N / df(t))
TF-IDF(t,d) = TF(t,d) × IDF(t)
Common words (like "the") get low IDF → low weight. Rare distinctive words get high weight.
Feature Engineering

Some tasks benefit from hand-crafted features beyond raw word counts.

Author Attribution features:
Average word length, average sentence length, punctuation frequency (Juola, 2006)
Warning: More features ≠ better performance. Features can confuse a classifier. Feature selection matters!

5. Classifiers Overview

What is a Classifier?

A function f(x) that maps an N-dimensional feature vector to a label. It learns a "model" from training data.

if counts['great'] > 2:
    return 'positive'
else:
    return 'negative'
# Simple rule-based classifier
Naive Bayes +

Probabilistic classifier based on Bayes' theorem with "naive" independence assumption.

P(class|doc) ∝ P(class) × ∏ P(word_i|class)
  • Fast, works well with little data
  • Strong baseline for text classification
  • Good for: spam detection, sentiment, language ID
Logistic Regression +

Discriminative classifier learning weights for features. Output is a probability.

P(y=1|x) = σ(w·x + b) = 1/(1+e^(-(w·x+b)))
  • Interpretable weights
  • Good probabilistic output
  • Foundation for neural networks
SVM — Support Vector Machine +

Finds the maximum-margin hyperplane separating classes.

  • Very effective for high-dimensional text features
  • Kernel trick for non-linear boundaries
  • Strong performer for many NLP tasks
Decision Tree / Random Forest +

Tree-based methods that split data on features recursively.

  • Highly interpretable (decision tree)
  • Random Forest = ensemble of trees → more robust
  • Can overfit easily (single tree)
Handling Multi-Class with Binary Classifiers
One-vs-All (OvA)
Train one binary classifier per class. Positive = that class, Negative = all others.
K classifiers for K classes.
All-vs-All (AvA)
Train classifier for each pair of classes.
K(K-1)/2 classifiers — doesn't scale to extreme classification!
Hyperparameters
Classification pipelines have many tunable options: vectorisation approach, classifier type, classifier settings (e.g. regularisation strength C in SVM/LR).

Hyperparameter tuning: Try different combinations systematically. Use libraries like optuna or scikit-learn's GridSearchCV.

6. Logistic Regression (Deep Dive)

From Jurafsky & Martin, Chapter 4

The Sigmoid Function

The sigmoid maps any real number to (0,1) — perfect for probabilities.

σ(z) = 1 / (1 + e−z)

P(y=1|x) = σ(w·x + b)
P(y=0|x) = 1 − σ(w·x + b)
Key property: 1 − σ(x) = σ(−x)
The input z = w·x + b is called the logit.
σ(z) = 0.500
Worked Example: Sentiment Classification

Features for the review: "It's hokey. There are virtually no surprises... I love this place!"

FeatureDefinitionValueWeight
x₁count(positive words)3+2.5
x₂count(negative words)2−5.0
x₃1 if "no" in doc1−1.2
x₄count(1st/2nd pronouns)3+0.5
x₅1 if "!" in doc0+2.0
x₆ln(word count) = ln(66)4.19+0.7
z = w·x + b = [2.5×3] + [−5.0×2] + [−1.2×1] + [0.5×3] + [2.0×0] + [0.7×4.19] + 0.1
= 7.5 − 10.0 − 1.2 + 1.5 + 0 + 2.933 + 0.1 = 0.833

P(+|x) = σ(0.833) ≈ 0.70 → Positive!
Cross-Entropy Loss
L_CE(ŷ, y) = −[y·log(ŷ) + (1−y)·log(1−ŷ)]
Correct prediction (y=1, ŷ=0.70):
L = −log(0.70) ≈ 0.357 (low loss)
Wrong prediction (y=1, ŷ=0.30):
L = −log(0.30) ≈ 1.204 (high loss)
We minimise this loss using Gradient Descent — iteratively update weights in the direction that reduces loss.
Regularisation (Avoiding Overfitting)
L2 (Ridge):
Adds λ‖w‖² to the loss. Shrinks weights toward zero. Most common for logistic regression.
L1 (Lasso):
Adds λ‖w‖₁ to the loss. Produces sparse weights — drives some to exactly 0.
Practice Problems — Logistic Regression
Practice LR1: Compute P(y=1|x) +

Given: weights w = [2, −1, 3], bias b = −0.5, and input x = [1, 2, 0].
Calculate P(y=1|x) using logistic regression. Show full working.

z = w·x + b = (2×1) + (−1×2) + (3×0) + (−0.5)
z = 2 − 2 + 0 − 0.5 = −0.5

σ(z) = 1 / (1 + e^(−(−0.5))) = 1 / (1 + e^0.5) = 1 / (1 + 1.6487) = 1 / 2.6487 ≈ 0.378

P(y=1|x) ≈ 0.378 → Classified as negative (below 0.5 threshold)
Practice LR2: Cross-Entropy Loss +

A model predicts ŷ = 0.3 for a sample where the true label is y = 1. Calculate the cross-entropy loss. Then compare to loss when ŷ = 0.9 for the same sample.

L_CE = −[y·log(ŷ) + (1−y)·log(1−ŷ)]

When ŷ=0.3, y=1: L = −[1·log(0.3) + 0] = −log(0.3) = −(−1.204) ≈ 1.204

When ŷ=0.9, y=1: L = −[1·log(0.9) + 0] = −log(0.9) = −(−0.105) ≈ 0.105
The model is heavily penalised for ŷ=0.3 when the true label is 1 (loss=1.204). Confident correct predictions (ŷ=0.9, y=1) get very low loss (0.105). This is how cross-entropy drives the model to be confident and correct.
Practice LR3: C parameter and regularisation (Lab 4 style) +

In scikit-learn's LogisticRegression, the parameter C controls regularisation. You try C=1 (default) and C=10. Training F1 improves significantly with C=10, but so does validation F1. Does this indicate overfitting? What does C control?

C = 1/λ — the inverse of regularisation strength.

C=1: More regularisation → weights are penalised more → model can't fit training data as closely.
C=10: Less regularisation → model can learn stronger per-feature weights.

If both training AND validation F1 improve with C=10, this is NOT overfitting — it means the model was underfitting with C=1 (too much regularisation suppressing useful features). Overfitting would show training F1 going up but validation F1 going down.

Precision vs Recall — The Tradeoff
Precision
P = TP / (TP + FP)

Of all items I predicted as positive, what fraction actually are?

High precision = few false alarms

Recall
R = TP / (TP + FN)

Of all items that actually are positive, what fraction did I find?

Also called: Sensitivity, True Positive Rate

The Tradeoff: Increasing precision often decreases recall and vice versa. The decision threshold controls this.
F1 and F-beta Scores
F1 = 2 × (Precision × Recall) / (Precision + Recall)   =   2TP / (2TP + FP + FN)

Fβ = (1 + β²) × (P × R) / (β²×P + R)
F0.5
Weights Precision more
F1
Equal weight (most common)
F2
Weights Recall more
When to use Fβ? Medical diagnosis → use F2 (missing a disease is worse than false alarm). Spam filter → use F0.5 (false alarms more annoying than missing spam).
The Problem with Accuracy
Class Imbalance Problem: If 99% of emails are NOT spam, a classifier that always predicts "Not Spam" achieves 99% accuracy — but is useless!

Use Precision, Recall, F1 instead when classes are imbalanced.

Practice P1: Confusion Matrix Calculation (Lab 4 style) +

A clinical trial classifier gives on the validation set: TP=20, FP=8, FN=52, TN=124. Calculate accuracy, precision, recall, and F1. Then interpret: is this a good classifier?

Accuracy = (20+124)/(20+8+52+124) = 144/204 ≈ 0.706
Precision = 20/(20+8) = 20/28 ≈ 0.714

The "always predict False" dummy classifier achieves accuracy ≈ 0.647 (the proportion of negatives). So 0.706 is only slightly better. High precision but very low recall — the classifier misses most clinical trials. F1=0.40 reflects this imbalance.

Practice P2: Spot the F1 Error (Exam-style) +

A report claims: Precision = 0.2, Recall = 0.5, F1 = 0.6. Is the F1 value correct? Show your working.

F1 = 2 × (P × R) / (P + R) = 2 × (0.2 × 0.5) / (0.2 + 0.5)
= 2 × 0.10 / 0.70 = 0.20 / 0.70 ≈ 0.286
The reported F1 of 0.6 is WRONG. The F1 score (harmonic mean) must always be between the precision and recall values. Since P=0.2 and R=0.5, F1 must be between 0.2 and 0.5. A value of 0.6 is mathematically impossible. This appeared as an anomaly in the 2025 exam!
Practice P3: Macro vs Weighted F1 +

Three-class classifier with results: Class A: F1=0.80, n=100 | Class B: F1=0.60, n=50 | Class C: F1=0.40, n=50. Calculate Macro-F1 and Weighted-F1.

Macro-F1 = (0.80 + 0.60 + 0.40) / 3 = 1.80/3 = 0.600

Weighted-F1 = (100×0.80 + 50×0.60 + 50×0.40) / (100+50+50)
= (80 + 30 + 20) / 200 = 130/200 = 0.650
Weighted-F1 (0.650) > Macro-F1 (0.600) here because Class A (the best class) has the most samples. Macro-F1 treats all classes equally. Use Macro when all classes matter equally; use Weighted when class frequency matters.

8. ROC Curves & AUC

Classifier Scores vs Labels

Most classifiers output a score, not just a label. We choose a threshold to convert scores to labels.

Example scores:
"Delicious food. Would go again" → Score: 0.82 → Positive
"Horrible place. Never again" → Score: 0.05 → Negative
"Bad food. Great staff" → Score: 0.47 → depends on threshold!
ROC Curve Construction

Sort predictions by score, then sweep threshold from highest to lowest:

  • Start at bottom-left (0,0)
  • Each actual positive: move UP (TPR ↑)
  • Each actual negative: move RIGHT (FPR ↑)
  • End at top-right (1,1)

Micro Average: Calculate global TP, FP, FN from per-class confusion matrices, then compute metric. Favours majority classes.
Micro-Precision = Σ(TP_i) / Σ(TP_i + FP_i)
Weighted Average: Take a weighted mean of per-class metrics, weighted by class frequency. Accounts for class imbalance.
Weighted-F1 = Σ(n_i × F1_i) / Σ(n_i)
K-Fold Cross-Validation
Why? For small datasets, k-fold gives a more reliable estimate of generalisation performance. You still want a separate final test set!
Statistical Significance Testing
Higher score ≠ Better model!
Small differences (0.682 vs 0.688 on N=27 test set) may be due to random chance. Use statistical tests (e.g. McNemar's test, bootstrap) to check if improvement is statistically significant.
Evaluating Multi-Label Classifications
Problem: You cannot create one global confusion matrix for multi-label classification — no single accuracy measure applies across all labels simultaneously.
Solution: Per-Label Evaluation
Create a separate confusion matrix for each label. Calculate Precision, Recall, and F1 for each label independently. Then aggregate using macro-average (equal weight per label) or micro-average (weighted by label frequency).
Example: For a document tagged with labels {Sports, Finance, Politics}:
→ Build 3 binary classifiers (one per label)
→ Evaluate each separately: Sports F1=0.82, Finance F1=0.74, Politics F1=0.79
→ Macro-F1 = (0.82 + 0.74 + 0.79) / 3 = 0.783

10. Building a Better Classifier

Why Doesn't My Classifier Do Better?
Data Problems
  • Label noise (unclear annotation guidelines)
  • Feature noise (typos, inconsistencies)
  • Class imbalance
  • Not enough data
Feature Problems
  • Missing key features
  • Irrelevant features added
  • Features not scaled properly
  • Wrong representation
Classifier Problems
  • Underfitting (too simple)
  • Overfitting (too complex)
  • Wrong algorithm
  • Poor hyperparameter tuning
Underfitting vs Overfitting
Underfitting: Model is too simple to capture patterns. High training error AND high test error.
Fix: More complex model, more features.
Overfitting: Model fits training data too closely. Low training error but HIGH test error.
Fix: Regularisation, simpler model, more training data.
Good fit: Low error on both training and test sets. Generalises well.
Error Analysis
Step 1: Look at errors on the training set → Do features have the right values? Are labels correct?
Step 2: Look at errors on the validation set → Which classes have most mistakes? Are there obvious missing features?
Prioritise: Get ~100 mislabelled validation examples. Count error types. If sports/business confusion = 50% of errors → fix it. If it's only 5% → don't waste time.
NEVER use test set insights to refine your model. That would invalidate your evaluation.
Class Imbalance Solutions
Evaluation: Don't use accuracy. Use F1, AUC, or per-class metrics.
Training: Resample training set to equal balance (oversample minority / undersample majority). Or use class-weighted loss.
Classifiers Don't Always Use the Patterns We Expect
What we hope: The classifier learns meaningful, interpretable features — e.g., sentiment words like "impeccable", "terrible", "fresh" that a human would also use.
What may actually happen: The classifier exploits spurious correlations in the training data — e.g., the article "a" appearing more frequently in negative reviews due to dataset-specific artefacts.
Why this matters: A model exploiting spurious patterns may get high training/test scores on one dataset but fail to generalise to new data or domains. Always inspect which features the model relies on.
Real example (Pang & Lee, 2004): A top-weighted feature in a sentiment classifier was the word "a" — correlating with negative reviews not because "a" expresses sentiment, but due to writing style differences between positive and negative reviewers in the training corpus.
Interpretability & Explainability
Inspecting weights (Logistic Regression): Because LR assigns a learned weight to each feature, you can directly inspect the top positive/negative weights — making LR one of the most interpretable classifiers. SVMs share this property for linear kernels.
LIME (Local Interpretable Model-agnostic Explanations)
Fits a simple local linear model around a single prediction to explain why the classifier made that decision. Works for any black-box model.
SHAP (SHapley Additive exPlanations)
Uses game-theory Shapley values to assign each feature a contribution score for a specific prediction. Consistent and theoretically grounded.
Caution: LIME and SHAP are vast simplifications of the model's true decision process. Explainability for complex models is an unsolved problem. Explanations can be misleading or unstable — treat them as approximations, not ground truth.
Other Tricks for Tweaking Performance
Upweighting: Give more importance to features from certain document regions by counting them multiple times in your feature vector.
Title words ×2 — Count words appearing in the title twice in the BoW vector. (Cohen & Singer, 1996)
First paragraph sentences — Weight sentences in the opening paragraph more heavily, as they tend to state the main topic. (Murata, 1999)
Sentences containing title words — Boost sentences that contain words from the document title, as they are likely topic-relevant. (Ko et al., 2002)
These are domain-specific heuristics — they work for news article classification but may not transfer to other text types (e.g., social media, legal documents). Always validate on your domain.

11. The Right Workflow

Step-by-Step Correct Workflow
1
Split Data into Train / Validation / Test sets before any modelling.
2
Train classifier on training set only.
3
Fit training set well — check for underfitting.
4
Fit validation set well — tune hyperparameters, do error analysis using validation.
5
Evaluate on test set — ONCE, for final performance estimate only.
6
Deploy — perform well in the real world!
Common Mistakes:
1. Using ALL data for training (no test set)
2. Measuring performance on training data
3. Using test set insights to tune the model (data leakage!)

Q1. Explain the difference between precision and recall. Give a practical example of when you would prioritise recall over precision.
Show Model Answer +

Precision: Of all items predicted as positive, what fraction truly are? P = TP/(TP+FP).

Recall: Of all truly positive items, what fraction did we find? R = TP/(TP+FN).

Example prioritising recall: Medical cancer screening. Missing a true cancer (FN) is far more dangerous than a false alarm (FP) that leads to further testing. We want to find ALL cancers even if we flag some healthy patients.

Q2. What is the difference between macro-averaged and micro-averaged F1? When would each be more appropriate?
Show Model Answer +

Macro-F1: Compute F1 for each class, take unweighted mean. Each class counts equally regardless of size.

Micro-F1: Pool all TP, FP, FN globally then compute F1. Dominated by majority class performance.

Use macro when all classes are equally important (e.g., rare disease classification). Use micro when class imbalance reflects real world frequency and you care about overall example-level accuracy.

Q3. Explain overfitting in the context of text classification. What causes it and how can it be mitigated?
Show Model Answer +

Overfitting: The model learns the training data too closely — it memorises noise and specific patterns that don't generalise. Low training error but high test error.

Causes: Too many features relative to training data size; overly complex model; insufficient training data.

Mitigation: Regularisation (L1/L2); reduce model complexity; collect more data; use cross-validation; feature selection; dropout (neural nets).

Q4. Why is it important to use a separate validation set and test set, rather than just a single held-out set?
Show Model Answer +

The validation set is used repeatedly during development — for tuning hyperparameters, feature selection, error analysis, and model selection. By using the validation set many times, the model is effectively "tuned" to it.

The test set must remain completely unseen until final evaluation to give an unbiased estimate of real-world performance. If we used the same set for both, our performance estimate would be optimistically biased — the model has indirectly "seen" the test set through our tuning decisions.

Q5. What is the One-vs-All (OvA) strategy for multi-class classification? What is its limitation?
Show Model Answer +

OvA trains K binary classifiers for K classes. Each classifier discriminates one class against all others. At test time, run all K classifiers and pick the class with the highest confidence.

Limitation: Doesn't scale to extreme classification (thousands/millions of classes). K classifiers needed, each with highly imbalanced training data (1 class vs all others).

Q6. What is the ROC curve and what does AUC measure? What does AUC=0.5 signify?
Show Model Answer +

The ROC (Receiver Operating Characteristic) curve plots True Positive Rate (recall) vs False Positive Rate at different classification thresholds.

AUC (Area Under the Curve) summarises the ROC into a single number from 0–1. It represents the probability that the classifier ranks a random positive example higher than a random negative example.

AUC = 0.5: Random classifier — no discriminative power. The curve follows the diagonal y=x line.

Q3. [Discussion] "Adding more features always improves classifier performance." Critically evaluate this statement. (8 marks)
Show Key Points +

Against the statement:

  • Irrelevant features add noise, confuse the classifier
  • More features → higher dimensionality → risk of overfitting (curse of dimensionality)
  • Correlated features can cause numerical instability (e.g. multicollinearity in LR)
  • Increases computational cost without benefit
  • Lecture explicitly states: "adding more features is not always useful"

Partial truth:

  • The right additional features CAN improve performance
  • Domain-specific features (e.g. upweighting title words) can help
  • Feature selection/regularisation can mitigate the negative effects

Conclusion: Quality over quantity. Thoughtful feature engineering guided by error analysis and domain knowledge is more valuable than blindly adding features.

2025 Resit Exam 4 marks Sub-word Tokenization ⭐
Q8. [2025 Q3d] A BERT-based model fine-tuned on open benchmark sentiment data classifies every sample mentioning the brand name "BeStep" as positive sentiment. False positives include:
  • "I disliked my experience with bestep."
  • "@Bestep I placed an order three weeks ago, and still haven't gotten it!"
  • "I'm not happy with my purchase BeStep. I want a refund."
The problem is caused by sub-word tokenisation. Describe the problem and suggest a solution.
Show Model Answer +

Problem: BERT uses WordPiece tokenisation. The brand name "BeStep" / "bestep" is likely split into subwords such as best ##ep. The token "best" is strongly associated with positive sentiment in the model's training data. Therefore, any text containing "BeStep" triggers the positive sentiment prediction, regardless of the actual sentiment expressed.

Solution: Replace the brand name "BeStep" with a neutral placeholder (e.g., [BRAND] or COMPANY) before feeding text to the model. This ensures the brand name doesn't tokenise into sentiment-bearing subwords. The placeholder itself won't carry any sentiment signal from pre-training.

Why this matters: This is an example of a model exploiting spurious correlations in training data — the model associates the token "best" with positive sentiment because "best" commonly appears in positive reviews. The fix is to remove the source of the spurious signal.

Q11. [2025 Q2b] You realise that samples with the "comfort food" label have been triplicated (repeated 3×) in your dataset. This error occurred before any data splitting. Give four effects this would have on training and evaluation.
Show Model Answer +
  1. Class imbalance — "comfort food" now has 3× more samples than other classes, creating artificial imbalance.
  2. Training bias — The classifier will over-focus on "comfort food" features during training, potentially at the expense of other classes.
  3. Test set leakage — When splitting the data, copies of the same "comfort food" sample may end up in both the training set AND the evaluation (val/test) set. This means the model is effectively evaluated on data it has already seen, inflating performance metrics.
  4. Unrealistic class distribution — The artificial imbalance doesn't reflect the true distribution of recipes on the website, so performance metrics won't reflect real-world performance.
Key concept: Test set leakage (data contamination) is one of the most serious evaluation errors — it makes your results look better than they really are. Always deduplicate before splitting!
