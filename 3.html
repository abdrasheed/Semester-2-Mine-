2. Probability Review

Core Rules

0 ≤ P(x) ≤ 1    and    Σx P(x) = 1
Joint
P(A, B)

Probability of both A and B occurring together.

Conditional
P(A | B) = P(A,B) / P(B)

Probability of A given B has occurred.

Chain Rule
P(A,B,C) = P(A|B,C)·P(B|C)·P(C)

Decomposes joint probability.

Bayes' Theorem

P(A | B) = P(B | A) · P(A) / P(B)

Lets us "reverse" conditional probabilities — useful for many NLP classifiers.

Independence

A ⊥ B  ⇔  P(A,B) = P(A) · P(B)

Two events are independent when knowing one tells you nothing about the other. Check: P(card is 8, card is red) = 2/52 = (4/52)×(26/52) = 2/52 ✓

3. Guessing the Next Token

Language models are trained to predict the next word. This single objective forces the model to implicitly learn grammar, semantics, and world knowledge.

Techniques for predicting the next token

Unigram

Count how often each token appears overall. Ignores context entirely.

Bigram

Count what follows the immediately preceding token.

N-gram

Use last n-1 tokens as context. More specific but more sparse.

Key insight: Predicting the next token implicitly captures grammar — it must learn that nouns follow "the", verbs follow nouns, etc.
Important: LLMs don't "know" or "understand" — their apparent knowledge is a statistical illusion from pattern-matching massive corpora.

4. Formal Problem Definition

A language model must specify two things:

1. Sentence probability
P(w1, w2, ..., wn)

e.g., P("I bake with butter") > P("I bake with but her")

2. Next-word probability
P(wk+1 | w1, ..., wk)

e.g., P("margarine" | "use butter instead of") > P("puppets" | ...)

Chain Rule Decomposition

Using the chain rule we can decompose any sentence probability into a product of conditional probabilities:

P("the weather is snowy outside")
 = P(the)
 × P(weather | the)
 × P(is | the, weather)
 × P(snowy | the, weather, is)
 × P(outside | the, weather, is, snowy)
Chain Rule — Jurafsky & Martin Eq. 3.4
Problem: Conditioning on a long history is intractable — we'd need to have seen every exact context before. Solution: the Markov Assumption.

Captures Both:

Syntax / Grammar
Structure rules — "like I tad" < "I like tad"
Semantics
Real-world meaning — "elephant at circus" > "supernova at circus"

5. N-gram Language Models

The Markov Assumption

P(wk+1 | w1,...,wk) ≈ P(wk+1 | wk-N+2,...,wk)

Instead of the full history, approximate with the last N-1 words (the "context window").

N-gram Orders

ModelFormulaContext usedNotes
UnigramP(wk+1)NoneBag-of-words; ignores word order
BigramP(wk+1 | wk)1 prev wordFast, surprisingly effective
TrigramP(wk+1 | wk-1, wk)2 prev wordsBetter quality, more sparse
4-gramP(wk+1 | wk-2, wk-1, wk)3 prev wordsHigh quality, very sparse

MLE Estimation (Maximum Likelihood)

P(wn | wn-N+1:n-1) = C(wn-N+1:n-1 wn) / C(wn-N+1:n-1)
Jurafsky & Martin Eq. 3.12

Count how often the context is followed by the target word, divided by how often the context appears total.

Worked Example (Bigram)

Corpus: <s> I am Sam </s>   <s> Sam I am </s>   <s> I do not like green eggs </s>

P(Sam | <s>)C(<s> Sam) = 1C(<s>) = 30.33
P(am | I)C(I am) = 2C(I) = 30.67

Practical Issue 1: Start & End Tokens

<s> the dog barks </s>

Special tokens allow modelling the probability of starting and ending a sentence. For a bigram, the first word is: P(w | <s>). For a trigram, use two start tokens: <s><s>.

Practical Issue 2: Log Space

log P(w1,...,wn) = Σi log P(wi | context)

Multiplying many small probabilities causes numerical underflow. Working in log space converts products to sums, is numerically stable, and often easier to interpret.

Practical Issue 3: Zero Probability / Sparsity

If a bigram (wi-1, wi) never appears in training, then P(sentence) = 0 — even if the sentence is perfectly reasonable. This cripples language systems. Solution: Smoothing.

6. Smoothing

Goal

Assign non-zero probability to words or n-grams not observed in training. Texts are just a sample from the true language — unseen events are possible, not impossible.

Strategy: discount (lower) probability of seen events and redistribute the leftover to unseen events.

Add-K (Laplace) Smoothing

PAddK(w | context) = [C(context, w) + k] / [C(context) + k|V|]
  • k = 1: Add-One / Laplace smoothing — simplest, but too much probability moved from seen events.
  • k < 1: Fractional — often better in practice.
  • |V|: vocabulary size (number of unique words).

Check: P(A|C)+P(B|C)+P(C|C)+P(</s>|C) = 2/6+1/6+1/6+2/6 = 6/6 = 1 ✓

Interpolated Smoothing

Combine a higher-order model (more specific, more sparse) with lower-order models (less specific, less sparse):

P̂(wn | wn-2, wn-1) = λ1·P(wn) + λ2·P(wn|wn-1) + λ3·P(wn|wn-2,wn-1)

where λ1 + λ2 + λ3 = 1. The λ values are tuned on a development set.

λ3 (trigram) 0.60
λ2 (bigram) 0.30
λ1 (unigram) 0.10

7. Evaluation: Perplexity & Cross-Entropy

Intrinsic vs Extrinsic Evaluation

Extrinsic

Measure performance on a downstream task (speech recognition accuracy, translation BLEU score, etc.). Most meaningful but expensive.

Intrinsic

Measure inherent quality via perplexity on a held-out test set. Fast, widely used, but only a proxy.

Important: Never evaluate on training data! Use separate train / dev / test sets to avoid data contamination.

8. Information Theory Connection

Perplexity and cross-entropy have roots in Information Theory (Claude Shannon, 1948). Shannon studied optimal encoding of information.

Entropy — How many bits to encode a message?

H(X) = − Σx P(x) log2 P(x)

Uniform distribution (2 items, equal prob):

H = −(0.5×log₂0.5 + 0.5×log₂0.5) = 1 bit → 1 question needed.

Uniform distribution (8 items, equal prob):

H = −8×(1/8×log₂(1/8)) = 3 bits → 3 questions needed.

Non-uniform distribution → LESS entropy! If items are not equally likely (like natural language via Zipf's Law), we can encode more efficiently. Fewer bits needed on average.

Interactive: Entropy Visualiser

Adjust the probability of 4 symbols to see how entropy changes.

High vs Low Entropy in Language Models

High Entropy (uniform dist.)

All words equally likely → hard to predict → high perplexity.

Low Entropy (peaked dist.)

A few words very likely → easy to predict → low perplexity. Natural language follows Zipf's Law → typically low entropy.

Cross-Entropy as "Questions with the Wrong Model"

Imagine playing 20 questions. Your strategy (model distribution) assumes the answer is usually "elephant or giraffe". But the question-setter switched to mostly picking "airplane or helicopter".

The extra questions you need due to your wrong assumption = Cross-entropy between the true distribution and your model's distribution.

H(p, q) = − Σx p(x) log2 q(x)

9. Text Generation

A language model gives P(next word | context). We can use this to generate text one token at a time.

Strategy 1: Greedy Decoding

wnext = argmaxw P(w | context)

Always pick the most likely next word. Problem: leads to boring, repetitive loops.

"the dog" → "the dog that" → "the dog that the" → "the dog that the dog" → ...

Strategy 2: Sampling

Treat probabilities as a distribution and sample from it. The most likely word is still most probable, but others get a chance. Produces more diverse, natural-sounding text.

Top-k sampling

Only consider the top k most likely words before sampling. Avoids very rare words.

Top-p (nucleus) sampling

Keep the smallest set of words whose cumulative probability ≥ p. Dynamic k that adapts to the distribution.

Strategy 3: Beam Search

Maintain B candidate sequences ("beams") at each step. Expand each beam by one token, then keep only the B most probable overall sequences.

  • Beam width B=3: keep top 3 sequences at each step
  • Score = product of probabilities (or sum of log-probs)
  • Avoids greedy's local optima without exploring all paths
  • Uncommon first tokens like "Barack" may survive if "Barack Obama" has high joint probability

Avoiding Repetition

  • Block repeated n-grams — never generate a sequence already in the output
  • Contrastive search — penalise tokens that are too similar to the recent context

Short Answer 4 — Entropy

Calculate the entropy of the distribution: P(A) = 0.5, P(B) = 0.25, P(C) = 0.25. Compare to the uniform distribution over 3 symbols.

H = −[0.5 log₂(0.5) + 0.25 log₂(0.25) + 0.25 log₂(0.25)]
 = −[0.5×(−1) + 0.25×(−2) + 0.25×(−2)]
 = −[−0.5 − 0.5 − 0.5] = 1.5 bits

Uniform over 3 symbols: H = log₂(3) ≈ 1.585 bits

Non-uniform distribution has lower entropy — easier to predict than uniform.
Short Answer 5 — Chain Rule

Use the chain rule to write out P("I", "like", "pie") as a product of conditional probabilities.

P(I, like, pie) = P(I) × P(like | I) × P(pie | I, like)

In a bigram model (Markov assumption):
≈ P(I | <s>) × P(like | I) × P(pie | like)

This is the key step: chain rule (exact) → Markov approximation (tractable).
Short Answer 6 — Perplexity Bounds

A model has vocabulary size |V| = 20,000 and is a uniformly random model. What is its perplexity? What if it were perfect?

Random model: Each word gets P = 1/20000. Perplexity = 1/(1/20000) = 20,000

Perfect model: Every word assigned P = 1. Perplexity = 1/1 = 1

Perplexity range: [1, |V|]. Lower is better.
Essay / Long Answer

Explain why zero probabilities are a critical problem for n-gram language models and describe two different smoothing techniques that address this. Include equations.

Problem: If a bigram (wi-1, wi) never appears in training, C(wi-1, wi) = 0, so P(wi|wi-1) = 0. Any sentence containing this bigram gets probability 0 — regardless of how plausible it is. This makes tasks like speech recognition impossible when a rare word appears alongside a common one.

Technique 1 — Add-K Smoothing:
PAddK(w|context) = [C(context,w) + k] / [C(context) + k|V|]
Pretends every sequence was seen k extra times. Simple but k=1 takes too much probability from seen events.

Technique 2 — Interpolated Smoothing:
P̂(wn|wn-2,wn-1) = λ₁P(wn) + λ₂P(wn|wn-1) + λ₃P(wn|wn-2,wn-1)
Combines high-order (specific) and low-order (less sparse) models. λ values tuned on a dev set; sum to 1. Even if the trigram is zero, the bigram and unigram give non-zero contributions.
Tricky / Application Question

A language model assigns these log₂ probabilities to a 10-token sentence: [−2, −1.5, −3, −0.5, −2.5, −1, −4, −0.8, −2, −1.7]. Calculate (a) cross-entropy and (b) perplexity.

(a) Cross-entropy:
H = −(1/10) × Σlog₂P = −(1/10) × (−2 − 1.5 − 3 − 0.5 − 2.5 − 1 − 4 − 0.8 − 2 − 1.7)
 = −(1/10) × (−19) = 1.9 bits

(b) Perplexity:
PPL = 2H = 21.9 ≈ 3.73

Part (c) — Why apply smoothing? [3 marks]

Why is smoothing necessary? Give an example of a value needing smoothing in Model Y. What is the downside of too much smoothing?

Why needed: Without smoothing, any n-gram not seen in training gets probability 0. This causes any sentence containing that n-gram to also get probability 0 — making it impossible for the model to be used on new text. Real language has unseen n-grams simply because of data sparsity, not because they're impossible.

Example from Model Y needing smoothing:
P(<E>|b) = 0.0 in both models — a sentence can never end after the token 'b', which is unrealistic.
Also P(a|a) = 0.2 in Model Y is already handled, but in a real training corpus many bigrams would be 0.

Downside of too much smoothing: Probability mass is diluted away from well-attested, frequent n-grams to give undeserved probability to nonsensical n-grams. The model generates spurious, incoherent output.
Part (d) — Choosing n for n-gram models [3 marks]

What are the problems with choosing n too small and n too large? How would you select a good n?

Too small n (e.g., n=1 unigram):
No context used — model ignores word order and local structure entirely. Cannot capture that "a <E>" is more likely than "b <E>" in different contexts.

Too large n (e.g., n=8):
Most n-grams never appear in training → extreme sparsity. Huge computational burden. Model effectively memorises training data rather than generalising. Most probabilities are zero even after smoothing.

Selection: Empirically evaluate on a held-out development set. Try several values of n, compute perplexity on dev data, pick n with lowest dev perplexity. In practice, n=3 (trigrams) or n=5 are common choices.

Part (e) — Why compute in log space? [3 marks]

Language models compute log probabilities instead of raw probabilities. Explain why, and show numerically what problem occurs without log space for a 100-token sentence where each token has probability 0.1.

Problem — Numerical Underflow:
P(sentence) = ∏ᵢ P(wᵢ|context)
If each token has P=0.1 and sentence has 100 tokens:
P = 0.1100 = 10-100

Standard float64 (double precision) can represent as small as ~5×10-324, but 10-100 is in range... however for realistic models with P≈0.01 and 500 tokens: 0.01500 = 10-1000 — this underflows to 0.0 in floating point, causing division errors and loss of all information.

Solution — Log Space:
log P(sentence) = Σᵢ log P(wᵢ|context)
log(0.1100) = 100 × log(0.1) = 100 × (−3.322) = −332.2 bits
This is a perfectly normal float64 number — no underflow.
Products become sums, which is both numerically stable and computationally faster.

Practice Q3 — Conceptual & Application 20 marks

Part (a) — Chain rule to Markov assumption [3 marks]

The chain rule gives the exact probability P("the cat sat on the mat"). Explain why we use the Markov assumption instead, and what we lose by doing so.

Chain rule (exact):
P(the,cat,sat,on,the,mat) = P(the)×P(cat|the)×P(sat|the,cat)×P(on|the,cat,sat)×...
Each factor conditions on the full history. Problem: most histories never appear in training → probability = 0 for almost all long contexts.

Markov assumption (approximate):
P(wₙ|w₁,...,wₙ₋₁) ≈ P(wₙ|wₙ₋N₊₂,...,wₙ₋₁) — use only last N-1 words.

What we gain: Tractability — short contexts appear many times in training, giving reliable probability estimates.

What we lose: Long-range dependencies. "The man who bought the very expensive computer in 1999 claimed it was ___" — "it" refers back to "computer" 10 words ago, which a bigram model would miss entirely.
Part (b) — <s> and </s> tokens [3 marks]

Why are sentence boundary tokens (<s> and </s>) needed in n-gram language models? What problem arises without them?

<s> (start token):
Allows modelling what words begin sentences: P(first word | <s>). Without it, the bigram model has no context for the first word — we'd need a separate model for sentence-initial positions. For trigrams, we use <s><s> as padding.

</s> (end token):
Allows the model to "know" when to stop generating. Without </s>, text generation never terminates — P(</s>|context) is never learned, so the model never assigns probability to stopping.

Seen in exam 2023 Q2(b): In Model X, P(<E>|b)=0 — a sentence can never end after 'b', causing greedy decoding to loop forever generating "bbb...". This is why </s> tokens with non-zero probability are essential.
Part (c) — Beam search advantage over greedy [4 marks]

Construct a concrete example (with probabilities) where beam search (width=2) finds a better sequence than greedy decoding. Explain why greedy fails.

Setup:
From <s>: P(A|<s>)=0.55, P(B|<s>)=0.45
From A: P(A|A)=0.9, P(</s>|A)=0.1
From B: P(</s>|B)=0.95, P(A|B)=0.05

Greedy: Pick A (0.55) → pick A (0.9) → pick A → ... → loops forever, never terminates!

Beam search (width=2):
Step 1: Keep A (0.55), B (0.45)
Step 2: AA=0.55×0.9=0.495, A</s>=0.55×0.1=0.055, B</s>=0.45×0.95=0.428, BA=0.45×0.05=0.023
Keep top 2: AA (0.495), B</s> (0.428)

AA will keep multiplying by 0.9 and never terminate. B</s> already terminates.
Beam search output: B </s> (prob=0.428) — a complete, valid sequence.

Why greedy fails: It makes locally optimal single-step choices (A=0.55 beats B=0.45) but misses globally better paths that require a slightly worse first step to reach a much better completion.
Part (d) — Spelling correction with LM [4 marks]

Describe how a bigram language model can be used for spelling correction. Give an example and state two limitations.

Algorithm:
1. Detect misspelled word (not in vocabulary or flagged by edit-distance check)
2. Generate candidates: all words within edit distance 1 (single insert/delete/substitute/transpose)
3. Score each candidate using bigram LM: P(candidate | previous word) × P(next word | candidate)
4. Return candidate with highest bigram probability score

Example: "I baked bred yesterday" — "bred" not in vocabulary.
Candidates: {bread, breed, bled, brad, ...}
P(bread|baked) >> P(breed|baked) >> P(bled|baked)
Model correctly selects "bread".

Limitation 1 — Real-word errors: "I baked read yesterday" — "read" is in vocabulary but wrong. LM may not catch this since P(read|baked) could be non-zero.

Limitation 2 — Context window: Bigram only looks 1 word back. "The recipe said I should baked bred" — needs longer context to know "baked" is wrong (should be "bake").
Part (e) — Intrinsic vs extrinsic evaluation [3 marks]

Distinguish intrinsic and extrinsic evaluation of language models. Why is perplexity alone insufficient for evaluating an LM used in speech recognition?

Intrinsic: Evaluates the model on its own — perplexity on a held-out test set. Measures how well the LM predicts text without any downstream task. Fast to compute, language-agnostic.

Extrinsic: Evaluates the model in a real application (speech recognition WER, machine translation BLEU, etc.). Measures actual usefulness.

Why perplexity alone is insufficient for speech recognition:
A language model trained on one domain (e.g., news) may have low perplexity on news test data but high perplexity — and thus poor WER — when applied to speech recognition of medical conversations. Two models with similar perplexity on the same test set can have very different performance when integrated into a speech system (where acoustic model interactions, OOV rates, and vocabulary coverage also matter). Perplexity is a proxy metric; only extrinsic evaluation tells you which model is actually better for the target task.
Part (f) — Entropy and Zipf's Law [3 marks]

Explain the connection between Zipf's Law, entropy, and why natural language has lower perplexity than random text.

Zipf's Law: Word frequencies follow a power law — the most common word is ~2× more frequent than the 2nd, ~3× the 3rd, etc. A small set of words accounts for most text.

Entropy connection:
H(X) = −Σ P(x)log₂P(x)
Uniform distribution (all words equally likely) → maximum entropy. Zipf distribution (skewed, few very common words) → much lower entropy.

Effect on perplexity:
Lower entropy → more predictable → lower cross-entropy → lower perplexity.
If "the" appears 10% of the time, predicting it is easy — contributes only log₂(0.1) = −3.32 bits. Random text where all 100,000 words are equally likely contributes log₂(1/100000) = −16.6 bits per token.

English estimated entropy: ~1-2 bits/character. Random character from 26-letter alphabet: log₂(26) ≈ 4.7 bits/character. This is why language models achieve perplexity much lower than vocabulary size.
