🧪 Practice Questions — Data Types

Q1. A dataset records (10000, Manhattan, 23.3, 1) for each test: sample size, metric, run time, unique ID. How best to describe this?
Sample size=quantitative, runtime=quantitative, metric=categorical (nominal), unique ID=categorical (identifier, not meaningful numeric). So 2 quantitative + 2 categorical.
Q2. A supermarket dataset A has names of 10 products most often bought by EACH customer. Dataset B has counts of how often each customer bought each of the top 10 products across ALL customers. What are these using Munzner's classification?
A is a simple table (customer × products list). B has two categorical keys (customer, product) and a quantitative value (count) — this is a multidimensional table.
Q3. Which of these is an example of a "link" data type?
A link is a relationship between two items. "Two runners train together" is a relationship (link). Finishing time is an attribute. A start position is a position data type.

Question 1

A city council wishes to build a visualisation system to help urban planners analyse transport data. The data includes: (i) the names and locations of 500 bus stops across the city; (ii) the number of passengers boarding at each stop per hour, recorded every day for one year; (iii) which bus routes connect which stops; and (iv) average journey time between connected stops.

Using Munzner's framework, classify each of the four components of this dataset in terms of data types (items, links, attributes, positions, grids), dataset types (table, network/tree, field, geometry), and attribute types (categorical, ordinal, quantitative). Justify each classification. Then describe two distinct visualisation tasks — one search task and one query task — that a planner might perform using this dataset, identifying the action and target for each.

Data Classifications:

(i) Bus stop names = categorical attributes (nominal, no order). Locations = position data type (2D spatial coordinates). Dataset type: geometry (spatial data).

(ii) Passenger counts per hour = quantitative attribute, sequential direction. Recorded every hour = regular sampling → grid data type. Combined with stops and time, this forms a multidimensional table.

(iii) Bus routes connecting stops = links (relationships between items/stops). The whole structure = network dataset type.

(iv) Journey times = quantitative attribute (sequential, ratio scale) — attributes on the links of the network.

Visualisation Tasks:

Search task (Locate): "Does route 42 serve stop X?" — the target (whether route 42 serves the stop) is known; the location of this information in the dataset is unknown. Action = Search/Locate; Target = topology of the network.

Query task (Compare): "Which of the five busiest stops has the highest average journey time to the city centre?" Action = Query/Compare; Target = attribute correlation (passenger volume vs. journey time).

Mark scheme: 2 marks per correct classification with justification (8 marks), 3 marks per task with correct action/target identification (6 marks), 1 mark for clarity. Total 15.

[15 marks]

Question 2

Explain why it is useful to describe data and visualisation tasks in an abstract way, independent of any specific domain or application. Use two contrasting domains as examples to illustrate your answer, describing how the same abstract task type applies in both. Your answer should reference Munzner's action/target framework.

Why abstraction is useful:

Abstract task descriptions allow visualisation designers to reuse solutions across domains. When a task is described abstractly, a solution developed for one domain can be directly applied to another with the same task structure. It also allows systematic evaluation — comparing which encoding or interaction technique best supports a particular task type, rather than re-solving each domain from scratch.

Example 1 — Hill Running vs. Financial Data:

In hill running, a task might be: "Identify the distribution of age categories across clubs" (Query → Identify, target = attribute distribution). In financial data, a task might be: "Identify the distribution of trade sizes across different brokers" (Query → Identify, target = attribute distribution). Both tasks share the same abstract form: examine the frequency of a categorical attribute across groups. A histogram or bar chart with faceting solves both.

Example 2 — Healthcare vs. Social Media:

In healthcare: "Are there clusters of patients with similar symptom profiles?" (Analyse → Discover, target = features/clusters). In social media: "Are there communities of users with similar interests?" Same abstract task. Both are served by dimensional reduction + clustering visualisation. A spring model layout solves both after computing appropriate similarity metrics.

5 marks for clear explanation of why abstraction is valuable; 5 marks each for two well-chosen domain examples with correct abstract task labelling.

Bar Chart — Univariate Categorical

Best for comparing quantities across discrete categories. Bars should start at zero.

Python / Altair 
import altair as alt
import pandas as pd

data = pd.DataFrame({
    'club': ['Carnegie', 'Carnethy', 'Deeside', 'Lochaber', 'Keswick'],
    'members': [113, 191, 183, 173, 137]
})

chart = alt.Chart(data).mark_bar(color='#6c63ff').encode(
    x=alt.X('club:N', sort='-y', title='Club Name'),
    y=alt.Y('members:Q', title='Number of Members'),
    tooltip=['club:N', 'members:Q']
).properties(
    title='Hill Running Club Membership',
    width=500, height=300
).configure_axis(
    labelColor='#e8eaf6', titleColor='#9fa8da'
)

chart.show()
Bar chart zero-baseline rule: The y-axis MUST start at zero for bar charts. Truncated axes create misleading visual comparisons because bar length encodes quantity.

Scatterplot — Bivariate Quantitative

Best for showing correlation/relationship between two quantitative variables. Add a third variable via colour or size.

Heat Map — Trivariate (2 categorical + 1 quantitative)

Encodes a quantitative value through colour for every combination of two categorical variables. Order of axes matters for pattern detection.

Python / Altair 
import altair as alt
import pandas as pd
import numpy as np

# Generate example data: months × product categories → sales
months = ['Jan','Feb','Mar','Apr','May','Jun','Jul','Aug','Sep','Oct','Nov','Dec']
categories = ['Outdoor', 'Indoor', 'Equipment', 'Apparel']
rows = []
for m in months:
    for c in categories:
        rows.append({'month': m, 'category': c,
                     'sales': np.random.randint(50, 500)})
df = pd.DataFrame(rows)

heatmap = alt.Chart(df).mark_rect().encode(
    x=alt.X('month:O', sort=months, title='Month'),
    y=alt.Y('category:N', title='Category'),
    color=alt.Color('sales:Q',
                    scale=alt.Scale(scheme='blues'),
                    title='Sales'),
    tooltip=['month:O', 'category:N', 'sales:Q']
).properties(
    title='Monthly Sales by Category',
    width=500, height=200
)

heatmap.show()
⚠ Colour encoding warning: Use sequential colour scales (light→dark) for ordered data. Never use rainbow colour maps for ordered data — hue is not ordered, so the viewer cannot reliably interpret the ordering.

SPLOM — Scatterplot Matrix

Shows all pairwise scatterplots. For d dimensions: d(d-1)/2 unique plots (the upper or lower triangle, excluding the diagonal). The code below shows the full d×d matrix (both triangles) — common in practice; in the exam always use d(d-1)/2 for the count of unique pairs.

\[ \text{Number of plots in SPLOM} = \frac{d(d-1)}{2} \]

Example: for 9 dimensions → 9×8/2 = 36 unique plots (not 81 = 9²; not 72 = 9×8)

Python / Altair 
import altair as alt
from vega_datasets import data as vd

iris = vd.iris()

# SPLOM with Altair
splom = alt.Chart(iris).mark_point(size=30, opacity=0.6).encode(
    alt.X(alt.repeat('column'), type='quantitative'),
    alt.Y(alt.repeat('row'), type='quantitative'),
    color=alt.Color('species:N', scale=alt.Scale(scheme='dark2'))
).properties(
    width=150, height=150
).repeat(
    row=['petalLength', 'petalWidth', 'sepalLength', 'sepalWidth'],
    column=['sepalWidth', 'sepalLength', 'petalWidth', 'petalLength']
).interactive()

splom.show()

SPLOM Key Facts for Exam

• Screen space grows quadratically with dimensions

• Brushing & linking makes SPLOM far more powerful

• Good for correlation detection between pairs of dimensions

• Unlike parallel coordinates, pairs are not position-dependent

Parallel Coordinates — Multivariate

Each object = one line. Each vertical axis = one dimension. Shows correlations between adjacent axes.

Python / Altair 
import altair as alt
import pandas as pd
from vega_datasets import data as vd

cars = vd.cars()

# Parallel coordinates in Altair
dims = ['Horsepower', 'Miles_per_Gallon', 'Displacement', 'Weight_in_lbs']

# Normalise each column to [0,1] for display
cars_norm = cars[dims + ['Origin']].dropna().copy()
for d in dims:
    cars_norm[d] = (cars_norm[d] - cars_norm[d].min()) / \
                   (cars_norm[d].max() - cars_norm[d].min())
cars_norm['id'] = range(len(cars_norm))

# Melt to long format
melted = cars_norm.melt(id_vars=['id', 'Origin'],
                         value_vars=dims,
                         var_name='dimension',
                         value_name='value')
# Encode dimension order
melted['dim_order'] = melted['dimension'].map(
    {d: i for i, d in enumerate(dims)})

pc = alt.Chart(melted).mark_line(opacity=0.4).encode(
    x=alt.X('dimension:N', sort=dims, title=''),
    y=alt.Y('value:Q', title='Normalised Value'),
    color=alt.Color('Origin:N'),
    detail='id:N'
).properties(width=500, height=300, title='Parallel Coordinates: Car Data')

pc.show()

Reading Parallel Coordinates

• Lines crossing between two axes = inverse correlation

• Lines parallel between two axes = direct correlation

• Order of dimensions on x-axis is crucial — reorder to find relationships

• Hard to follow individual lines with large N → use interaction (mouseover)

🧪 Practice — Depicting Data

Q1. You have 100 tests of a program with run time and dataset size. A scatterplot is planned with dataset size on x, runtime on y. What's the best design choice for the identifier of each test?
With 100 unique identifiers, colour hue cannot distinguish 100 categories (max ~8-12 distinguishable hues). Colour value also fails. The identifier is an arbitrary label with no useful visual encoding — it should not be encoded. The scatterplot already encodes the meaningful variables (size vs. runtime).
Q2. For bivariate data where one variable is quantitative and one is categorical, which chart is most appropriate?
A bar chart is ideal when one axis is categorical (unordered) and the other is quantitative. A scatterplot needs two quantitative variables. A line chart implies an ordering/continuity between categories which doesn't exist for nominal data.

🎨 Week 3a: Jacques Bertin — Semiology of Graphics (1967)

Bertin was a French cartographer who formalised the visual language of maps and charts. His framework remains foundational in information visualisation.

🔷 Bertin's Visual Variables

Two categories: Location variables (position on the plane) and Retinal variables (perceptual properties of marks).

The 6 Retinal Variables

VariableDescriptionExample
ShapeForm of the markCircle, square, star
SizeArea or length of markSmall dot vs. large dot
OrientationAngle of mark's prominent axisVertical bar vs. 45° bar
TextureSpacing of repeated elementsFine grain vs. coarse grain
HueColour wavelengthRed, blue, green
ValueDarkness/lightness (greyscale)Light pink vs. dark red

Bertin's 4 Perceptual Properties

Associative/Dissociative ▼

Associative: All variations are perceived equally prominent. No value dominates. (e.g., hue, shape, orientation, texture)

Dissociative: One variable dominates and overshadows others (e.g., size, colour value — darker/larger draws the eye).

Selective ▼

You can focus on all marks sharing one value of the variable, ignoring others. Only shape is NOT selective — hard to group all hexagons by ignoring other shapes.

Ordered ▼

Variations perceived as ranked. Colour value (light→dark) is ordered; colour hue is NOT (green is not "more" than red).

Quantitative ▼

Extension of ordered: can estimate the ratio/magnitude of the difference. Position and size are quantitative (you can roughly tell that one bar is "twice as long"). Colour value is ordered but not reliably quantitative.

📐 Week 3b: Data Encoding — Munzner's Framework

Munzner calls Bertin's visual variables channels. Channels are ranked by effectiveness.

Expressiveness Principle

Choose a channel that matches the data attribute type:
• Nominal → hue, shape, orientation (unordered channels)
• Ordinal → colour value (ordered, non-quantitative)
• Quantitative → position, size (ordered + quantitative channels)

Effectiveness Principle

Encode the most important attributes with the highest-ranked channels. Use position first, then size/length, then colour.

Channel Rankings (Magnitude — Ordered Attributes)

1Position on common scale
2Position on unaligned scale
3Length (1D size)
4Tilt/angle
5Area (2D size)
6Depth (3D position)
7Colour value

⚡ Stevens' Psychophysical Power Law (1957)

The Law:

\[ S = k \cdot I^n \]

Where: S = perceived sensation, I = physical intensity of stimulus, n = exponent (power), k = constant


Key exponents (n values):

ChannelExponent (n)Interpretation
Electric shock3.5Overestimated (feels much worse than it is)
Saturation (colour)1.7Slight overestimation
Length / Position~1.0Accurate perception (linear)
Area (2D size)0.7Underestimated (circles look smaller than they are)
Depth (3D)0.67Underestimated
Brightness (luminance)0.5Strongly underestimated

Why n=1 is ideal for IV

When n=1, perceived sensation = physical intensity. The viewer accurately perceives the encoded value. Position and length achieve this — which is why bar charts (length) and scatterplots (position) are highly effective.

Why area (n=0.7) is problematic

In bubble charts, circles appear smaller than their true data value. A bubble representing 100 looks like it represents ~63 (100^0.7 ≈ 25, relatively). This causes systematic underestimation — viewers underread large values.

Stevens' Law — Altair Code Example

Python / Altair — Visualising Stevens' Power Law 
import altair as alt
import pandas as pd
import numpy as np

# Show how different channels distort perception
intensities = np.linspace(0.1, 5, 50)
channels = {
    'Length (n=1.0)': 1.0,
    'Area (n=0.7)': 0.7,
    'Brightness (n=0.5)': 0.5,
    'Saturation/Chroma (n=1.7)': 1.7
}

rows = []
for name, n in channels.items():
    for I in intensities:
        perceived = I ** n  # k=1 for simplicity
        rows.append({'channel': name, 'intensity': I, 'perceived': perceived})

df = pd.DataFrame(rows)

chart = alt.Chart(df).mark_line(strokeWidth=2.5).encode(
    x=alt.X('intensity:Q', title='Physical Intensity'),
    y=alt.Y('perceived:Q', title='Perceived Sensation'),
    color=alt.Color('channel:N',
                    legend=alt.Legend(title='Encoding Channel')),
    strokeDash=alt.condition(
        alt.datum.channel == 'Length (n=1.0)',
        alt.value([1,0]),  # solid for ideal
        alt.value([4,2])   # dashed for others
    )
).properties(
    title="Stevens' Psychophysical Power Law — Channel Comparison",
    width=500, height=350
)

# Add reference line for ideal (n=1)
rule = alt.Chart(pd.DataFrame({'y': [0]})).mark_rule(
    color='white', strokeDash=[8,4], opacity=0.3
)

chart.show()

🧪 Practice — Bertin & Encoding

Q1. Which of Bertin's retinal variables is NOT selective (i.e., cannot be easily isolated from other variables in a display)?
Bertin states that shape is the only retinal variable that is NOT selective. You cannot easily focus on "all hexagons" while ignoring circles — shapes require serial search. Colour hue and value are selective (you can quickly group all red objects).
Q2. According to Stevens' Power Law, which encoding channel leads to the most accurate quantitative perception?
When n=1, perceived sensation equals physical intensity — perfectly accurate. Position on a common scale achieves n≈1. Area (n=0.7) is systematically underestimated. Brightness (n=0.5) is strongly underestimated — large differences in brightness feel much smaller than they are.

Question 4 — Stevens' Power Law (from example paper)

Outline the basic concept of Stevens' psychophysical power law, and why it is important in the design of information visualisation systems. In your answer, outline three different common styles of chart or graphical encoding, and critique each of them in terms of this power law.

Stevens' Psychophysical Power Law:

Stevens (1957) proposed that the perceived magnitude of a sensation is related to the actual physical intensity by a power function: S = k·Iⁿ, where S is perceived sensation, I is physical intensity, k is a constant, and n is an exponent that varies by modality/channel.

When n=1, perception is perfectly accurate (linear). When n<1, large values are underestimated (compression). When n>1, large values are overestimated (expansion).

Importance for IV design: If we encode data values using a channel with n≠1, viewers will systematically misread the data. A good IV designer should choose channels where n≈1, or compensate for the perceptual distortion (e.g., by using area² instead of area to represent a value, correcting for n=0.7).

Chart 1 — Bar chart (length, n≈1.0): Bar length is perceived very accurately. A bar twice as tall is seen as representing twice the value. This makes bar charts one of the most reliable quantitative encodings. No compensation needed.

Chart 2 — Scatterplot (position, n≈1.0): Position on a common axis (like x or y in a scatterplot) also achieves n≈1. Viewers can accurately rank and estimate differences between points. The most highly-ranked channel in Munzner's hierarchy precisely because of this accuracy.

Chart 3 — Bubble chart (area, n≈0.7): Area in bubble charts is strongly underestimated. A circle with 4× the area looks only about 2.6× larger (4^0.7 ≈ 2.6). This means viewers consistently underestimate large values and overestimate the similarity between differently-sized bubbles. To compensate, designers must scale circle radius² (not radius) to the data value, since area = π·r². Despite this, bubble charts remain problematic and should be used cautiously.

4 marks for explaining law and its IV significance; 3-4 marks per chart critique (9-11 marks). Partial marks awarded.

Question 5

A data analyst is designing a visualisation showing running club data with five attributes: club name (categorical), number of members (quantitative), percentage male (quantitative), membership fee (quantitative), and founding year (quantitative). Using Munzner's expressiveness and effectiveness principles, and drawing on Bertin's visual variables, design an encoding for a scatterplot-based visualisation that shows all five attributes simultaneously. Justify every encoding choice, including which channels are used for which attributes and why. Identify any weaknesses in your design.

Proposed encoding:

1. Membership fee (quantitative) → x-axis position (position on common scale, n≈1): Highest-ranked channel; most important attribute for the analyst to read accurately. Expressiveness: position is quantitative ✓.

2. Number of members (quantitative) → y-axis position: Second most important quantitative attribute gets second spatial axis. Scatterplot x/y.

3. % male (quantitative, diverging around 50%) → colour value: Ordered channel. Use diverging colour scale (e.g., blue=more female, red=more male, white=50/50). Expressiveness: colour value is ordered ✓. Weakness: not highly quantitative (n<1).

4. Founding year (quantitative, sequential) → size/area of mark: Ordered channel; larger = newer. Weakness: area has n=0.7, so underestimated. However, it is a less critical attribute for this task.

5. Club name (categorical) → colour hue AND tooltip on hover: Hue is unordered (associative) — matches nominal attribute. However, with many clubs (100+), hue becomes unreliable beyond ~8-12 colours. Tooltip is the reliable fallback for exact identification.

Weaknesses: With 100 clubs, colour hue for name fails (too many categories). Size (area) is perceptually imprecise for founding year. Channel interference: combining colour value AND colour hue may confuse viewers — these channels interact (dissociative variables compete).

👁️ Week 3c: Visual Perception

Based on Ware (2021). Three levels of visual processing — crucial for understanding WHY certain vis designs work and others fail.

🧠 Three-Level Perceptual Model

Level 1: Pre-attentive (Parallel, ~200ms)

Rapid extraction of low-level features. Bottom-up, data-driven. Examples: colour, size, orientation, motion. Pop-out effect.

Design implication: Use pre-attentive features to highlight important data points. A single red dot among blue dots is found instantly regardless of how many blue dots exist.

Level 2: Pattern Recognition (Sequential, attention needed)

Contour detection, region grouping. Uses BOTH bottom-up and top-down processing. Gestalt laws operate here.

Design implication: Use Gestalt principles to help viewers perceive meaningful groups without conscious effort.

Level 3: Object Identification (Sequential, slow)

Top-down. Uses memory and context to identify objects. Interference can occur between levels (Stroop effect).

Design implication: Reduce cognitive load by making object identification immediate through good encoding and clear labelling.

🔷 Gestalt Laws (Level 2)

Rules describing how we perceive groups and patterns in visual displays.

LawPrincipleIV Application
ProximityClose items are groupedPlace related chart elements close together
SimilaritySimilar items are groupedUse same colour for same category across views
ConnectednessConnected items are groupedDraw edges/lines to show relationships in networks
ContinuitySmooth paths are perceived as wholeConsider line chart continuity with overlapping data
SymmetrySymmetric items are groupedSymmetric layouts aid comparison of similar structures
ClosureGaps in contours are mentally closedUse enclosing regions to group related data
Figure & GroundSmall areas seen as figureUse background/foreground contrast for hierarchy
Common FateMoving-together items are groupedDon't animate unrelated objects simultaneously

Colour Rules for IV

✓ Use hue for categorical (nominal) data — max ~8 distinguishable hues

✓ Use colour value (lightness) for ordered data

✓ Use saturation for emphasis; neutral for background

✗ Don't use rainbow colour maps for ordered data — hue is not ordered

✗ Don't use blue for thin lines (poor acuity at edges)

✗ Don't use adjacent colours varying in blue (chromatic aberration)

✓ Use neutral tone for zero in diverging scales

Reference: ColorBrewer2.org for perceptually safe colour maps

Question 6

A designer is creating a visualisation of a city's public transport network, showing 50 bus routes on a map. They plan to colour each route with a distinct hue, use thick lines to show high-frequency routes, and animate all routes simultaneously to show passenger flow. Critically evaluate this design using the three-level perceptual model (Ware), Gestalt principles, and colour theory. Propose specific improvements with justifications.

Critique using three-level model:

Level 1 (Pre-attentive): 50 distinct hues far exceeds the ~8 distinguishable colours in cross-cultural studies (Berlin & Kay; Ware, 2021). Beyond 8-12 hues, viewers cannot reliably identify or distinguish routes by colour alone — the colour encoding fails at Level 1. The thick lines for frequency is a better use of Level 1 (size is pre-attentive) but may be dominated by the colour clutter. Animation of all routes simultaneously creates "common fate" confusion — viewers cannot determine which animated motion belongs to which route, overwhelming Level 1 processing.

Level 2 (Pattern recognition / Gestalt): Animating unrelated routes simultaneously violates the "common fate" Gestalt principle — motion groups objects. If all 50 routes animate at once, no useful grouping is perceived; patterns become noise. Proximity grouping may help identify clusters of routes, but only if routes are spatially separated, which they may not be in a dense city centre.

Level 3 (Object identification): Identifying a specific route from memory (e.g., "which one is route 42?") becomes a slow, serial, top-down search across 50 coloured lines with no reliable colour anchor. Cognitive load is very high.

Improvements:

1. Reduce hues to 8 max, encoding route type (bus/tram/metro) rather than individual route ID. Use tooltips/labels for exact identification on hover.

2. Use colour value (lightness) instead of hue for frequency — ordered, perceptually appropriate for ordered data.

3. Animate routes individually or on demand (user selects route → animation plays for that route only). This exploits "common fate" beneficially: the animated route pops out from the static background.

4. Apply overview-first principle (Shneiderman): show all routes as light grey by default; let user filter/select specific routes, which then become highlighted.
