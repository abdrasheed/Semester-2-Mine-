Query Taxonomy & Web Characteristics

Broder (2002) Query Taxonomy

The canonical classification of web queries into three types based on user intent, not content.

🧭 Navigational (~20%)

Reach a specific website. User already has a target in mind. E.g. "facebook login", "university of glasgow". The correct answer is a single page. Measured by MRR.

📖 Informational (~48%)

Acquire information available on the web. E.g. "how do vaccines work", "history of glasgow". Reading is the primary action. Multiple relevant pages exist.

🛒 Transactional (~30%)

Reach a site for further interaction. E.g. "buy iPhone", "download python". A goal exists beyond just reading — purchase, download, sign up, etc.

Three Actor Perspectives

Web search involves three stakeholders with different — and sometimes conflicting — objectives:

User

Wants relevant results for their information need. Measures success by satisfaction — finding what they were looking for quickly. Cares about precision, recall, and speed.

Search Engine

Wants to provide quality results to retain users, while also generating profit through advertising. Balances organic (relevance-based) results with paid placements.

Advertiser

Wants conversions — clicks that lead to purchases, sign-ups, or other actions. Bids for ad placements on high-intent queries (transactional queries most valuable).

⚠️ Tension Between Actors

Advertisers want maximum visibility for their pages regardless of true relevance; users want purely relevant results; search engines must balance both to stay profitable and useful. This creates incentives for spam, SEO manipulation, and link farm creation.

Web Dynamics

Four Types of Web Dynamics

The web is not static — it changes continuously along four dimensions that each pose different challenges for search engines.

📐 Size Dynamics

The total number of indexed pages grows continuously. Google estimated 30 trillion+ pages in 2013. New sites created, old ones deleted. A search engine's index is always a snapshot of the web, not the full current web.

Implication

Crawlers must continuously discover new pages. Index growth strains storage and processing infrastructure.

📝 Content Dynamics

Pages change their content over time. Key finding from Adar et al. (2009):

  • 34% of pages never change (static content)
  • Average page changes every ~123 hours
  • Popular/news pages change much more frequently

Implication

Crawl scheduling must prioritise frequently-changing pages. Stale index = wrong results for dynamic content.

🔍 Query Dynamics

User query patterns change over time. What people search for shifts with current events, seasons, and culture:

  • Query popularity fluctuates (trending topics)
  • 33% of queries are repeats of previous queries
  • Average query length grew from 2.4 → 3.08 words
  • Seasonal patterns (e.g., "flu symptoms" spikes in winter)

📍 Location/Usage Dynamics

The same query from different locations or users means different things. Local intent is a key challenge:

  • "pizza" in Glasgow vs. New York → different results needed
  • Device type (mobile vs. desktop) affects results
  • Time of day changes query intent
  • 40% of queries are re-finding queries (same user, same page)

Temporal Dynamics in Detail

Temporal dynamics cut across all four types. A query's intent can shift over time (e.g., "super bowl" means different things before vs. during vs. after the event). Result freshness (index recency) is a ranking signal — newer pages may be more relevant for time-sensitive queries even if they have fewer inlinks.

⚠️ Freshness vs. Authority Trade-off

A new Wikipedia article about a breaking event may be more relevant than an old authoritative page. Search engines blend freshness signals (publication date, crawl date, content change rate) with authority signals (PageRank, inlinks).

Ranking Framework for Web Search

Probabilistic Ranking Framework: p(r | d, x)
\[ \text{score}(d, q) = P(\text{relevant} \mid d, x) \]

Where x = context = (query q, user features, session, device, location, time). This generalises classic IR: instead of estimating relevance purely from document-query term matching, we estimate the probability of relevance given all available context.

Feature Taxonomy for Web Ranking

Web ranking features are classified into three groups based on what they depend on:

Query-Independent (QI) Features

Computed from document alone — no query needed. Pre-computable and stored in index. Examples: PageRank, spam score, page quality, load time, social signals. Same value for all queries.

Query-Dependent (QD) Features

Computed from both document AND query. Examples: BM25, TF-IDF, query term coverage, anchor text match, semantic similarity. Different value per (query, document) pair.

Query Features

Computed from query alone — no document needed. Examples: query length, query type (nav/info/trans), query frequency in logs, query clarity. Same for all documents returned for that query.

Hyperlink Intuitions

Hyperlinks are more than navigation — they encode two types of information:

Quality Signal

A link from page A to page B is an endorsement — A's author chose to point to B. Many inlinks = many endorsements = likely high-quality page. This is the basis of PageRank ("wisdom of crowd" signal).

Content Enhancement (Anchor Text)

The text of a hyperlink describes the linked page from an outsider's perspective. Anchor text "click here for cheap flights" tells us about the destination page — often better than the page itself.

PageRank

PageRank Formula (Random Surfer Model)
\[ PR(d) = \frac{1-\alpha}{N} + \alpha \sum_{d' \in \text{inlinks}(d)} \frac{PR(d')}{|\text{outlinks}(d')|} \]

α = damping factor (typically 0.85), N = total pages. Intuition: a random surfer follows links with probability α, teleports to a random page with probability 1−α. PageRank = long-run fraction of time spent at each page.

Matrix Formulation

PageRank can be formulated as a matrix power iteration problem:

Step 1: Adjacency Matrix A

A[i][j] = 1 if page i links to page j, else 0.

Step 2: Transition Matrix T

Normalise rows of A by out-degree: T[i][j] = A[i][j] / outdegree(i). Row i sums to 1. T describes probabilities of moving from page i to any linked page.

Step 3: PageRank Vector M = TT
\[ \mathbf{r} = M \cdot \mathbf{r} \]

PageRank vector r is the left eigenvector of M with eigenvalue 1. Computed by power iteration: r ← M·r, normalise, repeat until convergence.

🔶 Matrix Example: 3-page web

Pages: 1, 2, 3. Links: 1→2, 1→3, 2→3, 3→1.

Adjacency A:
  [0, 1, 1]
  [0, 0, 1]
  [1, 0, 0]

Transition T (normalise each row):
  Row 1: outdegree=2 → [0, 0.5, 0.5]
  Row 2: outdegree=1 → [0, 0, 1]
  Row 3: outdegree=1 → [1, 0, 0]

M = TT:
  [0, 0, 1]
  [0.5, 0, 0]
  [0.5, 1, 0]

PageRank Convergence

Starting from uniform distribution, PageRank converges iteratively. Example convergence values for a 5-page graph (k = iteration number):

Iteration kPR(page 1)PR(page 2)PR(page 3)PR(page 4)PR(page 5)
k=0 (uniform)0.2000.2000.2000.2000.200
k=10.3870.2900.1290.1290.065
k=40.3870.1940.1290.1940.097
k=∞ (converged)0.3870.1940.1290.1940.097

Convergence is typically fast (20–100 iterations for most graphs). The stationary distribution exists when the graph is strongly connected and aperiodic.

PageRank Problems

⚠️ Disconnected Graphs

If the web graph has disconnected components, the random surfer can get "stuck" in one component and never visit others. The stationary distribution depends on the starting component.

⚠️ Dangling Nodes

Pages with no outlinks (PDF files, dead-end pages). The random surfer gets stuck here with no link to follow. Transition matrix row for dangling nodes sums to 0 — violates stochastic property.

⚠️ Rank Sinks

A group of pages that link only among themselves but receive links from outside. They "absorb" PageRank from the rest of the web without redistributing it back — ranks accumulate without bound (relative to others).

Teleportation: The Google Matrix

All three problems above are solved by adding teleportation — a small probability of jumping to a completely random page:

Google Matrix G
\[ G = (1 - \lambda) M + \lambda S \]

Where:
• M = PageRank transition matrix (with dangling node handling)
• S = teleportation matrix (uniform: S[i][j] = 1/N for all i,j)
• λ = teleportation probability (Google uses λ = 0.15, so α = 0.85)

Why This Fixes All Problems

  • Disconnected graphs: Teleportation connects all components — surfer can jump to any page
  • Dangling nodes: Replace dangling node row with uniform 1/N — surfer teleports from dead ends
  • Rank sinks: Teleportation drains PageRank from sinks — some always "leaks" out
🔶 Teleportation Worked Example (λ=0.15, N=5)

5-page graph. After convergence with teleportation, PageRank vector:

[page1, page2, page3, page4, page5] = [0.200, 0.200, 0.285, 0.285, 0.030]

Note: pages 3 and 4 have highest PR (linked-to by high-degree pages), page 5 has very low PR (few/no inlinks). The teleportation floor prevents any page from having PR=0.

Python: PageRank (Power Iteration)

import numpy as np

def pagerank(adjacency, alpha=0.85, max_iter=100, tol=1e-6):
    N = len(adjacency)
    pr = np.ones(N) / N  # initialise uniform

    # Build transition matrix (handle dangling nodes)
    out_degree = adjacency.sum(axis=1)
    dangling = (out_degree == 0)
    out_degree[dangling] = 1  # avoid div-by-zero
    transition = (adjacency.T / out_degree).T
    transition[dangling] = 1.0 / N  # dangling → uniform teleport

    S = np.ones((N, N)) / N  # teleportation matrix
    G = (1 - alpha) * S + alpha * transition  # Google Matrix

    for _ in range(max_iter):
        new_pr = G.T @ pr
        if np.linalg.norm(new_pr - pr) < tol:
            break
        pr = new_pr
    return pr

# Example: A=0, B=1, C=2. A→B, A→C, B→A, C→A
adj = np.array([[0,1,1],[1,0,0],[1,0,0]], dtype=float)
scores = pagerank(adj)
print(f"PR(A)={scores[0]:.3f}, PR(B)={scores[1]:.3f}, PR(C)={scores[2]:.3f}")

Link Analysis & Web Signals

Wisdom of the Crowd — In-degree as Relevance

The simplest link feature is in-degree — the number of pages that link to a document. The intuition:

  • Each hyperlink is an editorial choice by a human author
  • More inlinks = more authors chose to point to this page
  • "Wisdom of the crowd" — many independent endorsements signal quality
  • In-degree is query-independent (same for all queries)

⚠️ Problem: Link Spam

Link spammers create many low-quality pages linking to a target to inflate its in-degree. PageRank is more robust than raw in-degree because it weights links by the PageRank of the linking page — links from authoritative pages count more.

Najork et al. (2007): How Much Does PageRank Matter?

An empirical study that measured the contribution of different feature types to ranking quality (NDCG):

NDCG 0.221
BM25F score alone (content matching)
NDCG 0.092
PageRank alone (link features)

⚠️ Key Finding: Link Features Are Surprisingly Weak

PageRank contributes significantly less to retrieval quality than content matching (BM25F). This challenges the popular assumption that PageRank is the dominant ranking signal. The study suggests link features are useful primarily as a quality filter to remove spam and low-quality pages, not as the primary relevance signal.

Interpretation

Content still dominates relevance. PageRank is best understood as a prior on document quality — useful for filtering, less useful for query-specific ranking. Modern systems combine both with hundreds of features via Learning-to-Rank.

Anchor Text: Power and Problems

Why Anchor Text Is Valuable

  • Describes the linked page from an outsider's perspective
  • Compensates for missing content (a PDF might have no descriptive text)
  • Aggregates descriptions from thousands of authors linking to a page
  • Anchor text for a page forms a "virtual document" of descriptors

⚠️ Anchor Text Manipulation: "Evil Empire"

Classic example: Google bombing — coordinated link campaigns where many pages link to a target with specific anchor text. The "miserable failure" Google bomb linked George W. Bush's biography. Another: "evil empire" was bomb-linked to Microsoft. This led Google to discount anchor text from clearly orchestrated campaigns.

HITS Algorithm

HITS — Hyperlink-Induced Topic Search (Kleinberg, 1999)

Unlike PageRank (query-independent, offline), HITS is query-dependent — it builds a subgraph around the query results and computes two scores per page: hub and authority.

HITS Update Rules
\[ \text{auth}(d) = \sum_{d' \rightarrow d} \text{hub}(d') \qquad \text{hub}(d) = \sum_{d \rightarrow d''} \text{auth}(d'') \]

After each iteration: normalise both vectors (divide by L2 norm). Repeat until convergence.

Formal HITS Algorithm (3-Step Process)

Step 1: Build Query Subgraph

Issue query → retrieve top-k documents (root set). Expand to "base set" by adding all pages that link to or are linked from any root set page. Typically base set = hundreds of pages.

Step 2: Iterative Scoring

Initialise: hub(d) = auth(d) = 1 for all pages in base set.
Repeat until convergence:
  1. auth update: auth(d) = Σ hub(d') for all d' → d
  2. Normalise auth: auth(d) = auth(d) / ||auth||₂
  3. hub update: hub(d) = Σ auth(d'') for all d → d''
  4. Normalise hub: hub(d) = hub(d) / ||hub||₂

Step 3: Rank by Authority

Return documents ranked by authority score. Hub scores are secondary but useful for finding "directories" or "topic overview" pages.

HITS Comparative 6-Node Example

Consider a 6-node graph: A→C, A→D, B→C, B→D, B→E, C→F, D→F.

✅ Analysis

After convergence:
High Authority pages: F (receives links from C and D), C and D (receive from A and B)
High Hub pages: A and B (link to multiple authorities C, D, E)

A and B never have high authority (nothing links to them)
F never has high hub score (links to nothing)
C and D have moderate hub and authority (both linked-to and link-out)

⚠️ HITS "Topic Drift" Problem

The base set expansion can introduce pages on unrelated topics. If many pages about topic X link to pages about topic Y, Y may get high authority for topic X queries. HITS authority can drift away from the original query topic.

Learning-to-Rank: Training Data

Learning-to-Rank (LTR)

Supervised ML approach to ranking. Given query q and a set of documents, learn a ranking function using labeled training data. Requires relevance-labeled (query, document) pairs.

Training Data Construction Methods

Pooling

Retrieve top-k results from multiple IR systems for each query. Union these into a "pool". Human assessors label pooled documents for relevance. Documents not in pool assumed non-relevant (but may be judged later via "move to front").

Editorial Judgements

Trained human assessors (editors) evaluate each (query, document) pair. More expensive but higher quality than crowdsourcing. TREC and LETOR datasets use editorial judgements. Time-consuming: TREC assessors spend ~1 min per document.

Multi-Graded Relevance

Instead of binary relevant/not-relevant, use graded scale (e.g., 0–4 or TREC 6-grade). Enables use of NDCG as evaluation metric. Graded judgements capture that "highly relevant" is better than "somewhat relevant".

TREC Relevance Grade Scale (6 grades)

GradeLabelDescription
4PerfectDocument is exactly what the user wanted — definitively answers the query
3ExcellentHighly relevant, very good answer to the query
2GoodRelevant and useful, though may miss some aspects
1FairSome relevance but significant gaps or tangential
0BadNot relevant; does not address the query
−1Junk/SpamSpam, offensive, or malicious content; harmful to show

NDCG is computed using these grades — a perfect result at rank 1 contributes much more than a fair result. The gain G(r) = (2^grade − 1) in standard NDCG.

LTR: Pointwise, Pairwise, Listwise

Pointwise

Predict relevance grade of individual (q,d) pairs. Loss = MSE. Simple but ignores relative ordering between documents for same query.

Pairwise

Learn that document d₁ should rank above d₂. Loss = hinge/cross-entropy on pairs. RankNet, LambdaMART. More natural for ranking tasks.

Listwise

Optimise the entire ranked list directly. Loss approximates NDCG. ListNet, AdaRank. Theoretically best but computationally expensive.

Summary

Query Taxonomy (Broder 2002)

Navigational (20%), Informational (48%), Transactional (30%). 33% of queries are repeats; 40% are re-finding. Query length grew from 2.4→3.08 words. Three actor perspectives: User (relevance), Search Engine (quality+profit), Advertiser (conversions).

Web Dynamics

Four types: Size (30T+ pages), Content (34% never change; avg 123h to change — Adar 2009), Query (seasonal/temporal shifts), Location/Usage (local intent, re-finding). These demand continuous crawling, index refreshing, and localisation.

Ranking Framework

p(r|d,x) — probability of relevance given document and context. Features: QI (PageRank, spam, quality, CTR, dwell, load time — precomputed), QD (BM25, anchor text, semantic similarity — computed per query), Query (length, type — per query).

PageRank

Random surfer model. Matrix formulation: G = (1−λ)M + λS (Google Matrix, λ=0.15). Problems: disconnected graphs, dangling nodes, rank sinks — all solved by teleportation. Najork 2007: BM25F NDCG=0.221 vs PageRank NDCG=0.092 — link features are surprisingly weak.

HITS

Hub and Authority scores. 3-step: build query subgraph, iterate auth/hub updates with normalisation, rank by authority. Query-dependent, computed online. Vulnerable to topic drift and hub manipulation. Less practical than PageRank.

LTR Training Data

Pooling + editorial judgements + TREC 6-grade scale (Perfect/Excellent/Good/Fair/Bad/Junk). Pointwise/pairwise/listwise loss formulations. Hundreds of QI, QD, and query features fed into models like LambdaMART.

Calculation Problems
PageRank Calculation: 4-page web. A→B, A→C, B→D, C→D, D→A. α=0.85, N=4. Initial PR=0.25 each. Compute one iteration for A and D.
Base = (1−0.85)/4 = 0.0375.
PR(A): Only D links to A. D has 1 outlink. PR(A) = 0.0375 + 0.85×(0.25/1) = 0.0375+0.2125 = 0.25
PR(D): B links to D (1 outlink), C links to D (1 outlink). PR(D) = 0.0375+0.85×(0.25/1+0.25/1) = 0.0375+0.425 = 0.4625
D gains PageRank because both B and C point to it.
HITS Iteration: Graph: A→B, A→C, B→C, D→A, D→B. All initial hub=1, auth=1. Compute auth(B) and auth(C) after one iteration, then normalise.
Auth update (auth = sum of hub scores of pages that link to it):
auth(A): D links to A → auth(A) = hub(D) = 1
auth(B): A and D link to B → auth(B) = hub(A) + hub(D) = 1 + 1 = 2
auth(C): A and B link to C → auth(C) = hub(A) + hub(B) = 1 + 1 = 2
auth(D): Nobody links to D → auth(D) = 0

Normalise: ||auth||₂ = √(1² + 2² + 2² + 0²) = √9 = 3
auth(A) = 1/3 ≈ 0.333; auth(B) = 2/3 ≈ 0.667; auth(C) = 2/3 ≈ 0.667; auth(D) = 0
B and C are the top authorities as they receive links from multiple pages.
Google Matrix: A 3-page web has PageRank matrix M (after transition matrix construction). With λ=0.15 and N=3, write the full Google Matrix G formula and explain what each component contributes.
G = (1 − 0.15) × M + 0.15 × S = 0.85M + 0.15S
Where S[i][j] = 1/3 for all i,j (uniform teleportation for N=3).

So G[i][j] = 0.85 × M[i][j] + 0.15 × (1/3) = 0.85 × M[i][j] + 0.05

Component M (weight 0.85): Follows actual web links — surfer follows a link from current page with probability 0.85. This captures link structure and propagates authority.

Component S (weight 0.15): Uniform teleportation — with probability 0.15, surfer jumps to any page at random. This prevents rank sinks, handles dangling nodes, and ensures all pages have minimum PageRank floor of 0.15/N = 0.05.

(2007) regarding the importance of PageRank for web ranking. [3]
(a) PR(d) = (1−α)/N + α × Σ_{d'→d} PR(d')/outdegree(d'). Damping factor α (typically 0.85): probability that random surfer follows a link rather than teleporting. With probability (1−α)=0.15, surfer jumps to a random page. Models realistic browsing behaviour. [3]

(b) Problem 1 — Disconnected graphs: if web graph has multiple components, surfer gets stuck. Solution: teleportation (λS) connects all components — surfer can jump to any page. Problem 2 — Dangling nodes: pages with no outlinks (PDFs) have row summing to 0 in transition matrix. Solution: treat dangling nodes as pointing to all pages with uniform probability (equivalent to teleportation). Problem 3 — Rank sinks: groups of pages that link only internally absorb PageRank without redistribution. Solution: teleportation drains rank from sinks — surfer always has probability λ of escaping. [6]

(c) Najork 2007: using BM25F alone achieves NDCG ≈ 0.221; using PageRank alone achieves NDCG ≈ 0.092. Interpretation: link features are significantly weaker than content matching for retrieval quality. PageRank is best used as a quality/spam filter rather than the primary relevance signal. This means content-based features dominate web ranking even though PageRank is often cited as revolutionary. [3]
H/M[8 marks]
Q3. (a) Distinguish between query-independent (QI) and query-dependent (QD) features in web ranking. Give TWO examples of each. [4] (b) Explain the value and problems of using anchor text as a ranking feature. Give a specific example of anchor text manipulation. [4]
(a) QI features: computed from document alone, no query needed, pre-computable. Examples: PageRank (link authority), spam score, page load time, social signals, dwell time. QD features: computed from query AND document at retrieval time. Examples: BM25/TF-IDF score, anchor text match to query, query term coverage, semantic embedding similarity. [4]

(b) Value: anchor text describes the linked page from an outsider's perspective — often better than the page's own content. Multiple anchor texts from thousands of linking pages form a "virtual document" of descriptions. Useful for pages with little indexable text (PDFs, images). Problem: can be deliberately manipulated via coordinated link campaigns. Example: "Google bombing" — many pages linking to a target with specific anchor text artificially inflates its ranking for that text. Classic case: pages linking "miserable failure" to George W. Bush's biography; "evil empire" bomb-linked to Microsoft. Led Google to discount orchestrated anchor text campaigns. [4]
H/M[8 marks]
Q4. (a) Describe the HITS algorithm: what are hub and authority scores, and outline the 3-step process. [4] (b) Compare HITS and PageRank on four dimensions: query-dependence, number of scores, spam resistance, and practical deployment. [4]
(a) Hub score: how well a page points to good authorities (high hub = links to many authoritative pages). Authority score: how many good hubs link to this page (high authority = linked by many good hubs). 3-step process: (1) Build query subgraph — retrieve top-k for query, expand by following links in and out (root set → base set). (2) Iterate: auth(d) = Σ hub(d') for all d'→d; hub(d) = Σ auth(d'') for all d→d''; normalise both vectors; repeat until convergence. (3) Rank results by authority score. [4]

(b) Query-dependence: HITS is query-dependent (different subgraph per query), PageRank is query-independent (single global score). Number of scores: HITS produces 2 scores per page (hub + authority), PageRank produces 1. Spam resistance: PageRank more resistant — links from high-PR pages count more; HITS vulnerable to artificial hub pages created by spammers. Practical deployment: PageRank widely used in production (offline-precomputed, cheap at query time); HITS rarely used in production (expensive online computation, topic drift problem). [4]
Flashcards
Broder Taxonomy
Nav (20%), Informational (48%), Trans (30%). Broder 2002. Based on user INTENT, not content.
PageRank Formula
PR(d) = (1−α)/N + α × Σ PR(d')/out(d'). α=0.85. Random surfer model. Query-independent.
Google Matrix
G = (1−λ)M + λS, λ=0.15. Fixes rank sinks, dangling nodes, disconnected graphs via teleportation.
HITS
Hub = links to good authorities. Auth = linked by good hubs. Query-dependent, 3-step: subgraph → iterate → rank by auth.
Najork 2007
BM25F NDCG=0.221 vs PageRank NDCG=0.092. Content >> link features for retrieval quality.
Web Dynamics
4 types: Size (30T+ pages), Content (34% never change, avg 123h), Query (33% repeats), Location (local intent, 40% re-finding).
QI vs QD Features
QI: precomputed, no query (PageRank, spam, load time). QD: query+doc at runtime (BM25, anchor match, semantic sim).
Anchor Text
Describes linked page from outsider perspective. Valuable (virtual document) but gameable (Google bombing, "evil empire").
TREC 6-Grade Scale
4=Perfect, 3=Excellent, 2=Good, 1=Fair, 0=Bad, -1=Junk. Used for NDCG with gain G=(2^grade−1).
Three Actors
User (relevance), Search Engine (quality+profit), Advertiser (conversions). Tensions: relevance vs ad placement vs spam.
