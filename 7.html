Algorithm 1 — Hearst Patterns

Marti Hearst (1992) — Lexico-syntactic patterns for hypernym extraction

🔎 The Hearst Pattern Intuition

💡
When you see "NP such as NP", you don't need to know what the second NP is — you can infer it's a type of the first NP. This is knowledge encoded in the surface text itself.
"Agar is a substance prepared from a mixture of red algae, such as Gelidium, for laboratory or industrial use."
Even without knowing what Gelidium is, the pattern tells us: Gelidium is-a red algae

The Five Canonical Hearst Patterns

PatternExampleInferred Relation
NPH such as {NP,}*(or|and) NP "red algae such as Gelidium" Gelidium is-a red algae
such NPH as {NP,}*(or|and) NP "such authors as Herrick, Goldsmith" Herrick is-a author
NPH {,} including {NP,}* "common-law countries, including Canada" Canada is-a common-law country
NPH {,} especially {NP,}* "European countries, especially France" France is-a European country
NP {,} NPH and other NP "temples, treasuries, and other civic buildings" temples is-a civic building

Formal Definition

$$\text{NP}_0 \text{ such as } \text{NP}_1, \text{NP}_2, \ldots, (\text{and}|\text{or}) \text{ NP}_i$$ $$\Rightarrow \forall \text{NP}_j, \, j \geq 1: \quad \text{hyponym}(\text{NP}_j, \, \text{NP}_0)$$
If NP₀ = "red algae" and NP₁ = "Gelidium": hyponym(Gelidium, red_algae)

Extended Patterns — Named Entity Constraints

import re
import spacy

nlp = spacy.load("en_core_web_sm")

HEARST_PATTERNS = [
    # PER, POSITION of ORG
    r"(?P<per>[A-Z][a-z]+ [A-Z][a-z]+),? (?P<pos>\w+(?: \w+)*) of (?P<org>[A-Z][A-Za-z &]+)",
    # PER (named|appointed|chose) PER Prep? POSITION
    r"(?P<subj>[A-Z][a-z]+) (?:named|appointed|chose) (?P<per>[A-Z][a-z]+ [A-Z][a-z]+) (?P<pos>\w+(?: \w+)*)",
]

def extract_role_relations(text):
    results = []
    for pat in HEARST_PATTERNS:
        for m in re.finditer(pat, text):
            results.append(m.groupdict())
    return results

sentence = "George Marshall, Secretary of State of the United States, was appointed by Truman."
print(extract_role_relations(sentence))

# Extract dependency path between two entities
def dep_path(token1, token2, doc):
    """Get dependency path between two tokens."""
    ancestors1 = set(t.i for t in token1.ancestors)
    ancestors2 = set(t.i for t in token2.ancestors)
    common = ancestors1 & ancestors2
    lca_idx = min(common, key=lambda i: doc[i].head.i if doc[i].head.i != i else 0,
                  default=token1.i)
    path_up = [token1] + [t for t in token1.ancestors if t.i >= lca_idx]
    path_down = [doc[lca_idx]] + [t for t in token2.ancestors if t.i >= lca_idx][::-1] + [token2]
    return path_up + path_down[1:]

🌱 Bootstrapping from Seed Tuples

🌟
Start with a small number of seed facts (e.g. "Ryanair has hub at Charleroi") and iteratively discover new facts and new patterns from a large corpus.

Confidence Scoring — Preventing Semantic Drift

⚠️
Semantic Drift: Bad patterns lead to wrong tuples → wrong tuples generate bad patterns → the relation's meaning "drifts" far from the original. Example: "Sydney has a ferry hub at Circular Quay" → wrong tuple (Sydney, Circular Quay) as airline hub.
$$\text{ConfRlogF}(p) = \frac{|\text{hits}(p)|}{|\text{finds}(p)|} \cdot \log(|\text{finds}(p)|)$$
where hits(p) = tuples in T that p correctly matches; finds(p) = all tuples p finds in corpus D
$$\text{Conf}(t) = 1 - \prod_{p \in P'} (1 - \text{Conf}(p))$$
Noisy-OR model: confidence in a tuple t given supporting patterns P' — assumes pattern failures are independent
import math

def conf_rlogf(pattern, current_tuples, corpus):
    """
    Confidence score for a pattern.
    Higher = pattern is both precise and productive.
    """
    finds = apply_pattern(pattern, corpus)      # all tuples found
    hits = finds & current_tuples               # correctly found tuples
    if not finds:
        return 0.0
    precision = len(hits) / len(finds)
    productivity = math.log(len(finds))        # reward high recall
    return precision * productivity

def noisy_or_confidence(tuple_t, supporting_patterns, corpus):
    """Confidence in a tuple using noisy-OR combination."""
    failure_prob = 1.0
    for p in supporting_patterns:
        conf_p = conf_rlogf(p, known_tuples, corpus)
        failure_prob *= (1 - conf_p)          # each pattern independently might fail
    return 1 - failure_prob

🔭 Distant Supervision

💡
Use an existing knowledge base (e.g., Freebase, WikiData) to automatically label training sentences. If the KB says (Apple, Steve Jobs, founder-of), then any sentence mentioning both Apple and Steve Jobs likely expresses that relation.
from wikidata.client import Client

def distant_supervision_label(sentence, entity_pairs, knowledge_base):
    """
    Auto-label sentences using a knowledge base.
    If (e1, e2) exists in KB with relation R,
    label all sentences mentioning both e1 and e2 as expressing R.
    """
    labeled = []
    for e1, e2 in find_entity_pairs(sentence):
        relation = knowledge_base.get_relation(e1, e2)
        if relation:
            labeled.append({
                'sentence': sentence,
                'e1': e1, 'e2': e2,
                'relation': relation,
                'label_source': 'distant_supervision'  # not manually verified!
            })
    return labeled

# Example: Freebase tells us (Apple Inc., Steve Jobs) has relation founder-of
# So: "Steve Jobs co-founded Apple in a garage." → labeled as founder-of
# Also: "Apple CEO Steve Jobs announced..." → labeled as founder-of (may be wrong!)
⚠️
Key limitation: Distant supervision introduces noisy labels. "Apple CEO Steve Jobs announced…" doesn't express founder-of, yet it gets labeled as such because (Apple, Steve Jobs, founder-of) is in the KB. Methods like multi-instance learning and attention can help reduce this noise.

🌐 Open Information Extraction (Open IE)

🌍
Instead of predefined relation types, Open IE extracts arbitrary (subject, relation, object) triples directly from text without a fixed schema. Relations are expressed as natural language verb phrases.
Input SentenceExtracted Triple
"Barack Obama was born in Hawaii." (Barack Obama, was born in, Hawaii)
"Dopamine treats Parkinson's disease." (Dopamine, treats, Parkinson's disease)
"United Airlines raised fares by $6." (United Airlines, raised fares by, $6) 
import openie  # or use spacy + custom rules

def open_ie_extract(sentence):
    """
    Open IE: extract (subject, relation, object) triples.
    No predefined schema required.
    """
    doc = nlp(sentence)
    triples = []
    for token in doc:
        if token.dep_ == "ROOT" and token.pos_ == "VERB":
            subjects = [t for t in token.lefts if t.dep_ in ("nsubj", "nsubjpass")]
            objects  = [t for t in token.rights if t.dep_ in ("dobj", "pobj", "attr")]
            for subj in subjects:
                for obj in objects:
                    triples.append((
                        " ".join(t.text for t in subj.subtree),
                        token.lemma_,
                        " ".join(t.text for t in obj.subtree)
                    ))
    return triples

# Advantages: works on any domain, no labelling needed
# Disadvantages: lower precision, relations can be verbose/redundant
✅
Works on ANY domain without labelled data. Scales to the entire web.
⚠️
Relations are noisy strings — harder to query. Can extract trivially true or uninformative facts.

Q3 [2 marks] — A hospital wants to deploy a BERT-based system to recommend treatments from clinical notes. Give TWO ethical concerns specific to this deployment.
Model Answer (2 marks):

1. Explainability / Liability [1 mark]: BERT is a black box — clinicians and patients cannot understand why a specific treatment was recommended. This violates regulatory requirements in many jurisdictions (e.g., EU AI Act, GDPR's "right to explanation") and creates liability issues if the recommendation harms a patient.

2. Bias [1 mark]: If the training data (clinical notes) contains historical biases (e.g., underdiagnosis of conditions in certain demographic groups), the model will perpetuate or amplify these biases, potentially providing worse recommendations for already-marginalised patients.
Q4 [3 marks] — Using the noisy-OR formula, calculate the confidence in a new tuple t, given three supporting patterns with confidences: Conf(p₁) = 0.9, Conf(p₂) = 0.7, Conf(p₃) = 0.5. Show your working.
Model Answer (3 marks):

Using: \(\text{Conf}(t) = 1 - \prod_{p \in P'} (1 - \text{Conf}(p))\)

Step 1: Calculate failure probabilities:
  (1 − 0.9) = 0.1
  (1 − 0.7) = 0.3
  (1 − 0.5) = 0.5

Step 2: Multiply failure probabilities:
  0.1 × 0.3 × 0.5 = 0.015

Step 3: Subtract from 1:
  Conf(t) = 1 − 0.015 = 0.985

This means we are 98.5% confident in tuple t, since it would require all three independently-failing patterns to be wrong simultaneously. [1 mark per step]
Q5 [2 marks] — Why does distant supervision produce noisy training labels? Give a concrete example.
Model Answer (2 marks):

Why noisy [1 mark]: Distant supervision assumes that any sentence mentioning both entities in a KB relation expresses that relation. But this assumption is often wrong — a sentence may mention both entities without expressing the KB relation at all.

Example [1 mark]: The KB states (Apple, Steve Jobs, founder-of). So "Apple CEO Steve Jobs announced the iPhone" is auto-labelled as expressing founder-of. But this sentence expresses an employment/announcement relation, not the founding relation. This introduces a label error into the training set.

2024 Exam — Q1: Tokenisation (20 marks)

[4 marks] Why are stopwords removed in bag-of-words but not removed for transformers? Give an example. ▼
📝
Model Answer:

Consider "The cat sat on the mat".

Bag-of-words [2 marks]: Stopwords add no discriminative signal to a BoW vector — "the", "on" are equally common in all documents. Removing them reduces dimensionality and noise. In BoW, word order is lost anyway, so "the cat sat on the mat" and "the mat sat on the cat" produce the same vector — stopwords convey no positional information.

Transformers [2 marks]: Transformers model word sequences in full context. Stopwords carry positional and syntactic meaning — "the cat is on the mat" and "the mat is on the cat" have different meanings that a transformer can distinguish. Removing stopwords would destroy this information.
⚠️
Common mistake: Saying "transformers don't use stopwords because they use attention" — this is vague. The key point is word order / contextual meaning.
[4 marks] A colleague says [UNK] is unnecessary for BPE tokenisers. Are they correct? Consider Unicode. ▼
📝
Model Answer:

The colleague is incorrect [1 mark].

BPE builds a vocabulary from characters seen during training. However, Unicode encodes far more characters (over 140,000) than are likely to appear in any training corpus [1 mark]. Additionally, new Unicode characters (emoji, scripts, symbols) are regularly added and will not appear in older training data [1 mark]. When such unseen characters appear at inference time, [UNK] is needed to handle them [1 mark].
[6 marks] Apply BPE rules to tokenise mississippi and pie. Show all steps. ▼

Rules (in order): i,s→is | p,i→pi | i,e→ie | p,ie→pie | p,pi→ppi | si,ppi→sippi

📝
Model Answer — mississippi:

Start: m i s s i s s i p p i
Apply (i,s→is): m is s is s i p p i
Apply (p,i→pi): m is s is s i p pi
(i,e→ie) does not apply
(p,ie→pie) does not apply
Apply (p,pi→ppi): m is s is s i ppi
(si,ppi→sippi) does not apply — no adjacent "si" and "ppi"
Final: m is s is s i ppi

pie:
Start: p i e
(i,s→is) does not apply
Apply (p,i→pi): pi e
(i,e→ie) does not apply — 'i' is now part of 'pi'
(p,ie→pie) does not apply
Final: pi e
⚠️
Rules are applied greedily left-to-right in the given order. Once merged, a subtoken is treated as a single unit.
[6 marks] Effect of BPE vocabulary size too low (100) or too high (100,000,000)? ▼
📝
Model Answer:

Too Low (vocab=100) [3 marks]: BPE would stop merging very early. Words get split into too many sub-units — effectively individual characters. Characters carry almost no semantic meaning on their own, making it very hard for downstream models to learn useful representations. Sequences become extremely long, increasing computational cost.

Too High (vocab=100,000,000) [3 marks]: This exceeds the number of distinct word types in most corpora, so every word gets its own token — no merging occurs. This defeats the purpose of subword tokenisation: rare and unseen words still get [UNK] treatment, and there are too many tokens for the model to learn good representations from limited data.

Practice [2 marks] — Name two advantages of subword tokenisation over pure word tokenisation for handling morphologically rich languages (e.g., Turkish, Finnish).
1. Handles unseen words by decomposing them into known subword units (e.g., a new Turkish verb form can be split into a root + suffix both seen in training).
2. Smaller vocabulary: morphologically rich languages have enormous word-form spaces; subwords represent all forms compactly, reducing memory and improving generalisation.

[8 marks] Bigram model + beam search (beam width=2): next 2 tokens. Show all beams. ▼

Model Answer (last char = B, so context for bigram is B):

First count bigram probabilities from B:
B→A: 1, B→B: 3, B→C: 5 (total 9 B's as context)
P(A|B)=1/9, P(B|B)=3/9=1/3, P(C|B)=5/9

• B: P=3/9 ≈ 0.333

[4 marks] Propose a 2-char string a bigram model cannot generate; how to fix it? ▼
📝
Model Answer:

String: "AA" [1 mark]

Why it can't be generated [1 mark]: P(A|A) = 0 because in the training text 'A' never follows 'A'. A greedy/beam search bigram model will never generate 'A' after 'A'.

Fix [2 marks]:
1. Apply Laplace (add-1) smoothing or Kneser-Ney smoothing to give all bigrams a non-zero probability.
2. Use sampling-based generation (temperature sampling) instead of greedy decoding, so low-probability tokens still have some chance of being selected.

Practice [3 marks] — What is perplexity? If a unigram model assigns P(A)=0.5, P(B)=0.3, P(C)=0.2, what is the perplexity on the test string "ABC"?
Perplexity [1 mark]: Perplexity = 2^(–(1/N)·Σlog₂P(wᵢ)) — it measures how "surprised" the model is by the test data. Lower = better.

Calculation [2 marks]:
P(ABC) = P(A)·P(B)·P(C) = 0.5 × 0.3 × 0.2 = 0.03
Log₂(0.5)= –1, Log₂(0.3)≈ –1.737, Log₂(0.2)≈ –2.322
Average log = (–1 – 1.737 – 2.322)/3 = –5.059/3 ≈ –1.686
Perplexity = 2^1.686 ≈ 3.22
Practice [2 marks] — Explain why beam search with beam width k=1 is equivalent to greedy decoding, but beam search with k→∞ is equivalent to exhaustive search.
k=1 [1 mark]: At each step, only the single best candidate is kept. This is identical to always choosing the locally highest-probability token — greedy decoding.
k→∞ [1 mark]: All possible candidates are kept at every step, so no path is ever pruned. The final output is the globally optimal sequence — equivalent to exhaustive search over all possible continuations.

2022 Exam — Q1: Distributional Semantics & Word Embeddings (18 marks)

[5 marks] Pseudo-code: given word vectors, find the outlier word (e.g., from {linux, windows, solaris, android, java}). ▼
📝
Model Answer:

Idea: Compare each word's vector against the centroid of the remaining words. The word with the lowest similarity to the centroid is the outlier.

Input: words w1,...,wn with vectors v1,...,vn
For i = 1 to n:
    c = vi                          # candidate outlier
    R = {v1,...,vn} \ {c}          # remaining vectors
    µi = (1/|R|) * Σ(v for v in R) # centroid of rest
    si = cosine_similarity(c, µi)  # similarity to centroid
Output: wi with the smallest si     # least similar = outlier
Key notation to define: V = set of all word vectors, µᵢ = centroid, sᵢ = similarity score [1 mark each component + 1 for correctness]
[2 marks] Distributional semantics window size k: too large vs too small? ▼
📝
Model Answer:

Too large k [1 mark]: Contexts become too broad and noisy. Almost any word will co-occur with almost any other word, making the vectors uninformative (P(context|word) approaches uniform distribution).

Too small k [1 mark]: Contexts are too narrow. Not enough co-occurrence data is captured, so vectors are sparse and unreliable — especially for rare words.
[5 marks] Single-pass pseudo-code for distributional semantics vector building. ▼
📝
Model Answer:

k = window size
D = {}  # dictionary mapping word → sparse vector

For i = 1 to P (P = total tokens in corpus):
    window = [t_{i-k}, ..., t_{i-1}, t_i, t_{i+1}, ..., t_{i+k}]
    v = term_frequency_vector(window)  # sparse counts
    D[t_i] += v                        # accumulate into word's vector

Return D
Key data structures: D is a dictionary of sparse vectors (e.g., Python dict of dicts or scipy sparse matrix) — efficient because most words never co-occur.
[2 marks] Why are function word vectors (the, of, is…) unreliable in this approach? ▼
📝
Model Answer:

Function words are extremely frequent and appear in nearly every context. Therefore, for a function word w, P(context_i | w) is close to uniform across all context words [1 mark].

Example: "the" appears before nouns, adjectives, proper names, numbers — essentially any word class. Its context vector will be roughly the average of the entire vocabulary, giving it no meaningful discriminative representation [1 mark].
[2 marks] Role of negative samples in word2vec objective function. ▼
📝
Model Answer:

Without negative samples, word2vec would only have positive examples (actual context words). The model could trivially "solve" this by making all word vectors identical [1 mark].

Negative samples provide contrast: the model must distinguish true context words from randomly sampled non-context words. This turns the problem into binary classification (positive vs negative pair), enabling stable gradient-based training [1 mark].
[2 marks] word2vec and polysemous words (jaguar, bank, python) — nearest neighbours and downstream problems. ▼
📝
Model Answer:

Nearest neighbours [1 mark]: word2vec produces a single vector per word, which averages over all meanings. For "python", the NN set mixes programming words (language, numpy, script) with animal words (snake, reptile, venom).

Downstream problem [1 mark]: This ambiguous vector hurts tasks like text classification. A document about Python programming would have a feature vector polluted by animal-related directions, potentially causing misclassification.
💡
Fix: Contextual embeddings (BERT, ELMo) solve this by producing different vectors for the same word in different contexts.

🏋️ Practice — Word Embeddings & Distributional Semantics

Practice [5 marks] — You have word vectors for: {football, rugby, tennis, cricket, banana}. Describe the full pseudo-code algorithm to identify "banana" as the outlier, and explain why cosine similarity is preferred over Euclidean distance for this task.
Algorithm [3 marks]:
For each word wᵢ: compute µᵢ = mean of all other word vectors.
Compute sᵢ = cosine_similarity(vᵢ, µᵢ).
Output: word with smallest sᵢ → "banana".

Why cosine over Euclidean [2 marks]:
1. Word vectors can have very different magnitudes (frequent words tend to have larger magnitude). Cosine similarity is normalised — it measures direction/angle, not magnitude, so frequency effects don't pollute the similarity.
2. Euclidean distance is affected by vector length; two vectors pointing in the same direction but with different norms would appear dissimilar under Euclidean, but similar under cosine.
Practice [3 marks] — PPMI (Positive Pointwise Mutual Information) is often applied to distributional vectors before use. What problem does it solve, and write the formula for PMI(w, c).
Problem solved [1 mark]: Raw co-occurrence counts are dominated by frequent words — "the", "of" appear with almost every word. PMI reweights by how much more often w and c co-occur than expected by chance, suppressing function word noise.

Formula [1 mark]: PMI(w,c) = log₂[ P(w,c) / (P(w)·P(c)) ]

PPMI [1 mark]: PPMI(w,c) = max(0, PMI(w,c)) — negative values (words that co-occur less than chance) are clamped to 0, since negative PMI estimates are unreliable with small counts.

[4 marks] Sørensen–Dice & Jaccard between Probe A and Probe B (show working). ▼

A={a, eda, bceda, eda, bcda, bce} → unique={a, eda, bceda, bcda, bce} (5 types)
B={ca, eda, bcba, eda, bceda, eda, bce} → unique={ca, eda, bcba, bceda, bce} (5 types)

📝
Model Answer:

A∩B (shared types) = {eda, bceda, bce} → |A∩B| = 3
A∪B = {a, eda, bceda, bcda, bce, ca, bcba} → |A∪B| = 7

Sørensen–Dice:
$$\text{DSC}(A,B) = \frac{2|A \cap B|}{|A| + |B|} = \frac{2 \times 3}{5 + 5} = \frac{6}{10} = 0.6$$
Jaccard:
$$J(A,B) = \frac{|A \cap B|}{|A \cup B|} = \frac{3}{7} \approx 0.429$$
🔑
Relationship: DSC = 2J/(1+J) always. Dice gives more weight to shared elements than Jaccard.
[3 marks] Show Sørensen–Dice breaks the triangle inequality using Probe C. ▼

C={beda, bceda, bceca, ebeda, bceda, b} → unique={beda, bceda, bceca, ebeda, b} (5 types)

📝
Model Answer:

A∩C = {bceda} → |A∩C|=1
DSC(A,C) = 2×1/(5+5) = 2/10 = 0.2

B∩C = {bceda} → |B∩C|=1
DSC(B,C) = 2×1/(5+5) = 2/10 = 0.2

Triangle inequality check: For a metric d, we need d(A,B) ≤ d(A,C) + d(C,B).
Using DSC as a distance = 1 – DSC:
d(A,B) = 1–0.6 = 0.4
d(A,C)+d(C,B) = (1–0.2)+(1–0.2) = 0.8+0.8 = 1.6
0.4 ≤ 1.6 ✓ — this holds.

Actually in the exam, the raw DSC values are compared:
DSC(A,B)=0.6, DSC(A,C)+DSC(B,C)=0.2+0.2=0.4
If we treat DSC directly as a "similarity metric distance", then:
0.6 ≤ 0.4 is FALSE — the triangle inequality is violated, confirming DSC is a semi-metric.

[4 marks] How to add POS tags to a BERT model (without ensemble)? How does this differ from BoW? ▼
📝
Model Answer:

BERT approach [2 marks]: BERT represents each token as a dense embedding (sum of token + position + segment embeddings). To incorporate POS, add a POS embedding layer — a learnable embedding table with one vector per POS tag. At input, add the POS embedding to the token embedding before feeding into the transformer layers. This is analogous to how segment or positional embeddings are added.

BoW approach [1 mark]: In a bag-of-features model, POS is incorporated by creating a separate feature for each (word, POS) pair — e.g., "light/NOUN" and "light/ADJ" become two distinct sparse features. The model is linear over these features.

Key difference [1 mark]: In BoW, POS creates explicit discrete features in a sparse vector, and POS information doesn't interact with other features. In BERT, POS embeddings are continuous and are processed by the transformer's attention mechanism alongside all other context, enabling richer interactions.

Practice [2 marks] — What is the difference between micro-averaged and macro-averaged F1 for a multi-class classifier? When would you prefer each?
Micro-averaged F1 [1 mark]: Pools all TP, FP, FN across all classes before computing P, R, F1. Gives more weight to larger classes. Use when class imbalance exists and you care about overall system accuracy.

Macro-averaged F1 [1 mark]: Computes F1 per class independently, then averages. Treats all classes equally. Use when each class matters equally regardless of size — e.g., for rare disease detection where a small class is just as important as a large one.

QF5 [2 marks] — Why does multi-stage fine-tuning (training on task A, then task B) sometimes degrade performance compared to just fine-tuning on task B alone?
Catastrophic forgetting [1 mark]: Fine-tuning on task A changes the model weights to specialise for A. When then fine-tuned on B, the model may "forget" the general representations learned during pre-training.

Task mismatch [1 mark]: If task A has different characteristics from task B (e.g., BOOLQ has direct yes/no answers while Circa has indirect answers), the fine-tuning on A shifts the model's decision boundaries in a direction that is harmful for task B.
