⚙️ YARN — Yet Another Resource Negotiator

YARN is a scheduling system designed for Hadoop ecosystem applications. Goal: Separation of Concerns — decouple Cluster Resource Management from Job Coordination. Solves the bottleneck of the original Hadoop Job Tracker.
Old Job Tracker problems: The original Hadoop Job Tracker had too many responsibilities — scheduling tasks, monitoring executions, restarting failed tasks, running speculative tasks, and calculating counters — all in one component. Single point of failure + scalability bottleneck.

YARN Components in Detail

Resource Manager

Scheduler: Examines available resources, allocates tasks/Application Masters to Node Managers. Pure resource scheduling — no job tracking.

Application Manager: Handles new application registration, first Application Master boot, restarts.

Application Master

Replaces the Job Tracker — but only tracks ONE job's lifecycle. Asks Resource Manager where tasks should go. More lightweight. Enables support for non-MapReduce jobs (Spark, Flink, etc.).

Node Manager

Replaces Task Tracker. Allocates containers to run tasks. Contains shuffle handlers for data passing (Map → Reduce). Tracks actual machine resources. Supports variably-sized tasks (not fixed slots).

Important Note: YARN "Node Manager Containers" (NMC) are NOT the same as Docker containers. NMCs are blocks of CPU/memory resources allocated per task within the Node Manager. Docker containers are software isolation units. Different concepts with the same word!

YARN Application Lifecycle

1

Client Registers Application

Client submits a new application request to the Resource Manager.

2

Resource Manager Starts Application Master

Resource Manager allocates an Application Master on a specific Node Manager worker machine.

3

Application Master Requests Resources

Application Master requests containers from Resource Manager. Resource Manager returns list of containers with: priority, hostname, resources (CPU/memory), number of containers.

4

Application Master Instructs Node Managers

Application Master tells Node Managers to start containers with specified resources. Node Manager Container (NMC) instances launched.

5

Application-Specific Logic Runs

Application Master manages job-specific logic until completion (e.g., MapReduce task management, Spark DAG execution).

☸️ Kubernetes

Kubernetes is an open-source container orchestration system for automating deployment, scaling, and management of containerized applications. Originally developed by Google, now maintained by the Cloud Native Computing Foundation. De facto standard for container management.
Key Difference from YARN: Kubernetes is designed for containers (Docker, containerd) whereas YARN was designed for JVM-based processes. Kubernetes uses a declarative state management model — users define desired state; Kubernetes continuously works to achieve it.

Kubernetes Architecture

Kubernetes Master

  • API: Registers new containers and configuration
  • ETCD: Central distributed key-value store holding ALL cluster state
  • Scheduler: Allocates containers/pods to nodes
  • Controller Manager: Failure recovery, node status tracking, container replication

Kubernetes Worker (Node)

  • Kubelet: Ensures pods are running; manages pod lifecycle; implements container engine
  • Kube-proxy: Maintains network rules; handles service-to-pod routing; internal/external networking
  • cAdvisor: Analyzes and exposes resource usage from running containers; performance metrics
State Management Philosophy: Users define a desired state as Kubernetes Objects. Kubernetes Scheduler + Controller Manager continuously work to achieve and maintain that state. If something deviates, Kubernetes auto-heals. You say "what you want", not "how to do it" (declarative, not imperative).

Kubernetes Objects

🫛

Pod

Smallest compute unit. Groups one or more containers. Containers share CPU, memory, storage. Always co-located (same physical machine). Created and destroyed together.

🌐

Service

Stable network identity for pods (whose IP changes). Internal hostname (e.g., service1:8080). Re-routes traffic to designated pods. Can load-balance across multiple pods.

🔗

Route

Exposes a Service externally. Provides public hostname (e.g., jupyter-ns.cluster.dcs.gla.ac.uk:80). Makes cluster services accessible from public internet.

Kubernetes Advantages & Disadvantages

Advantages

  • De facto industry standard — universal adoption
  • Reliable and lightweight
  • Granular CPU/memory resource allocation
  • Built-in network load balancing
  • Native Docker container support
  • Self-healing (auto restart, replication)
  • Declarative configuration (desired state)

Disadvantages

  • Steep learning curve
  • Many objects beyond Pods/Services/Routes
  • Storage management can be complex
  • Debugging is difficult (multiple abstraction layers)
  • Distributed nature complicates root cause analysis

⚖️ Legal & Ethical Considerations

Core Principle: Big Data systems can process and analyze large volumes of data very quickly, identify behavioral patterns, and enable data-driven decisions at scale. This power can be harmful to individuals or society. With "big" data comes "big" responsibility.

Case Study: Facebook–Cambridge Analytica Scandal

2013

App Development

Cambridge Analytica develops "This Is Your Digital Life" — a Facebook survey app, publicly available. Users paid to complete survey, told it was for academic use (University of Cambridge).

2013

Data Overcollection

App used Facebook API to crawl users' social network: friends' public profiles, page likes, birthdays, cities, connections. Users consented to their OWN data — not their friends'.

2013–2015

Scale of Violation

~250,000 direct survey users → data collected on 87 million users total (~86.75M without direct consent). Detailed enough to create psychographic profiles: personality, behavior, political preferences.

2016

Political Targeting

Data used for targeted political campaigns: US Trump presidential campaign (2016) and UK Vote Leave campaign (Brexit). Psychological vulnerability profiles used for tailored messaging.

2018

Public Exposure & Consequences

Scandal made public. Facebook stock: -$100B market cap in days. Cambridge Analytica: bankruptcy. Facebook fined $5B (largest FTC privacy fine). Accelerated GDPR enforcement globally.

Why it was unethical AND illegal:
  • Informed consent violation: Users consented to their own data, not friends'
  • Secondary use violation: Data used for political targeting, not academic research
  • Scope violation: Data collection exceeded what users authorised
  • Manipulation: Used psychological vulnerability profiles to influence political behaviour

1. Privacy

Privacy as a Human Right

Recognised under: Human Rights Act 1998 (UK), European Convention on Human Rights. Data Protection Act 1998 (UK) implementation.

The fuzzy definition problem: Privacy is not clearly defined in practice. Humans don't understand implications of online publishing. Key challenge: distinguishing public vs. private users and usages — important but difficult in practice.

Key question: Are social media spaces public or private? Does posting publicly mean it's open to any use? Cassandra Analytica used "public" Facebook data — but users did not expect or consent to its use for political profiling.

2. Informed Consent

Definition

An individual's explicit, voluntary, and knowledgeable agreement to the processing of their data for clearly understood uses.

Why Big Data Makes This Hard

Very little may be known about future uses of data when collected. Consent at collection time is one-off — future analyses are unknown. Traditional consent frameworks not designed for this.

Terms & Conditions Problem

Validity of consent via T&Cs is debatable. Users rarely read them. Often incomprehensible. Acceptance is coerced ("agree or can't use service"). Doesn't meet strict "informed consent" definition.

Practical Reality

Obtaining truly informed consent may be impossible or prohibitively expensive for Big Data analytics. Trade-off between privacy protection and service utility.

3. De-identification

Definition: Process where data elements that might immediately identify a person have been removed or masked (anonymization, pseudonymization).
Key insight: Identifiability is NOT binary (identified vs. anonymous). It is a continuum. Very few datasets are truly anonymous. De-identification reduces re-identification risk but cannot eliminate it.

Dimensionality Risk

More variables = higher re-identification risk. Combining multiple demographic variables (age + location + occupation) creates unique combinations that identify individuals even without names.

Linkage Risk

Merging anonymised data with other data sources (public records, social media) can enable re-identification. Different datasets may have overlapping identifiers.

Analytics Power Risk

Machine learning can extract patterns that re-identify individuals. Inference attacks can deduce sensitive information even from seemingly anonymous data.

Mitigation strategies: Data aggregation, noise injection, differential privacy, access restrictions. Disclosure risks CAN be mitigated but CANNOT be eliminated.

4. Data Protection Act 1998 (UK)

Applies to any "personal data" — any data that could be used to identify a living individual. Individuals must consent to collection.
1

Fair & Lawful Processing

Data shall be processed fairly and lawfully. Must have legal basis (contract, legal obligation, consent).

2

Purpose Limitation

Obtained only for specified lawful purposes. No further processing incompatible with that purpose.

3

Data Relevance

Adequate, relevant and not excessive in relation to the purpose. No unnecessary data collection.

4

Accuracy

Data shall be accurate and kept up to date where necessary.

5

Storage Limitation

Not kept longer than necessary for the purpose. Must justify retention and delete when done.

6

Data Subject Rights

Processed in accordance with rights of individuals: access, correction, objection, restriction.

7

Security

Appropriate technical and organisational measures against unauthorised processing, accidental loss or destruction.

8

International Transfer

No transfer outside EEA unless adequate protection guaranteed. Prevents "data havens".

5. Freedom of Information Act 2000 (UK)

Enhanced rights for public organisations

Provides the public with MORE rights than DPA 1998 for data held by public bodies. Includes:

  • Data Access Right: Right to view data held about you (reasonable fee may apply)
  • Data Correction Right: Right to request correction of incorrect information
  • Processing Protection: Right to prevent use that could cause damage or distress
  • Marketing Opt-Out: Right to prevent data use for direct marketing

6. GDPR — EU General Data Protection Regulation

Extraterritorial reach: GDPR applies to ANY organisation processing personal data of EU residents — even non-EU organisations. Violating GDPR: up to 4% of annual global revenue OR €20 million (whichever is higher).

GDPR Definition of Personal Data

"Information that relates to an identified or identifiable individual" — taking into account all means reasonably likely to be used to identify the individual. Broader than just direct identifiers. Even your IP address or cookie ID can be personal data.

GDPR — 6 Lawful Bases for Processing

1. Explicit Consent

Clear, voluntary, specific consent for defined purposes. Must be withdrawable and unambiguous.

2. Contractual Necessity

Processing necessary to fulfill contractual obligations (employment, service agreements).

3. Legal Obligation

Processing required by law (tax records, compliance).

4. Vital Interests

Protect life of data subject or another person. Health emergencies.

5. Public Interest

Task in public interest or exercising official authority. Government functions.

6. Legitimate Interests

Necessary for legitimate interests of controller or third party — UNLESS overridden by data subject's rights.

Ethics ≠ Law

Critical principle: Something legal may not be ethical. Just because you can process data doesn't mean you should. Cambridge Analytica's initial data collection was arguably legal under Facebook's API terms — but clearly unethical. Consider broader societal impacts, not just legal compliance.

📋 Past Exam Questions & Model Answers

[2025 Exam Q] Describe the YARN architecture and explain how it improves upon the original Hadoop Job Tracker. (10 marks)

Model Answer

Problem with original Job Tracker: All-in-one component with too many responsibilities — scheduling tasks, monitoring executions, restarting failed tasks, speculative execution, computing counters. Single point of failure; could not support non-MapReduce applications.

YARN Architecture (Separation of Concerns):

  • Resource Manager (replaces Job Tracker for resource management): Scheduler examines resources and allocates; Application Manager handles app registration and Application Master lifecycle
  • Application Master (replaces Job Tracker for job tracking, one per job): Lightweight, only tracks one job's lifecycle; requests resources from Resource Manager; tells Node Managers to start containers; supports non-MapReduce jobs
  • Node Manager (replaces Task Tracker): Allocates containers with specified resources; handles shuffle; tracks actual machine resources; supports variably-sized tasks

Application Lifecycle: Client → Resource Manager (register) → Resource Manager starts Application Master → Application Master requests containers → Resource Manager returns container list → Application Master instructs Node Managers → tasks run in containers → Application Master manages until completion.

Key improvements: No central SPOF for job management (each job gets own Application Master), enables Spark/Flink/etc. (not just MapReduce), variable container sizes vs fixed slots, cleaner separation of resource scheduling vs job tracking.

[2024 Exam Q] Explain Kubernetes' declarative state management model. Describe the roles of Pods, Services, and Routes. (10 marks)

Model Answer

Declarative State Management: Users define desired cluster state through Kubernetes Objects (YAML). The Kubernetes Scheduler and Controller Manager continuously work to achieve and maintain that state. If something deviates (pod crash, node failure), Kubernetes auto-heals. Users say "what they want", not "how to do it" — unlike traditional imperative management where you issue explicit commands.

Pod: Smallest compute unit. Groups one or more containers. Containers in a pod: share CPU/memory/storage, always co-located (same physical machine), visible to each other over network, created and destroyed together. Kubernetes doesn't define a "container" object directly — you define a Pod.

Service: Provides stable network identity for pods (whose location/IP changes when restarted). Has internal hostname (e.g., service1:8080). Re-routes traffic to designated pods. Can load-balance across multiple pods. Managed by kube-proxy.

Route: Exposes a Service externally (outside cluster). Provides public hostname (e.g., http://jupyter-ns.cluster.dcs.gla.ac.uk). Makes cluster services accessible from public internet. Flow: User → Route → Service → Pod(s).

[2024 Exam Q] Describe the Cambridge Analytica scandal. What ethical and legal principles did it violate? (12 marks)

Model Answer

What happened: Cambridge Analytica developed "This Is Your Digital Life" Facebook app (2013). ~250,000 users took survey, consented to their OWN data collection for "academic use". App exploited Facebook API to also collect data on users' FRIENDS — without those friends' knowledge or consent. 87 million users' data collected total. Data used to build psychographic profiles. These profiles used for targeted political advertising: Trump 2016 campaign and UK Vote Leave (Brexit).

Ethical violations:

  • Informed consent: Friends never consented — fundamental violation of data ethics
  • Secondary use: Data collected under academic pretext, used for political manipulation
  • Psychological exploitation: Used identified vulnerabilities to manipulate political choices
  • Deception: Users misled about purpose and scope of data collection

Legal violations:

  • DPA 1998 Principle 2: Purpose limitation — academic data used for political targeting
  • DPA 1998 Principle 1: Unfair processing — friends processed without any consent
  • GDPR (once enforced): Would violate Articles on lawful basis, consent, and data subject rights

Consequences: Facebook -$100B market cap; $5B FTC fine; Cambridge Analytica bankruptcy; accelerated GDPR enforcement worldwide.

[2023 Exam Q] Explain GDPR's definition of personal data and list the 6 lawful bases for processing. Why is GDPR stricter than the DPA 1998? (10 marks)

Model Answer

GDPR personal data definition: "Information that relates to an identified or identifiable individual" — taking into account all means reasonably likely to be used to identify. This includes indirect identifiers: IP addresses, cookie IDs, device IDs, location data. Much broader than DPA's narrow focus on direct identifiers.

6 Lawful Bases:

  1. Explicit Consent — clear, voluntary, specific, withdrawable
  2. Contractual Necessity — fulfilling contractual obligations
  3. Legal Obligation — required by law
  4. Vital Interests — protecting life
  5. Public Interest / Official Authority — government functions
  6. Legitimate Interests — balanced against data subject rights

Why stricter than DPA 1998:

  • Broader definition of personal data (includes indirect identifiers)
  • More robust consent requirements (explicit, specific, withdrawable)
  • Mandatory Data Protection Officer appointment
  • Right to erasure ("right to be forgotten")
  • Right to data portability
  • 72-hour breach notification requirement
  • Massive fines: up to 4% global revenue or €20M
  • Extraterritorial: applies to non-EU organisations processing EU data
[2022 Exam Q] Why is de-identification insufficient to guarantee privacy in Big Data? Describe three risks. (8 marks)

Model Answer

Key insight: Identifiability is a continuum, not a binary. De-identified data still carries re-identification risk that cannot be eliminated, only mitigated.

Three risks:

  • Dimensionality Risk: More variables in dataset → more unique combinations. Even removing name/ID, combining age + postcode + occupation + health condition can uniquely identify individuals in small populations. Risk increases with dataset richness.
  • Linkage Risk: Anonymised dataset can be re-identified by joining with other public data sources (voter rolls, social media profiles, public records). Different datasets may share overlapping features that create identifying links when combined.
  • Analytics Power Risk: Machine learning and inference attacks can extract patterns that re-identify. Models trained on anonymised data may "memorise" individual records. Sophisticated adversaries can probe ML models to infer training data.

Mitigation (not elimination): Data aggregation (report statistics, not individuals), differential privacy (add calibrated noise), access restrictions, data minimisation. These reduce risk but cannot guarantee zero re-identification.

✏️ Practice Questions

Q1. A company collects email addresses for newsletter subscriptions, then later wants to use those emails to train an ML model to predict churn. Under GDPR, what must they check before doing this? Which DPA principle is most relevant?

GDPR checks required:
  • Original lawful basis: Email addresses were collected for newsletter use — that's the declared purpose.
  • Compatible further processing: Using for ML churn prediction is likely incompatible with the newsletter purpose. GDPR requires assessing: link between purposes, context/nature of data, nature of processing (ML training), possible consequences for data subjects.
  • Re-consent or new lawful basis: Unless there's legitimate interest justification, company likely needs to obtain fresh explicit consent for the new use.
Most relevant DPA 1998 principle: Principle 2 — Purpose Limitation
"Personal data shall be obtained only for one or more specified and lawful purposes and shall not be further processed in any manner incompatible with that purpose."

The purpose (newsletter) is specified at collection time; churn prediction ML is a different, incompatible purpose.

Q2. In Kubernetes, what is the difference between a Pod and a Service? Why do you need both to run a web application on the cluster?

Pod: Smallest compute unit — groups one or more containers that share resources and are co-located. The pod runs the application code. But pods are ephemeral: when Kubernetes restarts a pod (after failure or scaling), it gets a new IP address. There's no stable network identity.

Service: A persistent network object with a stable hostname (e.g., webapp:80). Services stay at the same address even as pods come and go. kube-proxy routes traffic from the Service to whichever pods match the service's selector. Services can load-balance across multiple pod replicas.

Why you need both:
Without a Pod: nothing runs.
Without a Service: other components (or routes) have no stable way to reach the pod — addresses change every time the pod restarts. Combining both: Pod(s) run the code; Service provides stable discovery and load balancing.

For external access: Add a Route to expose the Service externally — all three objects work together.

Q3. A researcher wants to use Twitter data (publicly posted tweets) for a study on mental health. Identify three ethical/legal issues they should consider.

Issue 1 — Privacy: Even "public" tweets may violate privacy expectations. Users tweet in context (Twitter community) — use for mental health research is a different context. Some users may not have intended medical research use. GDPR may apply if tweets contain mental health indicators (special category data).

Issue 2 — Informed Consent: Twitter users have not consented to mental health research. Accepting Twitter T&Cs is not informed consent for this purpose. Under GDPR, mental health data is "special category data" requiring explicit consent or specific research exemption.

Issue 3 — De-identification / Re-identification Risk: Tweets are often pseudonymous (username, not real name) but username + tweet content can easily re-identify individuals. Mental health analysis makes re-identification more sensitive (could harm subjects if linked back). Linkage with other public data (bio, location) increases risk.

Additional — Research Integrity: Commercial restrictions on Twitter data (now X/xAI). Twitter API limits redistribution. Must document data provenance and collection methods. Research ethics board approval likely required.

Q4. What is the difference between YARN's Resource Manager and an Application Master? Why was separating them architecturally important?

Resource Manager: Cluster-wide resource management service. Contains Scheduler (allocates CPU/memory to jobs) and Application Manager (registers apps, manages Application Master lifecycle). One per cluster. Knows cluster state (available resources on each node) but does NOT know about individual job logic.

Application Master: Per-job coordinator. One per running application. Only tracks its own job's lifecycle (task dependencies, progress, failures). Requests resources from Resource Manager (which nodes, how much CPU/memory). Instructs Node Managers to start containers. Does NOT know about other jobs.

Why separation matters:
  • Scalability: Original Job Tracker managed ALL jobs — bottleneck for large clusters. With Application Masters, job management load is distributed (each job gets own AM)
  • Application diversity: Resource Manager is application-agnostic. Application Master is application-specific. This enables Spark, Flink, custom apps — not just MapReduce
  • Fault isolation: One failing Application Master only affects one job, not entire cluster
  • Variable resource needs: Different application types need different resource containers; AM handles job-specific sizing
