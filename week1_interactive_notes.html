Week 1: What is Big Data?

COMPSCI5088 (M) · University of Glasgow · Dr. Richard McCreadie

This week covers the foundations of Big Data: what it is, why it matters, the hardware that limits us, how we use it, and the ethical/legal responsibilities that come with it. These topics are heavily tested in exams — every past paper has at least one scenario-based question on Big Data dimensions.

What is Big Data?

Official Course Definition

"Data whose capturing, storage, curation, management, and processing are not possible with traditional tools within a tolerable amount of time"

Defined by Use

  • Capturing, storage, curation, management → how we store and access it
  • Processing → how we gain value from it

Defined by Available Tools

  • Traditional tools → the software available
  • Tolerable amount of time → the hardware available

Big Data is RELATIVE

What counts as Big Data changes over time. In the 1990s, 100MB might have been Big Data. Today, 1 Petabyte (10⁹ MB) might be Big Data. This shift happens as hardware and software become more powerful. By 2025, global data is projected to exceed 180 zettabytes.

1990s: 100MB = Big Data2025: 180 Zettabytes created/year
Exam Tip

When asked "is this a Big Data problem?", always justify with reference to: (1) the scale/volume of data, (2) whether traditional tools could handle it, and (3) the time constraints involved. The examiner awards marks for your reasoning, not just yes/no.

The 6 Dimensions of Big Data (The 6Vs)

Big Data is characterised by multiple dimensions. Pick any two and you are probably working in a Big Data space.

📦
Volume
The sheer amount of data. Thank you, Captain Obvious. But it's the most obvious dimension — terabytes, petabytes, exabytes.
🎲
Variety
Structured (CSV, DB), semi-structured (XML, JSON), unstructured (text, video, audio, photos). Wikipedia = text + infoboxes.
⚡
Velocity
Near-real-time requirements. Data arriving faster than you can store or process it. Twitter, sensor streams, live transactions.
🔍
Veracity
Data quality and trustworthiness. Is it the "true" data? Errors, alterations, noise, missing values. Requires data cleaning.
📈
Variability
Data flows with peaks and valleys. Hurricane season vs. off-season. System must handle both min and max load.
🕸️
Complexity
Entities, hierarchies, links, relationships. Social network graphs, supply chains, multi-source integration.
Exam Tip — Applying the Vs to Scenarios

In exams, a scenario is given and you must identify which dimensions apply AND explain WHY. 1 mark for naming the dimension, 1-2 marks for the explanation. Volume + Variety are often distractors — make sure they genuinely apply to the scenario (e.g., if only one data format is present, Variety doesn't apply).

Hardware Primer

Hardware limits define whether a problem is a Big Data problem. "Can I solve this on a laptop?" — if no, and traditional tools are too slow, it's Big Data.

General Purpose Compute (CPU)

How quickly a CPU completes a task. CPUs improve by fitting more transistors or optimising architecture. Use benchmarks, not cores/GHz to compare.

Key point: We are approaching the reticle limit (~858mm²) — CPU die sizes can't grow indefinitely. And making transistors smaller costs exponentially more (5nm = 5× more expensive than 45nm).

Specialist Compute (GPU/Quantum)

CPUs are general purpose — often not optimised for specific workloads. Hardware accelerators fill this gap:

  • GPUs — thousands of cores for parallel matrix ops (deep learning)
  • Quantum Cores — emerging paradigm for certain optimisation problems

Why this matters for Big Data

Big Data applications must minimise expensive storage accesses. Spark keeps data in RAM. Hadoop writes everything to disk (HDD). This 1,000,000× latency difference is why Spark outperforms Hadoop for iterative workloads.

Service Needs: How We Use Big Data

Big Data is defined partly by what we use it for. Three main use-case types:

Extraction / Filtering

I have a large silo of data and need to extract a subset matching some criteria.

SQL SELECT Batch Search Stream Filtering
Transformation

Apply a function to each item in my data and save the output.

Search Indexing Sentiment Analysis ML Training Fraud Detection
Aggregation

Merge (and transform) a set of data items together.

SQL JOIN Word Counting Clustering Time Window Analytics

Batch vs. Streaming

The nature of data arrival determines which processing model to use.

📦 Batch Processing
Static Data
  • Large blocks processed at once
  • Multiple blocks processed concurrently
  • Results merged at the end
  • Cares about: completion time
  • Tools: Hadoop MapReduce, Spark batch
⚡ Stream Processing
Live Data
  • Items processed individually or in micro-batches
  • Pipeline stages execute concurrently
  • Low-latency per-item processing
  • Cares about: processing latency per item
  • Tools: Apache Flink, Spark Streaming, Kafka

Core Thesis of this Course

The Big Data course is really a course about Horizontal Scaling of Compute and Storage, along with the tools that enable both.

Physical Limits of Vertical Scaling

Reticle Limit (Compute)

CPU/GPU die sizes are bounded by the photolithography reticle limit (~858mm²). Die sizes are approaching this limit. You can make transistors smaller, but cost per mm² increases exponentially (from $1 at 45nm to $5 at 5nm).

Cost Trends (Storage)

Hardware costs have been decreasing historically, but the pace has slowed dramatically for compute and storage. We can no longer rely on Moore's Law to solve Big Data problems for us.

Compute Parallelism

Definition

Parallel Computing: Solving a Big Data problem by breaking it into multiple tasks that can be solved simultaneously, using horizontally scalable resources.

Levels of Parallelism

Within a CPU Core
  • Pipelining: Split processor datapath into stages (fetch, decode, execute) — multiple instructions in-flight simultaneously
  • Superscalar: Multiple copies of ALUs — more instructions per clock cycle
  • Invisible to programmer
Across CPU Cores
  • Each core processes different instructions
  • Exposed as threads to programmers
  • Shared memory, same machine
Across Different Machines ← Focus
  • Tasks compiled and sent to remote machines with their data
  • This is horizontal scaling
  • What Hadoop, Spark, and all Big Data tools do
  • Communication over network required

Measuring Parallelism: Speed-up

The effectiveness of parallelism is measured with:

\[ S(n, p) = \frac{T_{\text{serial}}(n)}{T_{\text{parallel}}(n, p)} \]
n = input size p = number of parallel processors

We expect: 0 < Speed-up ≤ p

Linear Speed-up (ideal): S(n,p) = p — doubling processors halves time

In practice, overheads (communication, synchronisation, load imbalance) prevent linear speed-up.

Real-World Parallelism Example: Star Citizen

Problem: The Star Citizen game universe is too large for one server to simulate.

Parallel Solution: Break the game world into regions. Assign one server per region. Move players between servers as they traverse the world. This is exactly how Big Data horizontal scaling works — partition the problem, distribute the work.

Flynn's Taxonomies

A hardware classification for CPU architectures (Flynn, 1972). Classifies by instructions (single/multiple) and data streams (single/multiple).

SISD
Single Instruction, Single Data
Classic von Neumann architecture. Serial computer. One instruction, one data item at a time. Old sequential programs.
SIMD
Single Instruction, Multiple Data
Same instruction applied to many data items simultaneously. GPUs, AVX instructions. Great for matrix operations.
MISD
Multiple Instruction, Single Data
Very rare in practice. Systolic arrays. Different operations applied to the same data.
MIMD ★
Multiple Instruction, Multiple Data
Modern CPUs + Big Data Clusters. Autonomous processors running independent programs on different data. This is how Hadoop/Spark clusters work.
Remember

Big Data distributed systems are MIMD — each machine (multiple processors) runs its own code (multiple instructions) on its own data partition (multiple data). GPUs are SIMD — same kernel on thousands of data elements.

Core Ethical Concepts

Privacy

Recognised as a human right (ECHR, Human Rights Act 1998). The definition is fuzzy — is social media public or private? Identifiability is a continuum, not binary.

Informed Consent

Individuals must consent to data processing for clearly understood uses. In Big Data, future uses are often unknown at collection time. T&Cs don't count as informed consent. May be impossible or prohibitively expensive.

De-identification

Removing/masking identifying elements. But re-identification risk grows with: more variables, linking multiple datasets, power of analytics. Risks can be mitigated but not eliminated.

Research Integrity

Data must have clear provenance — sources and processing documented. Administrative data may have different quality standards. Commercial data (Twitter) has legal restrictions on reproduction.

Key Laws

UK · 1998
Data Protection Act 1998
  • Protects "personal data" — any data identifying a living individual
  • 8 principles: fair/lawful processing, purpose limitation, data minimisation, accuracy, storage limitation, rights of subjects, security, no transfer outside EEA without adequate protection
UK · 2000
Freedom of Information Act 2000
  • Expanded rights for public organisations
  • Right to view held data (for reasonable fee)
  • Right to correct inaccurate data
  • Right to prevent harmful or direct marketing use
EU · 2018
GDPR — General Data Protection Regulation
  • Personal data = info relating to identified or identifiable individual
  • 6 lawful bases for processing (consent, contract, legal obligation, vital interests, public interest, legitimate interests)
  • Data Controller must declare purpose, retention, sharing
  • Must have designated Data Protection Officer
  • Applies to EU + UK processing of EU citizens' data
Exam Tip — Ethics Questions

Ethics/legal questions are usually worth 2 marks per point: 1 mark for naming the principle (Privacy, Consent, Data Retention) + 1 mark for explaining WHY it applies to the specific scenario. Always connect to the scenario — don't just list principles generically.

Past Exam Questions

Exam 2025 Q1(a) · 3 marks
Context: Containers2You operates 80 trucks. Each truck sends a data packet every second. The company serves 300 retailers across Europe. They are considering letting retailers track goods live.
Would this change result in a Big Data problem?
[3 marks] — 1 for correct yes/no, 2 for reasons
  • Answer: NO [1 mark] — this is NOT a Big Data problem.
  • The company only needs to serve relatively small, low-frequency data to a small number of businesses (300 retailers) [1 mark].
  • The data rate is modest: 80 trucks × 1 packet/second — traditional tools can handle this [1 mark].
  • Examiner note: The key is that 300 businesses + 80 trucks is small scale. Big Data requires at least 2 dimensions (Volume, Velocity, etc.) to be genuinely problematic.
Exam 2025 Q1(b) · 6 marks
Context: Containers2You installs dashboard cameras streaming at 480p (~2MB/min video) via low-orbit satellite. Equipment quality is poor, causing periodic loss of video feeds.
Processing the dashboard camera video constitutes a big data task, why?
[6 marks] — 2 dimensions required, 1 mark per dimension name + 2 marks for explanation
  • Velocity [1 mark]: The platform needs to process images fast enough to alert drivers to road conditions [2 marks]. Near-real-time processing is required — this is a latency-critical application.
  • Veracity [1 mark]: The cameras have errors causing periodic feed loss [2 marks], meaning significant data cleaning will be needed to make the feeds usable.
  • Examiner note: Volume and Variety are NOT valid here. Data volume is modest (2MB/min × 80 trucks). Only one data format (video). Focus on the velocity requirement and the data quality issues.
Exam 2025 Q1(c) · 6 marks
Context: Management wants to use all sensor and video data from trucks to train an AI self-driving truck model.
What would be the legal and ethical implications of training such a model?
[6 marks] — 3 points expected, 2 marks per point
  • Privacy [2 marks]: Dashboard cameras will have recorded people's faces and car number-plates. Using raw footage would be an invasion of privacy — GDPR prohibits processing personal data without lawful basis.
  • Consent [2 marks]: The company did not obtain informed consent from the people captured by the cameras. They had no opportunity to consent or object.
  • Data Retention [2 marks]: EU legal requirements (GDPR) place limits on how long a company can hold personal video data. This makes future model replacement problematic as the training data may need to be deleted.
  • Other valid answers: bias in training data, security of stored video, cross-border data transfer issues.
Exam 2023 Q1(a) · 6 marks
Context: Satellite imaging company. 100 satellites (doubling in 5 years). Each active satellite sends 10MB image/second. ~20% active normally, up to 50% during hurricane season.
List the Big Data dimensions that make this a Big Data problem and discuss why.
[6 marks] — 3 dimensions, 1 mark each + 1 mark per explanation
  • Volume [1 mark]: Up to 50 satellites × 10MB/s = 500MB of images per second arriving — this is a large volume of data [1 mark].
  • Velocity [1 mark]: The use-case is real-time disaster alerting — there are strict latency requirements for processing [1 mark].
  • Variability [1 mark]: The amount of data varies over time — 20% normal vs 50% during hurricane season [1 mark]. The system must scale dynamically.
  • Veracity also accepted if argued that satellite images may have noise/errors.
Exam 2023 Q1(b) · 8 marks
Context: A hardware manufacturer offers a single mainframe to process the satellite data.
Discuss why this is not a good option given their requirements.
[8 marks] — 4 distinct points, 2 marks each
  • Scaling limit [2 marks]: Mainframes have a maximum limit to scaling (both compute and storage) — cannot grow beyond physical/reticle limits.
  • Cost [2 marks]: Mainframes are more costly than horizontally scaled solutions — cost per unit of compute is higher.
  • Growth plans [2 marks]: The company plans to double their satellites. A mainframe solution may become unfit for purpose shortly after installation.
  • Single point of failure [2 marks]: If the mainframe fails, the entire disaster alerting system goes down — catastrophic for a real-time alerting use-case.

Practice Questions

Practice Q1
A social media company stores 500TB of user posts, images, and videos. They want to analyse which posts are likely to go viral within 30 seconds of posting to serve them to more users. Identify the Big Data dimensions and explain which processing model (batch/stream) they need.
Dimensions: Volume (500TB of content), Velocity (30-second latency requirement), Variety (text, images, videos = multiple formats).

Processing model: Stream processing — the 30-second latency requirement means batch processing (which processes large blocks at once) is too slow. Each post must be analysed in real-time as it arrives in a streaming pipeline.

Note: Variability may also apply if viral content has unpredictable surges (e.g., breaking news events).
Practice Q2
A company currently runs its analytics on a powerful single server (vertical scaling). Give 3 reasons why they should consider horizontal scaling instead, linking each to a specific Big Data requirement.
1. Physical limits: Vertical scaling hits the reticle limit — cannot buy a bigger machine indefinitely. Horizontal scaling adds more commodity machines.

2. Fault tolerance: A single server is a single point of failure. Horizontal scaling across multiple machines means one failure doesn't stop the system.

3. Cost efficiency: Commodity hardware in a cluster is cheaper per unit of compute than high-end mainframe hardware. Horizontal scaling scales cost linearly rather than exponentially.
Practice Q3
A hospital wants to train a machine learning model on patient records from the last 20 years (10 million patients) to predict sepsis risk. Identify 3 ethical/legal concerns.
1. Informed Consent: Patients from 20 years ago did not consent to their data being used for AI training when they were treated. GDPR requires explicit consent for this use.

2. Data Retention: GDPR limits how long personal medical data can be held. 20-year-old records may violate storage limitation principles.

3. De-identification risk: Even if data is anonymised, combining age, diagnosis, treatment, and hospital with external datasets can re-identify individuals. Risk cannot be fully eliminated.
Practice Q4 — Calculation
A serial program takes 400 seconds. A parallel version on 10 machines takes 60 seconds. (a) What is the speed-up? (b) Is this linear? (c) What does the remaining overhead likely come from?
(a) S(n,p) = 400/60 ≈ 6.67

(b) Not linear. Linear speed-up would be S = 10. We achieved 6.67, which is 66.7% efficiency.

(c) Overhead likely from: network communication latency between machines, load imbalance (some machines finish before others), synchronisation points where machines must wait, and the non-parallelisable serial fraction of code (Amdahl's Law).
