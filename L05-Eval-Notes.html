Evaluation Methodology

IR H/M Course · Sean MacAvaney · 2026

Learning Objectives

  • Explain why IR systems need evaluation and the Cranfield paradigm

  • Understand TREC test collections, pooling, and track types
  • Interpret and construct recall-precision curves with interpolation

  • Distinguish offline vs online evaluation methods (A/B testing, interleaving)

Why Evaluate?

💰 Economic

Buyers want to know system effectiveness before purchasing.

🔬 Scientific

Researchers need to show their method is better than alternatives.

✅ Verification

System builders must verify their system performs as intended.

Test Collections

A test collection consists of: (1) a set of documents, (2) a set of queries (topics), (3) relevance assessments (qrels) — ground-truth judgments of which documents are relevant for each query. The TREC (Text Retrieval Conference) standard, started in 1992, provides such collections.

The Cranfield Paradigm

Cranfield Paradigm

The gold-standard methodology for IR evaluation, originating from Cyril Cleverdon's Cranfield experiments (1960s). A reusable, system-independent, offline evaluation framework built on four components:

Four Components

  • Test Collection — a static set of documents (the corpus)
  • Queries (Topics) — a representative sample of information needs, often with a title, description, and narrative
  • Relevance Judgements (qrels) — ground-truth labels: for each (query, document) pair, is the document relevant? Usually binary (relevant/not), sometimes graded.
  • Evaluation Measure — a metric such as MAP, NDCG, or MRR computed from the system output vs qrels

Why Cranfield Works

  • Reusability: Many systems can be compared on the same collection without re-judging
  • Reproducibility: Offline evaluation — no need for live users
  • Cost-effective: Judgements are done once, reused many times
  • Limitations: Static snapshots of user needs; relevance is subjective; pooled judgements may miss unjudged relevant docs

Key Assumption

The Cranfield paradigm assumes relevance is binary (or graded) and stable — i.e., a document's relevance to a query does not change between systems. This is a simplification: in practice relevance is subjective and context-dependent.

Confusion Matrix for IR

The Four Cells

Every document in the collection falls into one of four categories with respect to a query:

Retrieved Not Retrieved
Relevant True Positive (TP) — correctly retrieved relevant docs False Negative (FN) — relevant but missed
Not Relevant False Positive (FP) — irrelevant but retrieved True Negative (TN) — correctly not retrieved

Example

Collection = 1000 docs. Query has 20 relevant docs. System retrieves 50 docs, of which 12 are relevant.
TP = 12  |  FP = 38  |  FN = 8  |  TN = 942
Precision = 12/50 = 0.24  |  Recall = 12/20 = 0.60

Why TN is usually ignored in IR

The number of non-relevant, non-retrieved documents (TN) is typically enormous (millions of web pages). Including TN inflates accuracy to near 1.0 for any reasonable system, making it useless. IR metrics focus on TP, FP, FN instead.

Precision, Recall & F-Measure

Precision and Recall
\[ \text{Precision} = \frac{|\text{Relevant} \cap \text{Retrieved}|}{|\text{Retrieved}|} = \frac{\text{TP}}{\text{TP} + \text{FP}} \]
\[ \text{Recall} = \frac{|\text{Relevant} \cap \text{Retrieved}|}{|\text{Relevant}|} = \frac{\text{TP}}{\text{TP} + \text{FN}} \]
Practice Example

A system retrieves 8 documents for a query. The collection contains 10 relevant documents. 5 of the retrieved documents are relevant. Compute Precision and Recall.

✅ Solved Example

|Retrieved| = 8, |Relevant| = 10, |Rel ∩ Ret| = 5
Precision = 5/8 = 0.625 (62.5% of retrieved are relevant)
Recall = 5/10 = 0.500 (50% of relevant are retrieved)
The system is reasonably precise but misses half the relevant documents.

Precision-Recall Trade-off

There is an inherent trade-off between precision and recall:

  • Retrieving more documents increases recall (fewer FN) but lowers precision (more FP).
  • Being more selective raises precision but reduces recall.
  • Systems can be tuned to favour one over the other depending on the application (e.g., legal search favours recall; spam filtering favours precision).
F-Measure (van Rijsbergen)
\[ F_1 = \frac{2 \cdot \text{Precision} \cdot \text{Recall}}{\text{Precision} + \text{Recall}} \]
\[ F_\beta = \frac{(1+\beta^2) \cdot \text{Precision} \cdot \text{Recall}}{\beta^2 \cdot \text{Precision} + \text{Recall}} \]

β controls balance: β=1 balances P and R equally; β<1 favours Precision; β>1 favours Recall. Harmonic mean is used because it penalises extreme imbalance — a system cannot score well with P=0 or R=0.

Practice Example

System A: P=0.8, R=0.3. System B: P=0.5, R=0.5. Compute F₁ for both and determine which is better.

✅ Solved Example

F₁(A) = 2×0.8×0.3/(0.8+0.3) = 0.48/1.1 = 0.436
F₁(B) = 2×0.5×0.5/(0.5+0.5) = 0.5/1.0 = 0.500
System B is better by F₁ despite lower precision — its balanced P/R gives a better harmonic mean.

Precision at Rank k (P@k) and Recall at Rank k (R@k)
\[ P@k = \frac{|\text{Relevant documents in top-}k \text{ results}|}{k} \]
\[ R@k = \frac{|\text{Relevant documents in top-}k \text{ results}|}{|\text{Relevant}|} \]

P@k: useful for web search — users typically only see the first page. R@k: what fraction of all relevant docs are in the top k? Commonly used P@5, P@10, P@20. R@k useful for understanding coverage at a given cut-off.

Practice Example

Ranked list: [R, N, R, N, R, N, R, N, N, R] (R=relevant, N=non-relevant). Total relevant in collection = 8. Compute P@3, P@5, P@10, R@5, R@10.

✅ Solved Example

P@3 = 2/3 ≈ 0.667 (ranks 1,3 are relevant out of top 3)
P@5 = 3/5 = 0.600 (ranks 1,3,5 are relevant)
P@10 = 5/10 = 0.500 (ranks 1,3,5,7,10 are relevant)
R@5 = 3/8 = 0.375 (3 of 8 relevant docs in top 5)
R@10 = 5/8 = 0.625 (5 of 8 relevant docs in top 10)

R-Precision
\[ \text{R-Precision} = P@R \]

Where R = total number of relevant documents for the query. R-Precision is the precision at the rank equal to the number of relevant documents. It is equivalent to recall at that rank (P@R = R@R when R docs are retrieved). Useful as a single-number summary when you know the total relevant count.

Example

Query has 6 relevant docs. Ranked list: [R, N, R, N, R, N, N, R, N, N]
R=6, so look at position 6. Documents at ranks 1–6: R, N, R, N, R, N → 3 relevant.
R-Precision = 3/6 = 0.500

Average Precision, MAP & MRR

Average Precision (AP)
\[ \text{AP} = \frac{1}{|R|} \sum_{k: d_k \text{ is relevant}} P@k \]

Average the precision values at each rank position where a relevant document is retrieved. |R| = total number of relevant documents (in the whole collection, not just retrieved). Documents not retrieved contribute P=0.

Practice Example

6 total relevant documents in collection. Ranked list: [R, N, N, R, R, N, N, R, N, N]. Compute AP.

✅ Solved Example

Relevant documents at ranks: 1, 4, 5, 8.
P@1=1/1=1.0, P@4=2/4=0.5, P@5=3/5=0.6, P@8=4/8=0.5
AP = (1.0+0.5+0.6+0.5)/6 = 2.6/6 = 0.433
Note: divided by 6 (total relevant in collection), not 4 (retrieved relevant). Documents not retrieved get P=0.

Why AP and not just P@k?

AP rewards systems that rank relevant documents early. A system that retrieves the same set of relevant documents but puts them all at the bottom scores lower AP than one that places them at the top. P@k is blind to the ranking within k results and ignores what happens beyond k.

Mean Average Precision (MAP)
\[ \text{MAP} = \frac{1}{|Q|} \sum_{q \in Q} \text{AP}(q) \]

Average AP over all queries Q. The most widely used single-number IR evaluation metric for multi-document queries. Sensitive to early placement of relevant documents across all queries.

Practice Example

3 queries with APs: AP(q1)=0.60, AP(q2)=0.35, AP(q3)=0.80. Compute MAP.

✅ Solved Example

MAP = (0.60 + 0.35 + 0.80) / 3 = 1.75/3 = 0.583

Mean Reciprocal Rank (MRR)
\[ \text{MRR} = \frac{1}{|Q|} \sum_{q \in Q} \frac{1}{\text{rank}_q} \]

rank_q = rank of the first relevant document for query q. Used when only one relevant document matters (navigational search, QA). If no relevant document is found, the reciprocal rank is 0.

Practice Example

Q1: first relevant at rank 2. Q2: first relevant at rank 5. Q3: no relevant found (rank = ∞). Compute MRR.

✅ Solved Example

RR(Q1) = 1/2 = 0.5
RR(Q2) = 1/5 = 0.2
RR(Q3) = 0 (no relevant document found)
MRR = (0.5+0.2+0)/3 = 0.233

Discounted Cumulative Gain (DCG) & NDCG

Why Graded Relevance?

Binary relevance (relevant/not) is too coarse. A document can be highly relevant, partially relevant, or not relevant. NDCG uses graded relevance scores (e.g., 0–3 or 0–4) and applies a logarithmic discount to reward ranking high-quality results early.

Discounted Cumulative Gain (DCG)
\[ \text{DCG}_k = \sum_{i=1}^{k} \frac{\text{rel}_i}{\log_2(i+1)} \]

rel_i = relevance grade of the document at rank i. The logarithmic discount means position 1 contributes full gain (log₂2 = 1), position 2 contributes less (log₂3 ≈ 0.63 of gain), etc.

Ideal DCG and Normalised DCG
\[ \text{IDCG}_k = \text{DCG of the ideal (perfect) ranking at rank } k \]
\[ \text{NDCG}_k = \frac{\text{DCG}_k}{\text{IDCG}_k} \]

IDCG = the DCG you would get if you sorted all documents by relevance (best first). NDCG normalises to [0,1]. NDCG=1 means perfect ranking. The standard metric for web search evaluation (TREC, NIST, commercial search).

Practice Example

5 ranked documents with graded relevance [3, 2, 3, 0, 1]. Compute DCG@5. The ideal ranking is [3,3,2,1,0]. Compute NDCG@5.

✅ Solved Example

DCG@5:
rank 1: 3/log₂(2) = 3/1 = 3.000
rank 2: 2/log₂(3) = 2/1.585 = 1.262
rank 3: 3/log₂(4) = 3/2 = 1.500
rank 4: 0/log₂(5) = 0
rank 5: 1/log₂(6) = 1/2.585 = 0.387
DCG@5 = 3.000+1.262+1.500+0+0.387 = 6.149

Ideal ranking [3,3,2,1,0]:
IDCG@5 = 3/1 + 3/1.585 + 2/2 + 1/2.322 + 0 = 3+1.893+1+0.431 = 6.324
NDCG@5 = 6.149/6.324 = 0.972

Two Key Assumptions of NDCG

  • Highly relevant documents are more valuable — captured by the graded relevance score (rel_i) in the numerator.
  • Lower-ranked documents are less useful — users are less likely to examine them. Captured by the log₂(i+1) denominator discount.

Alternative DCG formula

Some implementations use: \(\text{DCG}_k = \sum_{i=1}^{k} \frac{2^{\text{rel}_i}-1}{\log_2(i+1)}\). This variant emphasises highly relevant documents even more (exponential numerator). Check which formula your exam/course uses.

Precision-Recall Curves & Interpolation

What is a P-R Curve?

As you retrieve more documents (expanding the result set), recall increases and precision generally decreases. Plotting precision vs recall at each rank produces a P-R curve. The curve is used to compare systems across all operating points.

Step-by-Step Construction

Ranked list: [R, N, R, R, N, R]. Total relevant = 6.
After rank 1: P=1/1=1.0, R=1/6=0.167
After rank 2: P=1/2=0.5, R=1/6=0.167
After rank 3: P=2/3=0.667, R=2/6=0.333
After rank 4: P=3/4=0.75, R=3/6=0.500
After rank 5: P=3/5=0.6, R=3/6=0.500
After rank 6: P=4/6=0.667, R=4/6=0.667
Plot these (R, P) pairs → the P-R curve.

Interpolated Precision at Standard Recall Levels
\[ P(r) = \max_{r' \geq r} P(r') \]

Precision at recall level r is defined as the maximum precision observed at any recall ≥ r. This "right-pessimistic" interpolation creates a step-function that allows averaging across queries at standard 11-point recall levels (0.0, 0.1, 0.2, …, 1.0).

Why Interpolate?

Different queries achieve recall at different rank positions, so raw P-R points don't align. By interpolating to standard recall levels, you can average across queries and compare systems at the same recall levels.

Reading a P-R Curve

  • A curve that is higher and to the right is better (more precision at each recall level).
  • The area under the P-R curve (AUC-PR) approximates MAP.
  • A steep drop in precision as recall increases indicates the system has few relevant documents ranked early.
  • 11-point average precision = average of interpolated precision at recall 0.0, 0.1, …, 1.0 — an older but still-used summary statistic.

TREC Methodology

TREC — Text REtrieval Conference

Organised by NIST (USA) since 1992. Provides shared tasks, document collections, and relevance judgements (qrels) to enable fair, reproducible comparisons of IR systems. The global standard for IR evaluation infrastructure.

TREC Test Collection Components

  • Documents — large static corpus (news articles, web snapshots, etc.)
  • Topics (queries) — structured with Title (short query), Description (1–2 sentences), Narrative (detailed relevance criteria)
  • Qrels — relevance judgements: for each (topic, doc) pair, a relevance grade (often binary 0/1, sometimes graded 0–3)
  • Submissions — participating teams submit ranked result lists (run files)

TREC Pooling Technique

  • Exhaustive relevance assessment of all documents is impossible for large collections
  • Pooling: take the top-k (e.g., 100) results from each participating system and merge into a pool
  • Human assessors judge only the documents in the pool
  • Unjudged documents are assumed non-relevant — creates a depth-k pool
  • Works well for systems submitted to TREC; may underestimate recall for novel systems

TREC Track Types

Ad Hoc

New queries against a static collection. The classic TREC track: judges submit a query, receive ranked results.

Filtering

Classifying streaming documents as relevant/not relevant to a standing query profile. Online binary decision.

Question Answering (QA)

Return an exact answer string, not a document. Evaluated with exact/partial string match, MRR.

Web Track

Navigational + informational queries on ClueWeb / Common Crawl. Uses NDCG@k, ERR.

Genomics / Legal

Domain-specific tracks. Legal discovery requires very high recall; uses recall-focused metrics.

Deep Learning Track

MS MARCO-based; large-scale passage/document retrieval. Graded relevance, NDCG@10.

Online Evaluation

Offline vs Online Evaluation

Offline (Cranfield)

  • Static test collection + qrels
  • Cheap, reproducible, no live users needed
  • May not reflect real user behaviour
  • Metrics: MAP, NDCG, MRR

Online

  • Uses real users and live traffic
  • Reflects actual user satisfaction
  • Expensive, irreversible, ethical concerns
  • Metrics: CTR, session length, conversion rate

A/B Testing

Randomly split users into two groups: Group A sees the control system, Group B sees the new system. Measure engagement metrics (click-through rate CTR, time-to-click, session depth, conversion).

Click-Through Rate (CTR)

\[ \text{CTR} = \frac{\text{number of clicks on result}}{\text{number of impressions}} \]

A higher CTR on relevant results suggests better ranking. Used at scale by commercial search engines.

Limitations

Position bias: users click rank 1 more regardless of relevance. Clicks != relevance (e.g., clickbait). Requires large traffic to detect small differences.

Interleaving

A more sensitive online method than A/B testing. Instead of showing one system to each group, interleave results from both systems into a single ranked list shown to all users.

  • Team Draft Interleaving: alternately pick top documents from each system's ranking to build a merged list
  • Infer which system wins based on which system's documents receive more clicks
  • More statistically efficient than A/B: same user sees both systems simultaneously, reducing variance
  • Used by Microsoft Bing for sensitivity at small scale

Implicit Feedback Signals

Clicks

Which results the user clicks on. Noisy signal — affected by position bias and snippet quality.

Dwell Time

Time spent on a clicked page. Long dwell time often indicates relevance; short dwell = "pogo-sticking" (quick back-click).

Eye-Tracking

In lab studies, eye-tracking shows where users look. Reveals attention patterns and the "golden triangle" of user focus on top results.

Query Reformulation

When users rephrase queries after seeing results, it signals dissatisfaction with the first attempt.

Bookmarks / Saves

Strong positive signal; users explicitly saved the result for later use.

Session Length

Short sessions can mean either great success (found it fast) or failure (gave up). Context-dependent.

Statistical Significance Testing

Why Significance Testing?

If System B scores MAP=0.45 and System A scores MAP=0.40, is B actually better, or could this difference be due to chance (random variation across queries)? Statistical significance testing answers this question.

  • Null hypothesis (H₀): no difference between systems (mean difference = 0)
  • We compute a test statistic and p-value from per-query metric differences
  • If p < α (usually 0.05), we reject H₀ and conclude the difference is statistically significant
  • More queries = higher statistical power = easier to detect small differences

Paired t-Test

Used when per-query metric differences are approximately normally distributed. "Paired" because we compare the same query on both systems.

  • Compute d_i = metric_B(q_i) − metric_A(q_i) for each query q_i
  • t-statistic: \( t = \frac{\bar{d}}{s_d / \sqrt{n}} \) where \(\bar{d}\) = mean difference, s_d = std dev of differences, n = number of queries
  • Look up t in t-distribution with n−1 degrees of freedom

Example

System A avg MAP = 41.1%, System B avg MAP = 62.5%. t-test gives t=2.33, p=0.02 < 0.05 → B is significantly better than A at α=0.05.

Wilcoxon Signed-Rank Test

A non-parametric alternative to the paired t-test. Does not assume normality of differences. More robust for small n or skewed distributions.

  • Ranks the absolute differences |d_i| across queries
  • Sums the ranks for positive vs negative differences
  • W-statistic compared to critical values
  • Often preferred in IR because per-query AP differences are not always normally distributed

Which to use?

Wilcoxon is safer for IR — AP values are often skewed (many queries with AP near 0). Bootstrap or permutation tests are also used. Always report the test used alongside p-values.

Practical Guidelines

  • Minimum ~30 queries recommended for reasonable power; TREC tracks typically use 50
  • Multiple comparisons problem: testing many pairs inflates Type I error — use Bonferroni correction
  • Statistical significance ≠ practical significance: a tiny MAP improvement may be statistically significant with 1000 queries but meaningless in practice
  • Report effect size (e.g., relative improvement %) alongside p-values

User Studies & Task-Completion Evaluation

Lab-Based User Studies

Participants given specific information tasks; researchers observe search behaviour and measure outcomes. More ecologically valid than offline evaluation but costly and small-scale.

Task Completion Rate

Proportion of users who successfully complete the assigned information task. Direct measure of system utility.

Time on Task

How long users take to find what they need. Lower time = more efficient system (but context-dependent).

Number of Queries

How many query reformulations the user needed. Fewer = better — system found the answer sooner.

User Satisfaction Surveys

Post-task questionnaires (e.g., Likert scale ratings) capture subjective satisfaction not visible in log data.

Evaluation Paradigm Comparison

Offline (Cranfield): cheap, reproducible, scalable, but may not reflect real user needs.
Online (A/B, interleaving): reflects real users, but expensive, risky, ethically complex.
User studies: rich behavioural data but small n, expensive, not scalable.
Best practice: use offline evaluation for rapid iteration, online for final validation.

Python: Evaluation Metrics

import numpy as np

def average_precision(ranked_list, total_relevant):
    ap, n_relevant = 0.0, 0
    for i, rel in enumerate(ranked_list, 1):
        if rel:
            n_relevant += 1
            ap += n_relevant / i  # P@rank
    return ap / total_relevant if total_relevant > 0 else 0

def dcg(ranked_rels, k):
    result = 0.0
    for i, rel in enumerate(ranked_rels[:k], 1):
        result += rel / np.log2(i + 1)
    return result

def ndcg(ranked_rels, k):
    actual = dcg(ranked_rels, k)
    ideal = dcg(sorted(ranked_rels, reverse=True), k)
    return actual / ideal if ideal > 0 else 0

def mrr(first_relevant_ranks):
    # list of rank positions of first relevant doc per query (0 = not found)
    return np.mean([1/r if r > 0 else 0 for r in first_relevant_ranks])

# Example
ranked = [1,0,0,1,1,0,0,1,0,0]  # binary relevance
graded = [3,2,3,0,1]
print(f"AP  = {average_precision(ranked, 6):.4f}")
print(f"DCG@5 = {dcg(graded, 5):.4f}")
print(f"NDCG@5 = {ndcg(graded, 5):.4f}")
print(f"MRR = {mrr([1, 3, 5]):.4f}")  # first relevant at ranks 1,3,5

Summary

Cranfield Paradigm

Test collection (docs) + topics (queries) + qrels (relevance judgements) + evaluation measure. The standard offline evaluation framework. Reusable: many systems compared without re-judging.

Confusion Matrix

TP (relevant+retrieved), FP (irrelevant+retrieved), FN (relevant+not retrieved), TN (irrelevant+not retrieved). TN ignored in IR because it inflates accuracy. Precision = TP/(TP+FP). Recall = TP/(TP+FN).

P & R, F1

Precision = fraction of retrieved that are relevant. Recall = fraction of relevant that are retrieved. F1 = harmonic mean. Trade-off: more retrieval → higher R but lower P.

AP & MAP

Average Precision averages P at relevant ranks for one query, divided by total relevant. MAP averages AP over all queries. Rewards early placement of relevant docs. Most widely used IR metric.

NDCG

Uses graded relevance. Discounts gains at lower ranks logarithmically. Normalised to [0,1] via IDCG. Standard for web search evaluation. Two assumptions: graded value + position discount.

MRR & R-Precision

MRR = mean of 1/rank of first relevant doc. Best for navigational/QA. R-Precision = P@R = precision when exactly R docs are retrieved.

TREC & Pooling

TREC (since 1992) provides standard IR infrastructure. Pooling: judge top-k from all systems, assume unjudged = not relevant. Avoids judging billions of documents.

Significance Testing

Paired t-test (normal differences) or Wilcoxon signed-rank (non-parametric). Per-query differences tested against H₀: no difference. p < 0.05 → reject H₀. Need sufficient queries (≥30).

Online Evaluation

A/B testing: split users between systems, measure CTR/satisfaction. Interleaving: merge ranked lists, infer winner from clicks — more efficient. Implicit feedback: clicks, dwell time, eye-tracking.

H/M[10 marks]
Q1. (a) Define Average Precision and explain why it is preferred over P@k for evaluating IR systems. [4] (b) For the following ranked list with 10 total relevant documents in the collection, compute AP: [R, N, R, N, N, R, N, N, R, N]. [6]
(a) AP = average P at ranks where relevant docs retrieved. Preferred over P@k because: (1) considers the full ranked list, not just a cutoff; (2) rewards systems that rank relevant docs higher; (3) accounts for all relevant docs (penalises missing ones); (4) single number that captures both P and R aspects; (5) more informative for comparing systems. [4] (b) Relevant at ranks 1, 3, 6, 9. P@1=1/1=1.0. P@3=2/3=0.667. P@6=3/6=0.500. P@9=4/9=0.444. AP = (1.0+0.667+0.500+0.444)/10 = 2.611/10 = 0.261. [6 marks: 1 for each P@k (4), 1 for sum, 1 for dividing by 10 not 4]
H[8 marks]
Q2. Explain Normalised Discounted Cumulative Gain (NDCG). What are its two key assumptions and why does it use a logarithmic discount? Compute NDCG@3 for ranked relevance [2, 3, 1] with ideal [3, 2, 1].
NDCG uses graded relevance; discounts gains at lower ranks; normalised by ideal [2]. Two assumptions: (1) highly relevant docs more useful than marginally relevant [1]; (2) lower-ranked docs are less useful (less likely to be examined) [1]. Log discount: gradual, realistic model of diminishing attention [1]. DCG@3: 2/log₂2 + 3/log₂3 + 1/log₂4 = 2+1.893+0.5 = 4.393. IDCG@3: 3/1 + 2/1.585 + 1/2 = 3+1.262+0.5 = 4.762. NDCG@3 = 4.393/4.762 = 0.923 [3 marks for correct computation]
H/M[10 marks]
Q3. Describe the Cranfield evaluation paradigm. What are its four components? What is the TREC pooling technique and why is it necessary? What is one key limitation of the Cranfield approach?
Cranfield paradigm: reusable offline IR evaluation framework (from Cleverdon's 1960s experiments). [1] Four components: (1) test collection (document corpus) [1]; (2) topics/queries — structured information needs [1]; (3) relevance judgements/qrels — ground truth relevance labels for (query, doc) pairs [1]; (4) evaluation measure — metric computed from system output vs qrels (e.g., MAP, NDCG) [1]. Pooling: since exhaustive judging of all documents is impossible for large collections, TREC pools the top-k results from all submitted systems, and human assessors judge only the merged pool. Unjudged docs assumed not relevant. [2 marks] Pooling allows practical judging at scale while maintaining fairness across participants. [1] Limitation (any one of): relevance is subjective/context-dependent; static snapshot may not reflect evolving information needs; unjudged docs penalise novel systems; binary/graded relevance is an oversimplification. [2]
H[8 marks]
Q4. Compare offline and online evaluation of IR systems. What is A/B testing and what is interleaving? Why is interleaving considered more statistically efficient? What implicit feedback signals can be used for online evaluation?
Offline: static test collection + qrels; cheap, reproducible, no live users; may not reflect real behaviour [1]. Online: live users, real traffic; reflects actual satisfaction; expensive, ethically complex [1]. A/B testing: randomly split users into control (A) and treatment (B) groups; measure engagement metrics (CTR, session length, conversion) between groups [2]. Interleaving: both systems' results merged into one ranked list shown to all users; winner inferred from which system's documents are clicked more [2]. Interleaving is more efficient because both systems are shown simultaneously to the same users, eliminating user-cohort variance — requires less traffic for equivalent statistical power [1]. Implicit signals: clicks (noisy but abundant), dwell time (long = satisfied, short = pogo-sticking), eye-tracking (attention patterns in lab), query reformulations (dissatisfaction signal), session depth [1]
H/M[6 marks]
Q5. Explain statistical significance testing in IR evaluation. Why is the Wilcoxon test preferred over the paired t-test for IR metrics? What is the minimum recommended number of queries and why?
Significance testing determines whether a difference in MAP/NDCG between two systems is due to the system or random variation across queries [1]. H₀: no difference; if p < 0.05 we conclude the difference is significant [1]. Wilcoxon signed-rank is preferred because: it is non-parametric (no normality assumption); per-query AP values are often skewed (many near 0), violating t-test assumptions; Wilcoxon ranks differences rather than averaging them, making it more robust to outliers [2]. Minimum ~30 queries: statistical tests have low power with few queries — small n means high variance in the test statistic, making it hard to detect genuine differences. TREC uses 50 topics for this reason [2].
Flashcards
Precision
|Rel∩Ret|/|Ret|. Fraction of retrieved documents that are relevant. High precision = fewer false positives.
Recall
|Rel∩Ret|/|Rel|. Fraction of relevant documents that are retrieved. High recall = fewer false negatives.
F₁ Measure
Harmonic mean of P and R: 2PR/(P+R). Penalises extreme imbalance between P and R. NOT arithmetic mean.
MAP
Mean Average Precision: average AP over all queries. Most widely used IR metric. Rewards early placement of relevant docs.
NDCG
Normalised DCG: uses graded relevance + log discount. NDCG = DCG/IDCG. Range [0,1]. Standard for web search eval.
MRR
Mean Reciprocal Rank: average of 1/rank of first relevant doc across queries. Best for navigational/QA tasks.
TREC
Text Retrieval Conference (since 1992). Standard IR evaluation infrastructure: collections, topics, qrels, shared tasks.
Pooling
TREC technique: take top-k from multiple systems, judge merged pool. Avoids judging billions of docs. Unjudged = not relevant.
Cranfield Paradigm
4 components: test collection + queries + qrels + evaluation measure. Offline, reusable, reproducible. From Cleverdon 1960s.
R-Precision
P@R where R = number of relevant docs. Precision when exactly R documents are retrieved. Equals Recall@R.
Interpolated P-R
P(r) = max P(r') for r' ≥ r. Maximum future precision at or beyond recall r. Allows averaging P-R curves across queries.
A/B Testing
Online eval: split users into control/treatment groups. Measure CTR, session length. Requires large traffic for statistical power.
Interleaving
Online eval: merge results from two systems, infer winner from clicks. More statistically efficient than A/B testing.
Wilcoxon Test
Non-parametric significance test. No normality assumption. Better than t-test for skewed IR metrics. Ranks absolute differences.
