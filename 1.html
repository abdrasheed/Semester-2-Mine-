Why Do Computers Need to Work with Text?

▼

The Core Argument

Humans communicate primarily through language. Language is most conveniently stored and transmitted as text. Therefore, text is the natural interface between humans and computers.

Scale of Text Data (Every Minute)

  • ~200 million emails sent
  • ~6 million Google searches
  • Billions of web pages indexed

Text data grows continuously — we must automate its processing.

Used pattern matching on words to simulate a therapist. When it saw "I need X", it responded "What would it mean to you if you got X?"

Despite simplicity, users believed it understood them — highlighting how humans anthropomorphise language systems.

Characters, ASCII & Unicode

▼

Before working with words, text must be stored as numbers. Every character has a numeric code.

ASCII

  • 128 possible characters (1 byte)
  • A–Z, a–z, 0–9, standard punctuation
  • Control characters (newline, tab)
  • Cannot represent: á, λ, 😀, Chinese characters

Unicode (UTF-8 encoding)

  • Variable-byte encoding (2–4 bytes)
  • Encodes alphabets of most languages
  • Emojis, math symbols, CJK characters
  • Regularly updated (v16.0 in Sept 2024)
  • Default on Mac/Linux; not default on Windows!

Character N-grams

Individual characters carry little meaning. Character n-grams (sequences of n consecutive characters) are more specific:

nNameExample from "IRN BRU"
1UnigramI, R, N,  , B, R, U
2BigramIR, RN, N ,  B, BR, RU
3TrigramIRN, RN , N B,  BR, BRU
 
def char_ngrams(text, n):
    return [text[i:i+n] for i in range(len(text) - n + 1)]

print(char_ngrams("IRN BRU", 2))
# ['IR', 'RN', 'N ', ' B', 'BR', 'RU']

Strengths of Char N-grams

  • More specific than single characters
  • Easy to implement
  • Language-agnostic (no word boundaries needed)
  • Useful for language detection

Weaknesses of Char N-grams

  • Small n → not specific enough
  • Large n → very rare n-grams
  • Same n-gram, different meanings:
    "ong" in "wrong" and "strong"

Tokenization

▼

Definition

Tokenization is the process of splitting a section of text into individual tokens. A token (or term) is a meaningful sequence of characters — not exactly a word.

📝
Token ≠ Word

"don't" is often split into two tokens: do + n't. Punctuation, numbers, and some whitespace can also be tokens.

Tokenization Approaches

Approach 1: Split on whitespace

sentence = "John's father didn't have £100."
tokens = sentence.split()
# ["John's", "father", "didn't", "have", "£100."]
# Problem: punctuation attached to words

Approach 2: Split on whitespace + punctuation

import re
tokens = re.split(r'[\s,\.;!@#$%\'"£]+', sentence)
# ["John", "s", "father", "didn", "t", "have", "100"]
# Problem: "didn't" becomes ["didn", "t"] — loses meaning
# "£100" loses the currency symbol

Ideal Tokenization (requires hand-crafted rules)

# Desired output:
# ["John", "'s", "father", "did", "n't", "have", "£", "100", "."]
# Rules needed:
# - possessives: John's → John + 's
# - contractions: didn't → did + n't
# - currency: £100 → £ + 100
# - keep final period separate

Using spaCy (used in labs)

import spacy
nlp = spacy.load("en_core_web_sm")
doc = nlp("John's father didn't have £100.")
tokens = [token.text for token in doc]
print(tokens)
# ["John", "'s", "father", "did", "n't", "have", "£", "100", "."]

# Access token attributes:
for token in doc:
    print(token.text, token.lemma_, token.pos_, token.is_stop)

Word N-grams

Single words lose context. Word n-grams capture phrases:

TypeExample from "It's a Scottish drink"
UnigramsIt's, a, Scottish, drink
Bigrams (n=2)"It's a", "a Scottish", "Scottish drink"
Trigrams (n=3)"It's a Scottish", "a Scottish drink"
 
def word_ngrams(tokens, n):
    return [tuple(tokens[i:i+n]) for i in range(len(tokens) - n + 1)]

tokens = ["It's", "a", "Scottish", "drink"]
print(word_ngrams(tokens, 2))
# [("It's", 'a'), ('a', 'Scottish'), ('Scottish', 'drink')]
💡
Scale consideration

English has ~7 million words (Wiktionary). Bigrams could number in the tens of billions. This makes word n-gram models computationally expensive for large n.

Stopwords

Common words like "the", "is", "a", "it" carry little standalone meaning and can overwhelm similarity computations. Stopword filtering removes them.

import spacy
nlp = spacy.load("en_core_web_sm")
doc = nlp("It's a Scottish drink and it's banned in some countries")

# Filter stopwords
meaningful = [token.text for token in doc if not token.is_stop]
print(meaningful)
# ['Scottish', 'drink', 'banned', 'countries']
⚠️
Stopword Caveat

Stopword lists are not definitive. Some meaningful phrases are made of stopwords: "The Who" (band), "to be or not to be". Removing stopwords loses these. Fun fact: the first standardised stopword list was proposed by Keith Van Rijsbergen (~1975) — who founded the Information Retrieval group at the University of Glasgow!

Step 3: Case Normalisation

"IRN" and "irn" should match. Convert to lowercase:

Caveat: capitalization sometimes carries meaning (proper nouns, acronyms).

Full Pipeline Example with spaCy

import spacy

nlp = spacy.load("en_core_web_sm")

def preprocess(text):
    doc = nlp(text.lower())          # tokenize + lowercase
    tokens = []
    for token in doc:
        if token.is_stop:  continue   # remove stopwords
        if token.is_punct: continue   # remove punctuation
        tokens.append(token.lemma_)   # use lemma
    return tokens

text = "Anyone tried Irn Bru? It's a Scottish drink!"
print(preprocess(text))
# ['try', 'irn', 'bru', 'scottish', 'drink']

Words & Corpora — Jurafsky & Martin Ch. 2

▼

Word Type vs. Word Instance

Word Type (vocabulary item)
A distinct/unique word form. Vocabulary size = |V|
Word Instance (token count)
Total running words in a corpus = N
$|V| = \text{types}, \quad N = \text{instances}$

Example: "the cat sat on the mat" → N=6 instances, |V|=5 types ("the" repeats)

Corpus Examples (J&M Fig 2.1)

CorpusTypes |V|Instances N
Shakespeare31K884K
Brown corpus38K1M
COCA2M440M
Google n-grams13M1 trillion

Larger corpora → more types. Vocabulary grows without bound!

Herdan's Law / Heaps' Law

The relationship between vocabulary size and corpus size follows a power law:

$$|V| = k \cdot N^b \quad \text{where } 0 < b < 1, \; k > 0$$
  • Typical values: $b \approx 0.44$ to $0.56$
  • Vocabulary grows roughly as the square root of corpus length
  • Two regimes: early growth (function + content words) → later slower growth (content words only)
🔑
Key Implication for NLP Models

Since vocabulary grows without bound, any NLP model will encounter out-of-vocabulary (OOV) words — words it has never seen. This motivates subword tokenisation (BPE) rather than whole-word tokenisation in modern LLMs.

Why Subword Tokenization? (J&M §2.4)

Modern LLMs (GPT, BERT) use Byte-Pair Encoding (BPE) to split text into subwords:

# BPE example: "unbelievable" might tokenize as:
# ["un", "##believe", "##able"]  (BERT-style)
# or ["un", "believ", "able"]   (GPT-style)
# New words can always be represented from known subword pieces

# Using HuggingFace tokenizers:
from transformers import AutoTokenizer
tokenizer = AutoTokenizer.from_pretrained("bert-base-uncased")
print(tokenizer.tokenize("John's father didn't have £100."))
# ['john', "'", 's', 'father', 'didn', "'", 't', 'have', '£', '100', '.']

BPE Step-by-Step Algorithm (High Exam Priority!)

How BPE Training Works

  1. Initialise: Split every word into individual characters. Vocabulary = all unique characters.
  2. Count pairs: Find the most frequent adjacent pair in the current segmentation.
  3. Merge: Replace every occurrence of that pair with the merged token. Add it to the vocabulary.
  4. Repeat steps 2–3 until target vocabulary size is reached.

When applying (not training) BPE: apply learned merge rules in order from first-learned to last-learned.

Worked Exam Example (2023 Past Paper) — "mississippi is pie", target vocab size = 8

Applying Pre-learned BPE Rules (2024 Past Paper Style)

Rules are applied in order. Example rules: (i,s)→is; (p,i)→pi; (i,e)→ie; (p,ie)→pie

Encode "pie" with base characters {p, i, e}:

(p,i)→pi[pi][e]
(i,e)→ie[pi][e] — no adjacent i,e pair now
(p,ie)→pie[pi][e] — no match

Final: pi | e — rules applied strictly in order, even if a later rule could have matched.

Stemming & Lemmatization

▼

Problem: "loved" and "loves" have the same meaning but won't match as strings. We need to reduce words to a canonical form.

Stemming

Rule-based removal of common suffixes. Works on single words without context. Fast but crude.

InputStem
walkingwalk
plasteredplaster
computingcomput
poniesponi

Lemmatization

Uses Part-of-Speech + meaning. Smarter — distinguishes words with same stem but different meaning.

InputLemma
emergencyemergency
emergeemerge
bettergood (adj.)
ranrun

The Porter Stemmer Algorithm

One of the most widely used stemming algorithms. Applies ordered rules in steps:

# Porter Stemmer rules (sample):

# Step 1a — plural/possessive
# sses → ss : caresses → caress
# ies  → i  : ponies   → poni
# s    → ø  : cats     → cat

# Step 1b — past tense / progressive
# (*v*)ing → ø : walking   → walk
# (*v*)ed  → ø : plastered → plaster

# Step 2 (long stems only)
# ational → ate : relational → relate
# izer    → ize : digitizer  → digitize

from nltk.stem import PorterStemmer
ps = PorterStemmer()
words = ["caresses", "ponies", "walking", "plastered", "relational"]
for w in words:
    print(f"{w} → {ps.stem(w)}")
# caresses → caress
# ponies   → poni
# walking  → walk
# plastered → plaster
# relational → relat

Stemming Weakness: Over-stemming

Words with different meanings collapse to the same stem:

WordPorter StemProblem
emergencyemergDifferent meanings, same stem!
emergeemerg

Lemmatization uses POS to distinguish: emergency (noun) → emergency; emerge (verb) → emerge.

Lemmatization with spaCy

import spacy
nlp = spacy.load("en_core_web_sm")

examples = ["loved", "loves", "loving", "better", "ran"]
doc = nlp(" ".join(examples))
for token in doc:
    print(f"{token.text:12} → {token.lemma_:10} ({token.pos_})")
# loved        → love       (VERB)
# loves        → love       (VERB)
# loving       → love       (VERB)
# better       → good       (ADJ)
# ran          → run        (VERB)

Document Similarity — Set Representation

▼

Core Hypothesis

If two documents share many of the same tokens, they are likely discussing similar subjects. The more overlap, the higher the similarity.

Representing a Document as a Set

A set is a collection of unique items. After preprocessing, represent each document as the set of its tokens:

# Two Reddit posts about drinks:
post_A = "Anyone tried Irn Bru? It's a Scottish drink."
post_B = "Has anyone had Irn Bru before? Unique Scottish taste."

import spacy
nlp = spacy.load("en_core_web_sm")

def to_token_set(text):
    doc = nlp(text.lower())
    return set(
        token.lemma_ for token in doc
        if not token.is_stop and not token.is_punct
    )

X = to_token_set(post_A)  # {'try', 'irn', 'bru', 'scottish', 'drink'}
Y = to_token_set(post_B)  # {'irn', 'bru', 'scottish', 'taste', 'unique'}

Set Similarity Measures

▼

What is a Similarity Measure?

A function $\text{sim}(X, Y)$ where $X$ and $Y$ are token sets:

  • High value → documents are similar
  • Low value → documents are dissimilar
  • Ideally bounded between 0 and 1

Measure 1: Raw Overlap Count

$$\text{sim}(X, Y) = |X \cap Y|$$

Pros

  • Simple and intuitive
  • Easy to compute

Cons

  • Not normalised — long documents always score higher
  • Not bounded between 0 and 1

Measure 2: Overlap Coefficient

$$\text{sim}(X, Y) = \frac{|X \cap Y|}{\min(|X|, |Y|)}$$

Interpretation: The percentage of tokens in the smaller document that also appear in the larger document.

Pros

  • Bounded [0, 1]
  • 0 = no overlap; 1 = one set is subset of other
  • Good when one document is shorter

Cons

  • A short document with all words in common with a much larger document scores 1.0 even if the documents are very different in scope
def overlap_coefficient(X, Y):
    return len(X & Y) / min(len(X), len(Y))

X = {'irn', 'bru', 'scottish', 'drink', 'try'}
Y = {'irn', 'bru', 'scottish', 'taste', 'unique'}
print(overlap_coefficient(X, Y))  # 3/5 = 0.6

Measure 3: Jaccard Similarity

$$\text{sim}(X, Y) = \frac{|X \cap Y|}{|X \cup Y|}$$

Interpretation: Overlapping tokens divided by all unique tokens across both documents.

🔑
Equivalent form:

Since $|X \cup Y| = |X| + |Y| - |X \cap Y|$, we can write: $\text{sim}(X,Y) = \frac{|X \cap Y|}{|X| + |Y| - |X \cap Y|}$

Properties

  • Bounded [0, 1]
  • 0 = completely different sets
  • 1 = identical sets
  • Very widely used in practice

Metric Properties

Jaccard distance $d(X,Y) = 1 - \text{sim}(X,Y)$ is a proper metric:

  • $d(X,X) = 0$
  • $d(X,Y) > 0$ if $X \neq Y$
  • $d(X,Y) = d(Y,X)$ (symmetric)
  • $d(X,Z) \leq d(X,Y) + d(Y,Z)$ (triangle inequality)
def jaccard_similarity(X, Y):
    intersection = X & Y
    union = X | Y
    if not union: return 0.0
    return len(intersection) / len(union)

X = {'irn', 'bru', 'scottish', 'drink', 'try'}
Y = {'irn', 'bru', 'scottish', 'taste', 'unique'}

# |X∩Y| = 3, |X∪Y| = 7
print(jaccard_similarity(X, Y))  # 3/7 ≈ 0.429
print(1 - jaccard_similarity(X, Y))  # Jaccard distance ≈ 0.571

Worked Example — Full Pipeline

import spacy
nlp = spacy.load("en_core_web_sm")

posts = {
    "interest": "Anyone tried Irn Bru? Scottish drink banned in some countries.",
    "A": "Irn Bru is a unique Scottish soft drink with a distinctive taste.",
    "B": "I love pizza. Italian food is the best cuisine in the world."
}

def to_set(text):
    doc = nlp(text.lower())
    return set(t.lemma_ for t in doc if not t.is_stop and not t.is_punct)

sets = {k: to_set(v) for k, v in posts.items()}

interest = sets["interest"]
print("Jaccard(interest, A):", jaccard_similarity(interest, sets["A"]))
print("Jaccard(interest, B):", jaccard_similarity(interest, sets["B"]))
# interest, A should score much higher than interest, B

Measure 4: Sørensen–Dice Coefficient

$$\text{Dice}(X, Y) = \frac{2|X \cap Y|}{|X| + |Y|}$$

Interpretation: Double the intersection divided by the total elements across both sets. Gives proportionally higher weight to shared elements than Jaccard.

💡
Dice vs Jaccard Relationship

If $J = \text{Jaccard}(X,Y)$, then $\text{Dice}(X,Y) = \dfrac{2J}{1+J}$. Dice ≥ Jaccard always. Example (Irn Bru, |∩|=3, |X|=|Y|=5): Jaccard = 3/7 ≈ 0.429, Dice = 6/10 = 0.6.

Properties

  • Bounded [0, 1]
  • 0 = disjoint sets (no overlap)
  • 1 = identical sets
  • Symmetric: Dice(X,Y) = Dice(Y,X)
  • Dice ≥ Jaccard for any X, Y

⚠️ NOT a Proper Metric!

The Sørensen–Dice distance $1 - \text{Dice}(X,Y)$ does NOT satisfy the triangle inequality, unlike Jaccard distance which does. This is a key exam distinction!

Explicitly tested in 2022 past exam — see worked example below.

def sorensen_dice(X, Y):
    return 2 * len(X & Y) / (len(X) + len(Y))

Three probe texts A, B, C (each with 5 unique tokens after deduplication):

  • A = {a, eda, bceda, bcda, bce} → |A| = 5
  • B = {ca, eda, bcba, bceda, bce} → |B| = 5
  • C = {beda, bceda, bceca, ebeda, b} → |C| = 5
PairIntersection|∩|Dice Score
A, B{eda, bceda, bce}32×3/(5+5) = 0.6

$0.6 \leq 0.2 + 0.2 \implies 0.6 \leq 0.4 \quad \textbf{VIOLATED!}$

Practice

Given $A = \{p, q, r, s\}$ and $B = \{q, r, t, u, v\}$, compute (a) Jaccard similarity, (b) Sørensen–Dice coefficient, (c) state which is larger and why.

$|A \cap B| = |\{q, r\}| = 2$, $|A \cup B| = |\{p,q,r,s,t,u,v\}| = 7$, $|A| = 4$, $|B| = 5$

(a) Jaccard: $\dfrac{2}{7} \approx 0.286$
(b) Dice: $\dfrac{2 \times 2}{4 + 5} = \dfrac{4}{9} \approx 0.444$
(c) Dice (0.444) > Jaccard (0.286). Dice always gives a higher or equal value because the denominator $|X|+|Y|$ counts shared elements twice, while Jaccard's denominator $|X \cup Y|$ counts them only once.

Comparison of Measures

MeasureFormulaRangeBest forProper Metric?
Raw Overlap$|X \cap Y|$[0, ∞)Quick checkNo
Overlap Coefficient$\frac{|X \cap Y|}{\min(|X|,|Y|)}$[0, 1]Short vs long docsNo
Jaccard Similarity$\frac{|X \cap Y|}{|X \cup Y|}$[0, 1]General useYes
Sørensen–Dice$\frac{2|X \cap Y|}{|X|+|Y|}$[0, 1]Bioinformatics, NLPNo

Weaknesses of Set-Based Similarity

  • All words are treated equally — but rare words should be more important
  • Word frequencies are ignored — "irn" appearing 10x vs 1x treated the same
  • Synonyms cannot match — "happy" and "joyful" are different tokens in a set
  • Word order ignored — set has no positional information

These weaknesses motivate TF-IDF (next lectures) and dense vector representations (word2vec, BERT).

Multiple Choice

MCQ

1. Which of the following best describes a token in NLP?

Correct! A token is a meaningful sequence of characters. Punctuation, numbers, and word-parts like "n't" from "didn't" can all be tokens. Tokens ≠ words.
MCQ

2. What does Herdan's/Heaps' Law state?

Heaps' Law: $|V| = kN^b$ where $0 < b < 1$. Vocabulary grows without bound — roughly as the square root of corpus length ($b \approx 0.5$). It never truly plateaus; new content words keep appearing.
MCQ

3. Given $X = \{a, b, c, d\}$ and $Y = \{b, c, e\}$, what is the Jaccard similarity?

$|X \cap Y| = |\{b,c\}| = 2$. $|X \cup Y| = |\{a,b,c,d,e\}| = 5$. Jaccard = $2/5 = 0.4$.
MCQ

4. Which statement about stopword removal is most accurate?

Correct. Stopword lists vary between toolkits and are not definitive. Some meaningful phrases ("The Who", "to be or not to be") consist entirely of common words, so blanket stopword removal can hurt performance in some tasks.
MCQ

5. The Jaccard distance $d(X,Y) = 1 - \text{Jaccard}(X,Y)$ satisfies all metric properties. Which property states that $d(X,Z) \leq d(X,Y) + d(Y,Z)$?

The triangle inequality states that the distance from X to Z is at most the distance going via an intermediate point Y. This is what makes Jaccard distance a proper metric (not just a similarity measure).
MCQ

6. Which of the following is a weakness of set-based document similarity?

Set-based similarity treats all words equally (no TF-IDF weighting) and ignores how often words appear. This means a rare, highly discriminative word like "photosynthesis" has the same weight as a stopword that slipped through. This motivates weighted approaches like TF-IDF.

Essay / Long Answer Questions

Essay

16. Describe the standard text preprocessing pipeline for a document similarity system. For each step, explain its purpose and identify a potential drawback or edge case.

Model Answer outline:
  1. Data Cleaning — Remove HTML tags, links, formatting. Ensures noise doesn't affect token extraction. Drawback: URLs sometimes contain useful information (domain = source).
  2. Tokenization — Split text into tokens using rule-based systems (spaCy). Handles contractions (didn't → did + n't), currency (£100 → £ + 100). Drawback: Language-specific; fails on Chinese without dedicated tools.
  3. Case Normalisation — Lowercase all tokens so "IRN" = "irn". Drawback: Loses named entity information ("Apple" company vs fruit).
  4. Stemming/Lemmatization — Reduce words to canonical form (loved → love). Drawback: Stemming can conflate different words (emergency → emerg, emerge → emerg).
  5. Stopword Removal — Filter out high-frequency, low-meaning words. Drawback: Some important phrases consist entirely of stopwords ("to be or not to be").
Essay

17. Compare structured and unstructured data in the context of building a search system. What are the advantages and disadvantages of each, and why is processing unstructured text challenging?

Model Answer outline:
Structured data advantages: Precise filtering (SQL queries), fast exact lookups, easy aggregation, no ambiguity in meaning (column headers label data).
Structured data disadvantages: Expensive to create and maintain schemas; loses nuance (a 1-star review contains reasoning about why; the rating alone does not).
Unstructured text advantages: Rich, contains full reasoning and context; natural for humans to produce; captures nuance, sentiment, relationships.
Unstructured text disadvantages: Ambiguity ("I saw the elephant with my telescope"); no labels; requires NLP to extract meaning; noisy (typos, informal language, emoji).
Why hard: Language requires world knowledge and reasoning, not just pattern matching. The same meaning can be expressed in infinitely many ways (paraphrase). Vocabulary grows without bound (Heaps' Law).
Essay

18. Explain three limitations of using set-based similarity (Jaccard) for document similarity. For each limitation, suggest what kind of approach could address it.

Model Answer:
  1. All words equally weighted. "the" and "photosynthesis" contribute equally if both appear. Fix: TF-IDF weighting, which upweights rare, discriminative terms and downweights common ones.
  2. Word frequency ignored. A word appearing 50 times vs 1 time is treated the same in a set. Fix: Bag-of-words (count) vectors or TF-IDF vectors capture frequency information.
  3. Synonyms cannot match. "happy" and "joyful" are different tokens; two documents about the same concept using synonyms score 0 overlap. Fix: Dense vector representations (Word2Vec, BERT embeddings) place synonyms near each other in vector space, enabling semantic similarity beyond string matching.

28. You are building an automatic writing assistant that provides grammar suggestions as a user writes. Would you use stemming, lemmatisation, and/or stopword removal? Explain why or why not for each.

Stemming — No. Grammar errors often involve incorrect inflection (wrong endings). Stemming removes endings, making it impossible to identify these errors. E.g., "I runned home" — the erroneous "-ned" would be stemmed away, hiding the mistake.

Lemmatisation — No. Lemmatisation also treats different inflectional forms as the same token, so incorrect inflections would be normalised and errors missed. Unlike stemming it uses POS, but the effect is the same — it erases the very surface form you need to flag.

Stopword removal — No. Stopwords are essential to grammar. Errors like "She go to store" involve function words and verb agreement that depend on stopwords being present. Removing them would blind the system to most grammatical error types.

Summary: None of the three are appropriate. This application needs to preserve surface forms, not normalise them.

Past Paper 2025 — Q1e [6 marks]

33. A colleague proposes a new set similarity measure:
$\text{sim}(A, B) = \dfrac{|A - B|}{|A \cap B|}$
(where $A - B$ is the set difference: elements in A but not in B)
Using DocX and DocY: compute sim(DocX, DocY) and describe three problems with this measure.

Calculation:
|DocX − DocY| = |{C}| = 1 (C is in DocX but not DocY)
|DocX ∩ DocY| = 3
sim(DocX, DocY) = 1/3 ≈ 0.333

Three problems:
  1. Measures dissimilarity, not similarity. A larger value means DocX has MORE elements not in DocY — i.e., they are LESS similar. This is counterintuitive and backwards from what "similarity" should mean.
  2. Asymmetric. sim(DocX, DocY) ≠ sim(DocY, DocX). The set difference |A−B| ≠ |B−A| when |A| ≠ |B|. Similarity between two documents should be the same regardless of which is called A or B.
  3. Division by zero. If A ∩ B = ∅ (no common tokens), the denominator is 0, making the measure undefined. Two completely different documents produce an error rather than a similarity of 0.

Practice — Heaps' Law

36. A model is trained on a corpus with $N = 4,000,000$ word instances. Using Heaps' Law with $k = 10$ and $b = 0.5$:
(a) Estimate the vocabulary size $|V|$.
(b) The corpus doubles to $N = 8,000,000$. Estimate the new vocabulary size.
(c) By what factor did the corpus grow? By what factor did vocabulary grow?
(d) What does this imply about out-of-vocabulary (OOV) words?

(a) $|V| = 10 \times (4{,}000{,}000)^{0.5} = 10 \times 2000 = \mathbf{20,000}$
(b) $|V| = 10 \times (8{,}000{,}000)^{0.5} = 10 \times 2828 \approx \mathbf{28,280}$
(c) Corpus doubled (×2). Vocabulary grew by factor ≈ 28,280/20,000 ≈ ×1.41 ≈ √2
(d) Vocabulary grows sub-linearly — even with very large corpora you will always encounter new words. Any model with a fixed vocabulary will inevitably see OOV words in deployment. This motivates subword tokenisation (BPE) which can represent any new word from known subword pieces.
Practice — TF-IDF Calculation

37. Given IDF values: "data"=3, "science"=4, "is"=1, "fun"=5, "hard"=4.
Compute the TF-IDF vector (in vocabulary order: data, science, is, fun, hard) for:
Document: "data science is fun data"

Token counts (TF): data=2, science=1, is=1, fun=1, hard=0

TF-IDF = TF × IDF:
data: 2 × 3 = 6
science: 1 × 4 = 4
is: 1 × 1 = 1
fun: 1 × 5 = 5
hard: 0 × 4 = 0

TF-IDF vector: [6, 4, 1, 5, 0]

Note: "is" gets a low weight (IDF=1) because it appears in many documents — TF-IDF correctly down-weights common words even without explicit stopword removal.
Practice — Contextual Preprocessing

38. For each application below, state whether you would apply stemming, lemmatisation, and/or stopword removal — and briefly justify each decision.
(a) A patent similarity search system.
(b) A chatbot that answers factual questions.
(c) A sentiment analysis system for product reviews.

(a) Patent similarity search:
— Stemming/Lemmatisation: YES. "compute", "computing", "computed" all indicate the same technical concept. Normalising improves recall of relevant patents using different inflections.
— Stopword removal: YES. Common words like "the", "is" add noise to similarity calculations but carry no domain signal.
— Caveat: Over-stemming could collapse different patent concepts (e.g., "alloys" and "alloying" vs a stem that matches unrelated words).

(b) Factual Q&A chatbot:
— Stemming: NO. "Is Australia" vs "was Australia" matters for temporal accuracy. Stemming would destroy this.
— Lemmatisation: MAYBE. For question understanding, lemmatising verbs helps (running → run). But for answer generation, surface forms matter.
— Stopword removal: NO. "Who is the president of France?" — removing stopwords gives "Who president France?" which loses critical question structure.

(c) Sentiment analysis:
— Stemming/Lemmatisation: YES for feature extraction — "loved", "loves", "loving" all indicate positive sentiment.
— Stopword removal: CAREFUL. "not bad" → removing "not" inverts the sentiment! Negation words matter. Custom stopword lists that preserve "not", "never", "no" are essential.
MCQ — Practice

39. Which sentence correctly identifies how words differ from tokens in NLP?

Correct. A token is any meaningful sequence of characters produced by a tokeniser — this includes punctuation marks, numbers, currency symbols, and sub-word units like "n't" from "didn't". Words are dictionary entries; tokens are the atomic units a NLP system actually processes. (2023 Q1a)
MCQ — Practice

40. Set X = {a, b, c, d, e} and Set Y = {a, b, c}. What is the Overlap Coefficient of X and Y, and what does the result tell you?

Correct. Overlap Coefficient = |X ∩ Y| / min(|X|,|Y|) = 3/min(5,3) = 3/3 = 1.0. This means Y is entirely contained in X. The weakness of Overlap Coefficient is exactly this: a small document that is a complete subset of a large one scores 1.0 even if the documents cover very different topics overall. Jaccard would give 3/5 = 0.6, which is more informative.
