Probabilistic Models

Why Probabilities?

IR deals with uncertain information: document representation is imperfect, queries are vague, relevance is subjective. Probability theory is the natural framework for quantifying uncertainty.

Probability Ranking Principle (Robertson 1977):

If a system ranks documents in decreasing order of P(Relevance|Document), then the overall effectiveness will be the best obtainable on the basis of available data.

Bayes Decision Rule for Relevance
\[ P(R|D) = \frac{P(D|R) \cdot P(R)}{P(D)} \]

Document D is ranked as relevant if P(R|D) > P(NR|D). Use Bayes' rule to estimate from training data.

Binary Independence Model (BIM) & RSJ Weights EXPANDED

Binary Independence Model (BIM / BIR)

The BIM is the original probabilistic retrieval model. Key assumptions:

  • Binary representation: each term is either present (1) or absent (0) in a document — no term frequencies
  • Term independence: terms are assumed to be independent given relevance status
  • Goal: estimate P(R=1 | d, q) for each document d and query q
BIM Ranking Score (log-odds of relevance)
\[ \text{score}(d,q) = \sum_{t \in q \cap d} \log \frac{p_t(1-q_t)}{q_t(1-p_t)} \]

Where:
• \(p_t = P(\text{term } t \text{ in doc} \mid \text{relevant})\)
• \(q_t = P(\text{term } t \text{ in doc} \mid \text{non-relevant})\)
Sum is over query terms that appear in the document.

Robertson-Sparck Jones (RSJ) Weights

When relevance information is available (e.g., from judged documents), the RSJ weight for term t is:

\[ w_t^{RSJ} = \log \frac{(r_t + 0.5)(N - n_t - R + r_t + 0.5)}{(n_t - r_t + 0.5)(R - r_t + 0.5)} \]

Where:
• \(N\) = total number of documents in collection
• \(R\) = number of known relevant documents
• \(n_t\) = number of documents containing term t (df)
• \(r_t\) = number of relevant documents containing term t
• The 0.5 values are Laplace smoothing to avoid log(0).

RSJ → IDF Approximation

When no relevance information is available (R=0, r_t=0), the RSJ weight simplifies to the standard IDF:

\[ w_t^{RSJ} \approx \log \frac{N - n_t + 0.5}{n_t + 0.5} \approx \log \frac{N}{n_t} \]

This is exactly the IDF formula used in BM25. So BM25's IDF is a special case of the RSJ weight with no feedback.

From BIM to BM25: Adding Term Frequencies

BIM only uses binary term occurrence. To incorporate term frequency and document length, BM25 extends BIM with:

  • A saturating TF function that gives diminishing returns for higher tf
  • A document length normalisation factor (penalises long documents that are long by chance)
  • The RSJ weight as the IDF component

BM25 — Best Match 25

BM25 Score
\[ \text{BM25}(d, q) = \sum_{t \in q} \underbrace{\log \frac{N - df_t + 0.5}{df_t + 0.5}}_{\text{IDF (RSJ approx.)}} \cdot \underbrace{\frac{(k_1 + 1) \cdot tf_{td}}{k_1 \left(1 - b + b \cdot \frac{|d|}{\text{avgdl}}\right) + tf_{td}}}_{\text{TF factor (saturating)}} \]

Parameters: k₁ ∈ [1.2, 2.0] (TF saturation), b ∈ [0, 1] (length normalisation, typically 0.75), |d| = doc length, avgdl = average doc length.

Practice Example

N=1000, df(cat)=100, |d|=200, avgdl=150, tf(cat,d)=5, k₁=1.2, b=0.75. Compute BM25 score contribution of term "cat".

Solved Example

Step 1 — IDF:
IDF(cat) = log((1000−100+0.5)/(100+0.5)) = log(900.5/100.5) = log(8.96) ≈ 2.19

Step 2 — TF normalisation:
Norm = k₁(1−b + b×|d|/avgdl) + tf
= 1.2(1−0.75 + 0.75×200/150) + 5
= 1.2(0.25 + 1.0) + 5
= 1.2×1.25 + 5 = 1.5 + 5 = 6.5

Step 3 — TF factor:
TF_factor = (k₁+1)×tf / Norm = 2.2×5/6.5 ≈ 1.692

BM25 contribution = IDF × TF_factor = 2.19 × 1.692 ≈ 3.705

BM25 Parameter Intuition

k₁ (TF saturation):

  • k₁=0 → binary (presence/absence only)
  • k₁→∞ → raw tf (no saturation)
  • Typical: k₁=1.2. High tf gets diminishing returns

b (length normalisation):

  • b=0 → no length normalisation
  • b=1 → full length normalisation
  • Typical: b=0.75. Long docs penalised less than TF-IDF

Python: BM25 Implementation

import math

def bm25_score(query_terms, doc_tf, doc_len, df, N, avgdl, k1=1.2, b=0.75):
    score = 0.0
    for term in query_terms:
        tf = doc_tf.get(term, 0)
        dft = df.get(term, 0)
        if dft == 0: continue
        idf = math.log((N - dft + 0.5) / (dft + 0.5))
        tf_norm = tf * (k1 + 1) / (tf + k1 * (1 - b + b * doc_len / avgdl))
        score += idf * tf_norm
    return score

# Example
query = ['information', 'retrieval']
doc_tf = {'information': 3, 'retrieval': 2}
df = {'information': 500, 'retrieval': 100}
N, avgdl = 10000, 200
score = bm25_score(query, doc_tf, 180, df, N, avgdl)
print(f"BM25 score: {score:.4f}")

Language Models for IR

Unigram Language Model

Each document d defines a unigram language model M_d — a probability distribution over the vocabulary. The probability of each word is estimated from the document. Different smoothing methods combine the document model with the collection model to handle unseen terms.

Query Likelihood Model
\[ \text{Score}(d, q) = P(q | M_d) = \prod_{t \in q} P(t | M_d) \]

Each document d has a language model M_d. Rank documents by the probability that M_d generated the query q. MLE estimate: P(t|M_d) = tf(t,d)/|d|.

Practice Example

Doc d: "the cat sat on the mat" (6 tokens). Query: "cat mat". Compute P(q|M_d) using MLE (no smoothing). What is the problem?

Solved Example

P(cat|M_d) = 1/6 ≈ 0.167
P(mat|M_d) = 1/6 ≈ 0.167
P(q|M_d) = 0.167 × 0.167 ≈ 0.028
Problem: If any query term has tf=0 in d, P(q|M_d) = 0 — the document is excluded even if it's otherwise relevant. Solution: smoothing.

Jelinek-Mercer (JM) Smoothing
\[ P(t|M_d) = (1-\lambda)\frac{tf(t,d)}{|d|} + \lambda \cdot P(t|M_c) \]

λ ∈ [0,1] controls the mix. P(t|M_c) = collection language model = cf(t)/|C| (cf = collection frequency, |C| = total tokens in collection). Prevents zero probabilities for unseen terms.

Practice Example

λ=0.5. Doc d: "cat sat" (2 tokens). Collection: 1000 tokens, "dog" appears 10 times, "cat" 50 times. Doc has tf(dog)=0, tf(cat)=1. Compute P(cat|M_d) and P(dog|M_d) with JM smoothing.

Solved Example

P(cat|M_c) = 50/1000 = 0.05. P(cat|M_d) MLE = 1/2 = 0.5.
P(cat|M_d) JM = 0.5×0.5 + 0.5×0.05 = 0.25+0.025 = 0.275
P(dog|M_c) = 10/1000 = 0.01. P(dog|M_d) MLE = 0.
P(dog|M_d) JM = 0.5×0 + 0.5×0.01 = 0.005 (no longer zero!)

Dirichlet Prior Smoothing NEW

Dirichlet Prior Smoothing

Bayesian smoothing: places a Dirichlet prior on document word probabilities. Uses a single parameter μ (mu) that controls how much the collection model is blended in. Typical value: μ = 2000.

Dirichlet Smoothed Language Model
\[ P(t | M_d) = \frac{tf(t,d) + \mu \cdot P(t|M_c)}{|d| + \mu} \]

Where:
• tf(t,d) = term frequency of t in document d
• |d| = length of document d
• P(t|M_c) = collection probability of term t (= cf(t)/|C|)
• μ = Dirichlet smoothing parameter (controls collection prior strength; typical value 2000)

Intuition behind Dirichlet Smoothing

  • Think of adding μ "pseudo-counts" drawn from the collection distribution to every document
  • For short documents (small |d|), μ dominates → heavier smoothing toward collection model
  • For long documents (large |d|), the document's own counts dominate → less smoothing needed
  • This provides automatic document-length-sensitive smoothing — unlike JM (fixed λ)
Dirichlet: Worked Example

Query: "machine learning". Doc d has |d|=500. tf("machine",d)=3, tf("learning",d)=0. Collection: P("machine"|Mc)=0.002, P("learning"|Mc)=0.005. μ=2000.

P("machine"|Md) = (3 + 2000×0.002) / (500 + 2000) = (3 + 4) / 2500 = 7/2500 = 0.0028

P("learning"|Md) = (0 + 2000×0.005) / (500 + 2000) = 10/2500 = 0.004 (not zero!)

JM vs Dirichlet Comparison

  • JM: fixed interpolation weight λ for all documents and all terms
  • Dirichlet: effective weight depends on |d| → longer docs get less smoothing
  • Dirichlet generally preferred for ad-hoc retrieval
  • JM preferred for routing/filtering tasks

Dirichlet Log-Score Form

Taking logs for the query likelihood model:

\[ \log P(q|M_d) = \sum_{t \in q} \log \frac{tf(t,d) + \mu \cdot P(t|M_c)}{|d| + \mu} \]

Divergence From Randomness (DFR) Framework NEW — EXAM CRITICAL

DFR Core Intuition

A term is informative in a document if its frequency in that document diverges significantly from what would be expected if words were placed randomly (Poisson/random process). The greater the divergence from random, the more informative the term. Proposed by Amati & Van Rijsbergen (2002).

DFR Framework: Two-Component Design

Every DFR model is a product of two components:

Component 1: Basic Model (Randomness)

Models the "elite" distribution — the probability that a term's frequency arose by chance. Penalises terms that could occur randomly. Models: Bose-Einstein (BE), Geometric (G), In-expB, In-expC, Poisson (PO)

Component 2: Normalisation

Normalises term frequency by document length and collection statistics. Models: Normalisation 1 (H1), Normalisation 2 (H2), Laplace Normalisation (L)

DFR General Weighting Formula
\[ w(t,d) = \text{Inf}_1(t,d) \times \text{Inf}_2(t,d) \]

Inf₁ = information content from the basic model = measures how much the observed tf diverges from the random baseline.
Inf₂ = normalisation = adjusts for document length and term informativeness in the collection.

More concretely, the DFR weight can be expressed as:
\[ w(t,d) = -\log_2 P_\text{rand}(TF \geq tf_{t,d} \mid \text{collection}) \times \text{normalisation} \] The first factor penalises terms that appear often by random chance (low weight to common terms in collection).

Key Insight: DFR vs BM25

Both BM25 and DFR models use IDF-like weighting and TF normalisation. The key difference: DFR derives the IDF and TF components from an explicit probabilistic model of randomness (Poisson distribution for PL2, or Bose-Einstein/geometric for others). BM25 uses a more heuristic-based derivation from BIM.

DFR Models: PL2, BB2, GL2 and Others NEW — EXAM CRITICAL

Naming Convention for DFR Models

Each DFR model is named by combining its basic model and normalisation:

  • First letter(s): basic randomness model (e.g., P = Poisson, B = Bose-Einstein, G = Geometric, In_exp = Inverse Expected)
  • Last letter: normalisation type (L = Laplace, 2 = Normalisation 2, etc.)
PL2 — Poisson + Laplace Normalisation 2

Most commonly used DFR model. Uses Poisson distribution as the randomness baseline, combined with Laplace normalisation (parameter c).

\[ w_{PL2}(t,d) = \frac{tf_n}{tf_n + 1} \cdot \left( tf_n \cdot \log_2 \frac{tf_n}{\lambda} + (\lambda - tf_n)\log_2 e + 0.5 \log_2(2\pi \cdot tf_n) \right) \]

where tf_n = normalised term frequency = tf·log(1 + c·avgdl/|d|) and λ = F/N (expected term frequency in collection; F = collection frequency, N = number of docs).

BB2 — Bose-Einstein 1 + Normalisation 2

Uses the Bose-Einstein distribution (non-parametric, based on sampling without replacement). Generally performs slightly differently from PL2 on different collection types.

\[ w_{BB2}(t,d) \propto \log_2 \frac{(F+N)(tf_n+1)}{N(F-tf_n+N)} \]

where F = collection frequency of t, N = collection size.

GL2 — Geometric + Normalisation 2

Uses a geometric distribution as the randomness model. The geometric model is simpler to compute than Poisson.

In_expB2 / In_expC2 — Inverse Expected

In_expB2: uses an inverse expected frequency model with Normalisation 2 (Stirling's approximation). In_expC2: same basic model but with a different normalisation. Both have been shown competitive with BM25 and PL2.

IFB2 — Inverse Term Frequency + Normalisation 2

Based on inverse document frequency as the randomness model. Bridges the gap between DFR and classical IDF weighting. Often used as a strong baseline within the DFR family.

PL2: The c Parameter (Term Frequency Normalisation)
\[ tf_n = tf \cdot \log_2\!\left(1 + c \cdot \frac{\text{avgdl}}{|d|}\right) \]

c is PL2's single free parameter (analogous to BM25's b):
• c controls how much term frequency is normalised by document length
• Larger c = more normalisation (similar to higher b in BM25)
• Typical value: c = 1.0
• When avgdl/|d| is large (short doc), tf_n is amplified; when doc is long, tf_n is reduced

PL2: Full Worked Example

Problem

Collection: N=10,000 docs, F(term)=200 (collection frequency), avgdl=300. Document d: tf=4, |d|=150. c=1. Compute tf_n and the approximate PL2 score (use simplified form).

Step-by-Step Solution

Step 1 — Collection probability λ:
λ = F/N = 200/10000 = 0.02

Step 2 — Normalised TF:
tf_n = tf × log₂(1 + c × avgdl/|d|) = 4 × log₂(1 + 1 × 300/150)
= 4 × log₂(1 + 2) = 4 × log₂(3) = 4 × 1.585 = 6.34

Step 3 — Poisson information (simplified):
Core = tf_n × log₂(tf_n/λ) = 6.34 × log₂(6.34/0.02) = 6.34 × log₂(317)
= 6.34 × 8.31 ≈ 52.7

Step 4 — Apply length normalisation factor:
w = tf_n/(tf_n + 1) × core = (6.34/7.34) × 52.7 ≈ 0.864 × 52.7 ≈ 45.5

(Full formula also includes the (λ − tf_n)log₂e term but the tf_n×log₂(tf_n/λ) term dominates at high tf_n.)

Pseudo-Relevance Feedback (PRF) & RM3 NEW

Pseudo-Relevance Feedback (PRF)

Assume the top-k documents returned by an initial retrieval are relevant (whether or not they actually are). Use these "pseudo-relevant" documents to expand or reweight the query, then re-retrieve. Usually improves recall significantly.

PRF Pipeline

  1. Run initial retrieval with original query q → top-k documents D_fb
  2. Extract expansion terms from D_fb (terms not in original query that appear frequently)
  3. Re-weight or expand the original query with these terms
  4. Re-retrieve with expanded query to get final ranked list
RM3 (Relevance Model 3) — Mixture Approach
\[ P(t | q_{exp}) = (1 - \alpha) \cdot P_{RM1}(t | D_{fb}) + \alpha \cdot P_{MLE}(t | q) \]

Where:
• RM1 = Relevance Model: \(P_{RM1}(t | D_{fb}) = \sum_{d \in D_{fb}} P(t|M_d) \cdot P(q|M_d) \cdot P(d)\)
• \(P_{MLE}(t|q)\) = MLE from original query terms (original query weight)
• α controls the interpolation between feedback model and original query (typical: α=0.5)
• Top fb_terms terms by RM1 weight are added to the query

RM3 Parameters

  • fb_docs: number of feedback documents to use (typical: 3–10)
  • fb_terms: number of expansion terms to add (typical: 10–50)
  • α (alpha): weight of original query vs feedback model (0.5 is common)

PRF Risk

PRF can fail ("query drift") if:

  • The top-k documents are not truly about the topic
  • The query is ambiguous and top-k docs are for the wrong sense
  • The collection contains a lot of spam/noise near the top

Axiomatic IR NEW

Axiomatic Approach to IR

Rather than deriving a retrieval model from probabilistic first principles, axiomatic IR defines a set of formal constraints (axioms) that any "good" retrieval function should satisfy. A model is then designed or evaluated based on how well it satisfies these constraints. (Fang, Tao, Zhai, 2004.)

Key Axiomatic Constraints

TF Constraint (TFC1)

If doc d₁ and d₂ are identical except d₁ has a higher frequency of a query term, then d₁ should be ranked higher:
tf(t,d₁) > tf(t,d₂) → score(d₁) > score(d₂)

IDF Constraint

Rare query terms should contribute more to the score than common ones. If df(t₁) < df(t₂) and both appear once in a document, the doc should score higher on t₁ than t₂.

Document Length Normalisation (LNC)

A document with the same term density (tf/|d|) as another but longer should not be ranked higher simply by being longer. Length normalisation penalises "verbose" documents that inflate term counts.

TF Saturation Constraint

A basic TF constraint alone is not enough — the saturation constraint requires:

\[ \frac{\partial \text{score}}{\partial \text{tf}} > 0 \quad \text{and} \quad \frac{\partial^2 \text{score}}{\partial \text{tf}^2} < 0 \]

i.e., score increases with tf (positive first derivative) but the increase slows down (negative second derivative — diminishing returns). BM25 satisfies this: the TF factor approaches k₁+1 asymptotically.

Why Axiomatic IR Matters for Exams

Examiners often ask: "Does model X satisfy constraint Y?" You need to be able to check whether a given scoring formula satisfies TF, IDF, and length normalisation constraints by inspection or by taking partial derivatives.

Field-Based & Proximity Models

BM25F — Field-based BM25

Web documents have fields: title, body, URL, anchor text. Different fields should be weighted differently. BM25F normalises TF within each field before combining:

\[ \text{score}(d,Q) = \sum_{t \in Q} \text{IDF}(t) \cdot \frac{(k_1+1) \cdot \tilde{tf}}{k_1 + \tilde{tf}} \]
\[ \tilde{tf} = \sum_f w_f \cdot \frac{tf_f}{1-b_f + b_f \cdot |d_f|/\text{avgdl}_f} \]

w_f = field weight, b_f = field-specific length normalisation parameter.

PL2F — Field-based PL2

Same idea as BM25F but applied to the DFR PL2 model. Combines per-field normalised TF values using field weights, then applies the Poisson information measure. Uses per-field c parameters (c_f).

\[ \tilde{tf}_{PL2} = \sum_f w_f \cdot tf_f \cdot \log_2\!\left(1 + c_f \cdot \frac{\text{avgdl}_f}{|d_f|}\right) \]

Proximity Models (Markov Random Fields)

Documents where query terms appear in close proximity may be more relevant. MRF models term dependencies:

\[ \text{score}(d,Q) = \lambda_1 \sum_{t \in Q} w(t,d) + \lambda_2 \sum_{c \in Q_o} w(c,d) + \lambda_3 \sum_{c \in Q_u} w(c,d) \]

Q_o = ordered pairs ("white house"), Q_u = unordered pairs ("white...house"). Sequential dependence λ₁=0.8, λ₂=λ₃=0.1 is a typical setting.

Summary

BIM & RSJ Weights

Binary Independence Model: terms are binary, independent. RSJ weights = log-odds ratio using relevance statistics. With no relevance info, simplifies to IDF — the foundation of BM25.

BM25

State-of-the-art classical retrieval. IDF × saturated TF × length normalisation. k₁ controls saturation, b controls length normalisation. Still widely used as a strong baseline.

Language Models + Smoothing

Rank by P(q|document model). JM smoothing: fixed λ mix with collection. Dirichlet prior: document-length-sensitive smoothing with parameter μ (typical 2000). Dirichlet preferred for ad-hoc retrieval.

DFR Framework

Term informativeness = divergence from random. Two-component design: basic randomness model × normalisation. Main models: PL2 (Poisson+Laplace, parameter c), BB2, GL2, In_expB2, In_expC2, IFB2. All implemented in Terrier.

PRF & RM3

Pseudo-relevance feedback assumes top-k retrieved docs are relevant, extracts expansion terms, re-retrieves. RM3 interpolates feedback model with original query (α parameter). Risk: query drift.

Axiomatic IR

Formal constraints: TF (more term occurrences → higher score, with saturation), IDF (rare terms weighted more), length normalisation (penalise verbose docs). Good retrieval models satisfy all three.

Field & Proximity

BM25F/PL2F weight different document fields (title, body, URL) independently. MRF proximity models reward documents where query terms appear close together.

IDF(system) = log((500−50+0.5)/(50+0.5)) = log(450.5/50.5) ≈ log(8.921) ≈ 2.188

TF_IR: (k₁+1)×4/(1.725+4) = 2.5×4/5.725 = 10/5.725 ≈ 1.747

Exam-Style Questions
H/M[10 marks]
Q1. (a) Write the BM25 scoring formula and explain the role of each parameter (k₁, b). [5] (b) Explain why language models require smoothing and describe the Jelinek-Mercer method. [5]
(a) BM25 = Σ IDF(t)×(k₁+1)×tf/(k₁(1−b+b×|d|/avgdl)+tf). k₁: TF saturation — how quickly increasing tf gives diminishing returns; k₁=0 → binary; k₁→∞ → raw tf. b: length normalisation — b=0 → no normalisation; b=1 → full normalisation by avgdl. Typical: k₁=1.2, b=0.75. IDF = log((N−df+0.5)/(df+0.5)). [5] (b) MLE P(t|Md)=tf/|d|. If a query term never appears in d, P=0 → document excluded even if otherwise relevant [2]. JM: P(t|Md)=(1−λ)×tf/|d| + λ×P(t|Mc). Mixes document model with collection model. λ controls how much background collection is used; prevents zero probabilities; penalises all documents equally for query terms absent from the collection [3].
H/M[12 marks]
Q2. Explain the Divergence From Randomness (DFR) framework for information retrieval. Your answer should: (a) explain the core intuition behind DFR [3]; (b) describe the two-component structure of DFR weighting functions [3]; (c) explain the PL2 model specifically, including what P, L and 2 stand for, and the role of the c parameter [4]; (d) name two other DFR models and their basic randomness components [2].
(a) DFR intuition [3]: A term is considered informative in a document if its frequency in that document diverges significantly from what would be expected if the term were distributed randomly across the collection (following a Poisson or similar random process). The greater this divergence, the higher the term's weight. This formalises the intuition that surprising/unexpected term occurrences carry more information.

(b) Two-component structure [3]: Every DFR model has: (1) a basic randomness model (e.g., Poisson, Bose-Einstein, Geometric) that computes the probability of the observed term frequency arising by chance — this is the "Inf₁" component; and (2) a normalisation component (e.g., Laplace Normalisation, H2) that adjusts tf for document length and collection statistics — this is "Inf₂". The final weight = Inf₁ × Inf₂.

(c) PL2 [4]: P = Poisson (the randomness model — assumes terms distributed according to Poisson distribution in the collection); L = Laplace normalisation (the normalisation method); 2 = Normalisation 2 (the specific normalisation formula variant). The c parameter controls how strongly tf is normalised by document length: tf_n = tf × log₂(1 + c × avgdl/|d|). Larger c → more normalisation (short documents amplified, long penalised). Typical c=1.

(d) Other DFR models [2]: BB2 (Bose-Einstein distribution as randomness model + Normalisation 2); GL2 (Geometric distribution + Normalisation 2); In_expB2 (Inverse Expected/Stirling approximation + Normalisation 2).
H/M[10 marks]
Q3. (a) Describe the Binary Independence Model (BIM) and state its two key assumptions. [3] (b) What are Robertson-Sparck Jones (RSJ) weights and how do they relate to the standard IDF formula? [4] (c) What does BM25 add to the BIM to improve retrieval? [3]
(a) BIM [3]: The Binary Independence Model represents each document as a binary vector (1=term present, 0=absent) and ranks documents by P(R=1|d,q) — the probability of relevance given the query and document. Key assumptions: (1) Binary representation — each term is either present or absent (no term frequency); (2) Term independence — terms are conditionally independent given the relevance status.

(b) RSJ weights [4]: RSJ weights are log-odds ratios computed from relevance judgments: w_t = log[(r_t+0.5)(N−n_t−R+r_t+0.5) / ((n_t−r_t+0.5)(R−r_t+0.5))], where N=collection size, R=relevant set size, n_t=df of t, r_t=number of relevant docs containing t. When no relevance information is available (R=0, r_t=0), the RSJ weight simplifies to log((N−n_t+0.5)/(n_t+0.5)), which is exactly the IDF formula used in BM25. Therefore IDF is a special (no-relevance-feedback) case of RSJ weighting.

(c) BM25 improvements [3]: BM25 extends BIM by: (1) Term frequency — BIM only uses binary presence; BM25 uses a saturating TF function (diminishing returns via k₁); (2) Document length normalisation — long documents are penalised via the b parameter and avgdl; (3) The RSJ weight (IDF approximation) is retained as the IDF component. Together these give a much more effective ranking than binary BIM.
H/M[8 marks]
Q4. Compare Jelinek-Mercer (JM) smoothing and Dirichlet prior smoothing for language models in IR. For each: state the formula, describe the parameter, and identify a key advantage and disadvantage. Which is generally preferred for ad-hoc retrieval and why? [8]
JM Smoothing [3]: P(t|Md)=(1−λ)×tf(t,d)/|d| + λ×P(t|Mc). Parameter λ ∈ [0,1] controls the mixing. Advantage: simple, single global parameter easy to tune. Disadvantage: same smoothing for all documents regardless of length — short documents get too little smoothing, long documents too much.

Dirichlet Smoothing [3]: P(t|Md)=(tf(t,d)+μ×P(t|Mc))/(|d|+μ). Parameter μ (typical=2000) controls prior strength. Advantage: document-length sensitive — short documents get heavier smoothing (μ dominates when |d| small), long documents less smoothing (|d| dominates). Also has Bayesian motivation. Disadvantage: slightly more complex, one more hyperparameter.

Preference [2]: Dirichlet is generally preferred for ad-hoc retrieval because the document-length-sensitive smoothing is more appropriate — short documents genuinely need more smoothing as they have fewer observations of the underlying distribution.
H/M[8 marks]
Q5. (a) What are the three core axiomatic constraints that a good IR model should satisfy? [3] (b) For each constraint, explain whether BM25 satisfies it, with brief justification. [5]
(a) Three axiomatic constraints [3]: (1) TF constraint with saturation: score increases with term frequency but with diminishing returns (∂score/∂tf > 0 and ∂²score/∂tf² < 0); (2) IDF constraint: terms appearing in fewer documents should receive higher weight (more discriminative); (3) Length normalisation constraint (LNC): documents should not be rewarded simply for being longer — a document with the same density of relevant content as another but longer should not score higher.

(b) BM25 satisfies all three [5]: (1) TF + saturation: BM25's TF factor (k₁+1)×tf/(k₁(…)+tf) is monotonically increasing in tf (satisfies TF constraint) but approaches the asymptote k₁+1 as tf→∞ (satisfies saturation). (2) IDF: BM25 uses IDF=log((N−df+0.5)/(df+0.5)), which decreases as df increases — rare terms get higher weight. (3) LNC: the denominator includes k₁×b×|d|/avgdl, which grows with document length, penalising long documents — satisfies length normalisation. BM25 satisfies all three constraints, which partly explains its strong empirical performance.
Flashcards
BM25
Best Match 25: IDF × saturated TF / length-normalised denominator. k₁ controls saturation, b controls length normalisation. Gold standard classical model.
Language Model (IR)
Each document has a language model Md. Score = P(q|Md) — probability the doc's model generated the query. Requires smoothing.
JM Smoothing
P(t|Md) = (1-λ)×tf/|d| + λ×P(t|Mc). Fixed λ mix with collection. Simple but not length-sensitive.
Dirichlet Smoothing
P(t|Md)=(tf+μP(t|Mc))/(|d|+μ). μ≈2000. Length-sensitive: short docs get heavier smoothing. Preferred for ad-hoc retrieval.
DFR Framework
Divergence From Randomness. Informative term = frequency diverges from random (Poisson/BE/Geometric). Two components: basic model × normalisation.
PL2
Poisson + Laplace Normalisation 2. DFR model. tf_n = tf×log₂(1+c×avgdl/|d|). c parameter controls length normalisation strength.
BIM / BIR
Binary Independence Model. Binary term vectors + term independence assumption. Ranks by P(R|d,q). RSJ weights derived from this. Foundation of BM25.
RSJ Weights
Robertson-Sparck Jones weights = log-odds of relevance with Laplace smoothing. Simplify to IDF when no relevance judgments are available.
PRP
Probability Ranking Principle (Robertson 1977): ranking by P(R|D) in decreasing order maximises expected effectiveness.
RM3 / PRF
Pseudo-Relevance Feedback: assume top-k docs relevant, extract expansion terms, re-retrieve. RM3 interpolates feedback model with original query (α parameter).
BM25F
Field-based BM25: normalises TF within each field (title, body, URL) independently before combining. Allows per-field weights w_f and b_f.
Axiomatic IR Constraints
TF (more occurrences → higher score, with saturation) + IDF (rare terms weighted more) + LNC (length normalisation). BM25 satisfies all three.
